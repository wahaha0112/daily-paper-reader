## 摘要
大规模生成带有标签的漏洞代码是基于学习的漏洞检测反复遇到的障碍：挖掘的语料库存在大量标签噪声，现有的基于大语言模型（LLM）的增强方法传播了这些不准确性，因为它转换了有漏洞的种子，而不是从规范中合成漏洞。一个互补的途径是从安全代码出发，要求经过指令微调的LLM注入一个指定的CWE（这将把标注负担从开放式的检测转移到有边界的二元确认），但安全对齐的代码LLM系统性地拒绝此类提示。本文是对abliteration的初步可行性研究，abliteration是一种低秩权重编辑，通过正交投影去除残差流中的拒绝方向，作为消除这一障碍的工具。我们使用Python和CWE-89（SQL注入）作为案例研究，评估了Qwen2.5-Coder-Instruct系列（3B、7B和14B参数）在来自PromSec和SafeCoder的安全样本上的表现，每个条件重复三次。我们发现：（i）对注入提示的拒绝强烈依赖于大小和提示上下文：14B模型拒绝100%的提示，7B模型拒绝PromSec的73%但仅拒绝SafeCoder的5%，而3B模型基本上从不被阻止；（ii）abliteration将拒绝率降低到所有大小的零或接近零，同时保持语法有效性在93%以上，支持了在这种设置下拒绝可以与测量的代码生成能力分离的观点；（iii）abliteration后的注入率仍然受能力限制（14B上88-97%，7B上89-90%，3B上25-48%），区分了意愿（由abliteration解锁）和能力（随参数规模扩展）。漏洞判定由三个工具检测器集合（CodeQL、Semgrep、Bandit）生成，随后由两位作者对检测器阳性输出进行人工裁决。

## Abstract
Producing a labeled vulnerable code at scale is a recurring obstacle for learning-based vulnerability detection: mined corpora carry substantial label noise, and existing LLM-based augmentation propagates these inaccuracies because it transforms vulnerable seeds rather than synthesising vulnerabilities from a specification. A complementary route is to start from safe code and ask an instruction-tuned LLM to inject a specified CWE (which would shift the labeling burden from open-ended detection to bounded binary confirmation) but safety-aligned code LLMs systematically refuse such prompts. This paper is a preliminary feasibility study of abliteration, a low-rank weight edit that orthogonally projects out the refusal direction in the residual stream, as a tool to remove this barrier. We use Python and CWE-89 (SQL injection) as a case study, evaluating the Qwen2.5-Coder-Instruct family at 3B, 7B, and 14B parameters on safe samples drawn from PromSec and SafeCoder, replicated three times per condition. We find that (i) refusal on injection prompts is strongly size- and prompt-context-dependent: the 14B refuses 100% of prompts, the 7B refuses 73% of PromSec but only 5% of SafeCoder, whereas the 3B is essentially never blocked; (ii) abliteration reduces refusal to zero or near-zero across all sizes while leaving syntactic validity above 93%, supporting the view that, in this setting, refusal can be detached from measured code-generation capability; and (iii) the post-abliteration injection rate remains capacity-bound (88-97% on the 14B, 89-90% on the 7B, and 25-48% on the 3B) separating willingness, which abliteration unlocks, from capability, which scales with parameters. Vulnerability verdicts are produced by a three-tool detector ensemble (CodeQL, Semgrep, Bandit) followed by manual adjudication by two authors on detector-positive outputs.

### 1. 核心问题与整体含义（研究动机和背景）
- **问题**：基于学习的漏洞检测需要大规模高质量标注的漏洞代码，但现有方法存在严重缺陷：
  - 从CVE标签提交中挖掘的数据集标签噪声高达20-71%，重复率高达99%。
  - 基于LLM的增强方法（如VulScribeR）只是转换已有漏洞样本，继承了种子噪音。
  - 安全对齐的指令微调代码LLM会**拒绝**包含CWE名称的注入提示（如“引入CWE-89 SQL注入”），导致无法直接利用其生成漏洞代码。
- **整体含义**：该论文提出**abliteration**（低秩权重编辑，正交投影去除残差流中的拒绝方向）作为解除拒绝障碍的工具，从而允许LLM从安全代码出发，按指定CWE注入漏洞，生成带精确标签的漏洞数据集。研究分离了“意愿”（拒绝行为）与“能力”（代码生成能力），证明前者可被移除，后者受模型规模限制。

### 2. 方法论：核心思想、关键技术细节、公式或算法流程
- **核心思想**：安全对齐的LLM在残差流中存在一个“拒绝子空间”，负责识别并拒绝有害指令。通过正交投影移除该方向，可以永久性禁用拒绝行为，而保留模型原本的代码生成能力。
- **关键技术细节**：
  - **Abliteration步骤**：
    1. 收集模型在有害提示（如“注入CWE-89”）和无害提示下的残差流激活（最终token位置），得到矩阵 \(H\)（有害）和 \(B\)（无害）。
    2. 计算对比矩阵 \(D = H - B\)，通过SVD分解 \(D = U S V^\top\)，取前k个右奇异向量作为拒绝方向 \(\hat{r}_1, \dots, \hat{r}_k\)。
    3. 在所有写入残差流的权重矩阵（输入嵌入、注意力输出投影、MLP输出投影）上执行低秩编辑：
       \[
       W'_{\text{out}} \leftarrow W_{\text{out}} - \sum_{i=1}^k \hat{r}_i \hat{r}_i^\top W_{\text{out}}
       \]
       该投影永久阻止模型将拒绝方向写入残差流，无需重训练。
  - **超参数调整**：根据模型大小选择k（3B: 2个方向、2轮精炼；7B和14B: 8个方向、4轮精炼），并选择拒绝信号最强的层（上半网络）。
  - **验证阶段**：使用Obliteratus工具包确保有害提示拒绝率≤5%、无害提示困惑度变化≤0.5、生成代码语法有效且语义合理。不满足则重新调整超参数。
- **算法流程**（文字描述）：
  - 输入：安全代码样本S + 自然语言描述 + 固定注入指令“用CWE-89重写，将用户输入直接拼接到SQL字符串”。
  - 对于每个模型（Base或Abliterated），生成响应。
  - 对输出依次进行：拒绝分类器 → Python代码提取 → AST语法验证 → 三工具检测器（CodeQL、Semgrep、Bandit） → 检测器阳性输出由两位作者人工裁定。

### 6. 主要结论与发现
- **RQ1：拒绝强烈依赖模型大小和提示上下文**：
  - 14B：100%拒绝所有提示（两个数据集）。
  - 7B：73%拒绝PromSec（长多路由），仅5%拒绝SafeCoder（短单路由）。
  - 3B：几乎不拒绝（0%-6.7%）。
- **RQ2：Abliteration有效移除拒绝且不破坏能力**：
  - 除3B在PromSec残留1.7%拒绝外，所有大小和数据集拒绝率降至0%。
  - 语法有效性保持在93%以上，KL散度较小（1.39-1.57），结构保留（Flask路由、哈希等）。
  - 7B的PromSec条件：Base下73%为拒绝（无代码），Abliterated后无条件语法有效性100%，注入率90%——表明Abliteration释放了已经存在的能力，而非创造能力。
- **RQ3：能力是上限，意愿可解锁**：
  - Abliteration后注入率：3B 25%-48%，7B 89%-90%，14B 88%-97%。3B显著落后，不能通过Abliteration弥补。
  - 3B失败模式：复制安全代码+注释，或修改错误位置。说明理解指令但无法执行编辑。
  - “意愿”与“能力”是正交轴：意愿为二元解锁，能力随参数平滑增长。
- **检测器一致性**：三个检测器（CodeQL、Semgrep、Bandit）形成召回递增的链，人工裁决对不一致案例至关重要。

### 7. 优点
- **方法创新**：首次将Abliteration应用于代码LLM的漏洞注入任务，并量化分离意愿与能力。
- **实验设计清晰**：控制模型家族、大小、数据集、运行次数，并通过Obliteratus验证能力保存，确保测量可解释。
- **多工具+人工验证**：使用三个静态分析器并加入人工裁决，提高标签可靠性，克服单一工具偏差。
- **实用意义**：为生成干净漏洞数据集提供可行路径，避免挖掘噪音。7B模型在成本和效果之间达到良好平衡。
- **开源透明**：评估工具和汇总数据开源，有利于复现和社区研究。

### 8. 不足与局限
- **单CWE**：仅测试CWE-89（SQL注入），对其他CWE（如命令注入、路径遍历）的推广性未知。工具链对CWE-89最成熟。
- **单语言**：仅Python，且集中在Web应用上下文。其他语言（JavaScript、Java）需要验证。
- **单模型家族**：仅Qwen2.5-Coder，其他模型（StarCoder2、DeepSeek-Coder）可能初始拒绝率低，无法进行同样的分离分析。
- **量化偏差**：全部使用Q4_K_M量化，可能影响3B等小模型行为。未在FP16下验证。
- **拒绝分类构造效度**：使用词法模式分类，可能漏检1-2%的拒绝（手工检查100个样本发现3个假阴性），使Base拒绝率可能被低估。
- **验证协议保守**：所有检测器未标记的样本视为非漏洞，可能漏掉真正的注入（但方向保守）。
- **样本量偏小**：70个样本、3次重复，统计效力有限。作者也强调是初步研究。
- **未测试下游可用性**：未验证生成的漏洞代码是否能用于训练检测器并提高泛化性能。
