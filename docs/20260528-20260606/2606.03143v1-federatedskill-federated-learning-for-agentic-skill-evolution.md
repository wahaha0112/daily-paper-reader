## 摘要
现代大语言模型智能体越来越依赖技能库来处理复杂任务，使得技能演化成为自我提升的主要驱动力。然而，孤立的单用户任务流缺乏构建全面技能所需的多样性。虽然跨用户协作可以克服这一数据瓶颈，但当前的轨迹共享方法会损害用户隐私，并强加一个无法适应客户端异质性的统一全局库。我们引入了FederatedSkill，一个用于协作智能体演化的隐私保护框架。超越原始轨迹共享，FederatedSkill利用语义技能差异（即本地库上的结构化补丁）作为通信的基本单元。在服务器端，一个演化智能体聚合这些补丁，动态建模客户端特定的能力边界，从而促进严格个性化的技能演化，而非次优的全局平均值。在20个不同的智能体任务族上进行的评估显示，FederatedSkill相对于自我演化的基线取得了显著提升，成功率最高提升44.4%，计算成本降低37.5%。

## Abstract
Modern LLM agents increasingly rely on skill libraries to handle complex tasks, making skill evolution a primary driver of self-improvement. However, isolated single-user task streams lack the diversity required to build comprehensive skills. While cross-user collaboration can overcome this data bottleneck, current trajectory-sharing approaches compromise user privacy and impose a uniform global library that fails to accommodate client heterogeneity. We introduce FederatedSkill, a privacy-preserving framework for collaborative agent evolution. Moving beyond raw trajectory sharing, FederatedSkill utilizes semantic skill diffs, structured patches over local libraries, as the fundamental unit of communication. On the server side, an evolution agent aggregates these patches to dynamically model client-specific capability boundaries, facilitating strictly personalized skill evolution rather than a suboptimal global average. Evaluated across 20 distinct agent task families, FederatedSkill demonstrates substantial gains over self-evolving baselines, achieving up to a 44.4% increase in success rate and a 37.5% reduction in computational cost.

# 论文总结：FederatedSkill: Federated Learning for Agentic Skill Evolution

## 1. 核心问题与整体含义（研究动机与背景）

- 现代LLM智能体（agent）依赖可复用的技能库（skill library）来处理复杂任务，例如网页导航、企业自动化等。技能库的演化（添加、修改、删除技能）是智能体自我提升的主要途径。
- 然而，单一用户的本地任务流覆盖范围狭窄，难以积累足够多样的经验来构建通用技能，导致智能体在面对新任务时频繁失败。跨用户协作可以扩大任务覆盖，但现有方法（如直接共享原始执行轨迹）存在两个根本缺陷：
  - **隐私风险**：原始轨迹可能包含敏感内容（如网页上的私人信息、电子表格中的机密数据），用户无法安全地将其上传到外部服务器。
  - **客户端异质性（heterogeneity）**：不同用户使用不同模型、不同智能体框架、实际任务分布不同。一个全局统一的技能库往往对所有人都不是最优的，不能满足个性化需求。
- 因此，论文提出核心问题：能否在保护隐私的同时，让用户协作演化技能，并且每个用户获得量身定制的技能库？

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：借鉴联邦学习的思想，客户端不上传原始轨迹，而是上传语义化的“技能补丁”（skill patch），服务器端通过一个演化智能体动态建模每个客户端的能力边界，生成个性化技能库更新。
- **框架整体流程**（图1）：
  - 客户端（Client）：
    1. 本地执行任务，收集轨迹批次（trajectory batch）。
    2. 本地反射（self-reflection）将轨迹蒸馏成结构化的技能补丁 \(\delta_i^t\)，包含ADD、EDIT、DELETE操作。
    3. 仅上传补丁，原始轨迹始终保留在本地。
  - 服务器端（Server）：
    1. 收集所有客户端的补丁，连同每个客户端的静态配置（模型类型、框架）和动态建模的能力边界。
    2. 一个LLM驱动的演化智能体（evolution agent）执行两个阶段：
       - **Stage 1：演化规划**：分析补丁，生成能力矩阵（capability matrix）记录每个客户端对每个任务流（workflow）的掌握状态（covered、absorbing、broken、gap）；维护两级记忆——高层共享记忆（全局观察）和低层私有记忆（客户端特定失败模式）；生成可行动的指令（directives）。
       - **Stage 2：逐个客户端的库演化**：根据指令为每个客户端单独执行库更新，吸收可转移的补丁、修复破损技能或重写同伴技能以适应目标客户端的配置。
- **补丁格式**：四元组 \(\delta_i^t = (U_i^t, D_i^t, R_{i,x}(\tau), s_i^t)\)，其中\(U_i^t\)是新增或替换的文件内容（技能文件），\(D_i^t\)是删除路径列表，\(R\)是任务奖励，\(s\)是一句摘要。
- **公式化问题**：形式化为一个部分可观测马尔可夫决策过程（POMDP），服务器只能观察到补丁和配置，需动态推断客户端能力边界，最大化累积性能增益。
- **隐私保护设计**：补丁仅包含库级别的语义，被明确提示要泛化而非包含具体值，且所有路径经过严格验证避免目录遍历。原始轨迹、验证器输出、中间文件等均留存在客户端。

## 3. 实验设计

- **数据集 / Benchmark**：使用SkillFlow（Zhang et al., 2026d），该基准专门评估智能体对技能的长期发现和演化，包含20个不同任务族（task families），每个族内有一系列顺序任务，难度递增。智能体初始为空库，按顺序完成任务并更新库，最终评估平均任务完成率。
- **对比方法**：主要基线是**自我演化（Self-Evolution, SE）**，即每个客户端独立基于自身轨迹演化技能库，不与其他客户端协作。此外还有消融实验中的非个性化基线（Global）：使用相同补丁协议但生成单一的全局技能库，不进行个性化建模。
- **实验设置**：为模拟真实异质性，使用不同背景模型（Qwen3.6-Plus、GLM-5、Kimi K2.5）和不同智能体CLI（Claude Code、Qwen Coder、Kimi CLI）。服务器端演化智能体使用GLM-5 + Claude Code。
  - 三种设置：
    - 同构设置（Homogeneous）：所有三个客户端使用相同模型（GLM-5）和相同框架（Claude Code）。
    - 异构背景模型（Heterogeneous Backbone）：三个客户端分别使用不同模型，但统一使用Claude Code框架。
    - 异构背景模型+框架（Heterogeneous Backbone & Harness）：模型和框架都不同。

## 6. 主要结论与发现

- **性能提升**：FederatedSkill相比自我演化基线，在三种设置下一致提升成功率。同构设置平均提升8.4个百分点（37.4%→45.8%），异构模型设置平均提升约5.8个百分点，异构模型+框架设置平均提升约4.8个百分点。最大单细胞提升达到44.4%（Kimi K2.5在Production Capacity Planning上）。
- **成本降低**：在异构模型+框架设置下，每解决任务的成本最高降低37.5%（Kimi K2.5），每轮成本降低7-24%。
- **隐私保护有效**：技能补丁的敏感实体泄露率仅5.08%，个性化更新仅有0.09%，远低于原始轨迹摘要的52%。
- **个性化是关键**：消融实验显示，使用全局库（不考虑个性化）平均性能比个性化演化低9.8-12.2个百分点。
- **库大小控制**：FederatedSkill通过跨客户端去重和保守采纳，将库大小稳定在1.0-1.6个技能/族，而自我演化容易导致库膨胀（~2.5个）或停滞。
- **补丁通信高效**：整个基准测试的通信量仅3.5 MB，远小于参数级联邦学习。
