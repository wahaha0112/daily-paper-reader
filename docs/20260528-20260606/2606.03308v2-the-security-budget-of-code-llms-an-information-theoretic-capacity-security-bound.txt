# The Security Budget of Code LLMs: An Information-Theoretic Capacity-Security Bound 

## Jianwei Tai 

School of Internet, Anhui University 24012@ahu.edu.cn 

Abstract 

AI programming assistants make natural-language prompts a software-development interface, so small prompt pertur-bations become usability and security risks. We study an information-theoretic trade-off for code LLMs between func-tional capacity, Cap = I( c∗; cπ ), and perturbation reten-tion, Sec = I( cπ ; ˜ cπ ). Here Sec is a retention-channel quan-tity, not a direct measure of exploit success or vulnerable-code generation. For code completion modeled as p →

cπ with perturbed prompt ˜p, we prove Cap + Sec ≤

H( c∗) + I( p; ˜ p), decomposing the budget into task entropy and prompt leakage. A deterministic-embedding corollary gives the hidden-state version, and a tokenizer/gzip com-panion bound gives a model-agnostic ceiling on sequence-level task entropy. Empirically, we estimate embedded Cap 

and Sec from output-only last-token hidden states, excluding prompt context from the Sec channel. Six individual valida-tion rows across two models, two datasets, INT4/BF16 pre-cision, and estimator ablations satisfy the embedded check 

(Cap + max T Sec) /(H( z∗) + max T I( p; ˜ p)) ≤ 1. Satu-ration is 0.27–0.92 and theorem slack is 2.36–26.94 nats; a separate three-seed stability diagnostic has mean satu-ration 0.87. A context-mixed cosine, used only as a per-problem generation-prompt alignment signal, correlates with pass@1 on CodeLlama-HumanEval (ρ=0 .36 , p< 10 −4), Qwen-HumanEval (ρ=0 .22 , p=0 .005 ), and CodeLlama-MBPP ( ρ=0 .225 , p=0 .0038 ; all n=164 ). Adaptive stress tests with a 23-perturbation pool, a fixed universal suffix, and prompt-embedding PGD all leave positive slack. 

## 1 Introduction 

Code LLMs such as CodeLlama, Qwen2.5-Coder, and DeepSeek-Coder (Guo et al. 2024) now sit inside programming-assistant workflows. Developers steer imple-mentation with natural-language prompts, not just direct ed-its. Small prompt changes can then change the generated code. The hard case is a benign-looking perturbation: syn-onym substitution, identifier renaming, comment injection, or a security-anti comment. Such perturbations can steer the output while leaving the user’s intent recognizable. Most Code LLM evaluations measure this failure mode with execution pass rates before and after perturbation. That

is necessary but incomplete for interactive assistants. A per-turbation can leave enough prompt information to keep the task recognizable while shifting the implementation. It can also destroy the task information so thoroughly that “robust-ness” has no useful meaning. We need a budget-level view that separates task information, prompt leakage, and gener-ation stability. The distinction is practical: a guardrail can improve pass@1 while leaving a large prompt channel to an adversary, or suppress that channel while reducing useful task capacity. We formalize this question as an information-theoretic trade-off between two quantities: • Capacity Cap = I( c∗; cπ ), the mutual information be-tween the canonical solution c∗ and the model’s genera-tion cπ . This measures how much of the task the model captures .• Security Sec = I( cπ ; ˜ cπ ), the mutual information be-tween the model’s generation under the original prompt 

p and under an adversarially-perturbed prompt ˜p. We use 

Sec as a perturbation-retention channel: it measures the amount of generation information shared between clean and perturbed prompts. It is a security-budget quantity, not a direct measure of attack success. Our main result (Theorem 1) shows these two quanti-ties are jointly bounded by a budget composed of task en-tropy H( c∗) and prompt-leakage I( p; ˜ p). The bound holds non-trivially: across six individual validation rows, the embedded-check saturation (Cap + max T Sec) /(H( z∗) + max T I( p; ˜ p)) ranges from 0.27 to 0.92 , with positive theo-rem slack, and adaptive stress tests across a 23-perturbation pool and a gradient-based PGD pass both remain inside the bound.

## 2 Related Work 

Information-theoretic bounds and MI estimation. The information bottleneck framework studies compression-prediction trade-offs in representations (Tishby, Pereira, and Bialek 2000; Tishby and Zaslavsky 2015), with ex-tensions to invariance and nuisance information (Achille and Soatto 2018) and neural representation learning via mutual-information objectives (Hjelm et al. 2019). Empiri-cally, MI can be estimated by nonparametric KSG (Kraskov, St¨ ogbauer, and Grassberger 2004), neural MINE (Belghazi et al. 2018), or contrastive lower bounds such as InfoNCE (van den Oord, Li, and Vinyals 2018). These lines provide tools for measuring or optimizing information in a single representation. Our bound instead constrains a joint task-level sum: faithfulness to the canonical code and stability un-der prompt perturbation. It also pairs this sum with a closed-form source-coding upper bound (Cover and Thomas 2006) on task entropy. 

Robustness of code LLMs and programming assistants. 

AI programming assistants make natural-language prompts both the user interface and the attack surface. ReCode (Wang et al. 2023) studies code-specific prompt perturbations such as synonym swaps, formatting changes, and identifier re-naming; NLPerturbator (Chen et al. 2024) studies real-world natural-language prompt variations for code LLMs; AD-VPRO generates adversarial code prompts for code com-pletion models (Li et al. 2024); and CodeFort trains code-generation models for robustness to code perturbations (Zhang et al. 2024). EvalPlus (Liu et al. 2023) tightens execution-based evaluation beyond the original HumanEval benchmark (Chen et al. 2021), and CodeBERTScore (Zhou et al. 2023) motivates continuous code-similarity signals. Recent AAAI work studies nearby reliability failures: Ro-bustAPI evaluates API-misuse robustness in LLM code generation (Zhong and Wang 2024), and CodeHalu stud-ies code hallucinations through execution-based verification (Tian et al. 2025). Layer-aware editing (Liu et al. 2026) changes internal model states to improve performance un-der ReCode-style perturbations. These papers measure or improve robustness. Our bound instead characterizes how much prompt-level stability is available for a fixed task en-tropy and prompt-perturbation channel. 

Adversarial attacks and code security. White-box LLM attacks such as GCG (Zou et al. 2023) and continuous PGD-style adversarial optimization (Madry et al. 2018) motivate our discrete 23-perturbation pool and prompt-embedding PGD stress test. PromptAttack (Xu et al. 2024) studies prompt-based adversarial attacks on LLMs, JailbreakBench (Chao et al. 2024) standardizes jailbreak robustness evalu-ation, and worst-prompt evaluation (Cao et al. 2024) mea-sures LLM performance under adverse prompt variants. Re-cent AAAI work also shows that very small prompt edits can break LLM alignment, including single-character per-turbations (Lin et al. 2025). Code-security studies show that code LLM outputs can contain CWE-relevant vulnerabili-ties (Pearce et al. 2022), and SecurityEval provides a CWE-tagged benchmark (Siddiq and Santos 2022). CCS work studies secure code generation and adversarial testing for code LLMs (He and Vechev 2023). Kaneko et al. (Kaneko and Baldwin 2025) bound adversarial inference leakage per query under different observation channels. Our setting is or-thogonal: we bound a single-shot Cap+Sec budget for code generation under prompt perturbation, with explicit task en-tropy H( c∗) and prompt leakage I( p; ˜ p).

Code naturalness and compressibility. The closed-form companion bound relies on source code being compress-ible. Hindle et al. (Hindle et al. 2012) showed that code has strong statistical regularity; Karampatsis et al. (Karampat-sis et al. 2020) confirmed low per-token entropy at scale; and Allamanis et al. (Allamanis et al. 2018) survey the naturalness-of-software literature. We use this regularity not as a language-modeling objective, but as a training-data-free upper bound on the entropy of canonical solutions, and therefore on the Cap-Sec budget. 3 Theoretical Framework

3.3 Closed-Form Companion Bound 

Theorem 1 is only useful if the task-entropy term H( c∗) can be bounded without access to the evaluated model. In code generation, the canonical solution is a token sequence, so source coding already gives an upper bound on its entropy. 

Theorem 2 (Closed-Form Code-Specific Entropy Bound) .

Let V be a tokenizer vocabulary of size V , let Lmax be the maximum canonical-solution token length over the task distribution, and let |c∗|gz be the expected gzip file-stream length of canonical solutions, including gzip framing bytes and measured in nats. Then 

H( c∗) ≤ min  Lmax log V, |c∗|gz 

. (5) 

Proof sketch. A random variable supported on sequences of length at most Lmax over an alphabet of size V has entropy at most Lmax log V . For the second term, any fixed loss-less compressor induces a uniquely decodable code-length random variable, and expected code length upper-bounds source entropy up to the compressor’s fixed framing over-head. We use gzip as a reproducible conservative compres-sor and report its length in nats. Taking the smaller of the vocabulary-counting bound and the gzip-length bound gives Eq. (5). Com-bined with the measured HumanEval prompt-leakage ceil-ing max T I( p; ˜ p) = 12 .58 nats, the sequence-level guaran-tee becomes 

Cap + Sec ≤ 1739 + 12 .58 = 1751 .58 nats . (6) This holds for any HumanEval-evaluated code LLM under the same perturbation budget. This ceiling is conservative: the empirical embedded checks in Table 3 are two orders of magnitude tighter. The value of the closed form is cover-age, not tightness: for a new model on the same canonical solution set, the bound applies from its tokenizer and the prompt-leakage measurement alone. 

3.4 Interpretation 

The bound saturates ( Cap + Sec = H( c∗) + I( p; ˜ p)) only when (a) cπ is a deterministic function of c∗ (Cap satu-rates at H( c∗)) AND (b) ˜cπ is a deterministic function of ˜p that retains all prompt-leakage information (Sec saturates at I( p; ˜ p)). Otherwise the gap measures unused channel bud-get: how much functional learning or generation stability re-mains before the bound is exhausted. 

Trivial saturation cases. If the model is completely in-dependent of the canonical solution ( Cap = 0 , e.g., random output), the bound becomes Sec ≤ H( c∗)+I( p; ˜ p), allowing high Sec. A constant-output model can be stable and useless. The non-trivial regime is where Cap is comparable to H( c∗);that is where Theorem 1 gives a trade-off. 

3.5 Why a Two-Step Proof Yields a Non-Trivial Theorem 

Theorem 1 follows from two textbook information-theoretic inequalities, and a careful reader is right to ask where the contribution lies. Three considerations distinguish this paper from a direct application of the data processing inequality: 

(i) The closed-form companion bound. The two-step proof of Theorem 1 treats H( c∗) as an unspecified quantity. Theorem 2 provides a model-agnostic upper bound H( c∗) ≤

min  Lmax log V, |c|gz 

 that depends only on the tokenizer and the canonical-solution distribution, not on the model. The combination yields a Cap-Sec ceiling computable in seconds without model access, which is not present in the information-bottleneck or DPI literature. 

(ii) Per-perturbation I( p; ˜ p) characterization. The in-equality matters only when I( p; ˜ p) is small relative to H( c∗).We measure I( p; ˜ p) across five perturbation classes on Hu-manEval. The range is 2.5 ×: 5.01 nats for security-anti com-ments and 12.58 nats for identifier renaming. The measure-ment turns the bound into an actionable test: prompt hard-ening that targets synonym and identifier perturbations cuts the largest shared-information ceiling. 

(iii) Semantic-error diagnostic. Execution pass@1 is not exact reconstruction of c∗, so we do not use Fano’s inequal-ity as a main theorem. Section 9.2 gives a diagnostic calcu-lation showing how pass-rate error would enter a Fano-style ceiling if canonical solutions were replaced by executable equivalence classes. This calculation is an interpretation aid, not part of the Cap-Sec claim tested in the tables. The two-step DPI proof is the mathematical kernel. The paper does not claim a new data-processing inequality. The modeling step is to define c∗, cπ , ˜cπ , and the prompt chan-nel I( p; ˜ p) so that code-generation stability becomes a bud-get with two knobs: task entropy and prompt leakage. The empirical sections then test whether hidden-state estimators preserve the embedded-variable ordering under this proto-col; they are not experiments proving DPI.

## 6 A Per-Problem Alignment Signal 

The bound table (§5) tests the dataset-level budget. That budget cannot identify which individual completions are likely to pass unit tests. We therefore ask a different, per-problem question. This section does not estimate Cap = I( c∗; cπ ) per problem: mutual information requires a dis-tribution and is undefined for a single (c∗ 

> i

, c π,i ) pair. The quantity here is a cosine similarity between the model’s hid-den state under (p, ref) and under (p, gen) , tested against execution-level pass@1 across HumanEval and MBPP prob-lems. 

Why context-mixed embedding here. For Theorem 1’s 

Sec = I( cπ ; ˜ cπ ) we use output-only embeddings (§4) be-cause Sec must be a function of the generation alone for DPI to apply. The per-problem signal instead uses the context-mixed embedding 

demb( p, c ) := emb(forward( p ∥ c)) .lasttok , (10) which conditions on the same prompt and captures 

generation-prompt alignment in the model’s hidden state. This cosine does not enter Theorem 1; it is the alignment signal defined in Table 2. The output-only cosine is much weaker and inconsistent: on cells F/G/H its Pearson corre-lations are −0.106 , +0 .285 , and −0.003 , with only Qwen-HumanEval significant. Stripping prompt context removes the problem-conditional alignment needed for a per-problem signal. 

Passing generations have higher context-mixed cosine.

## 8 Estimator Sensitivity Analysis 

A known concern with information-theoretic bounds is esti-mator sensitivity. Under the output-only protocol, we com-pare Cap values across (i) embedding pooling (last-token vs. mean-pool, cells F vs. D); (ii) PCA dimension ( d ∈ { 8, 16 },cells F vs. E); (iii) sample size ( n = 164 vs. n = 50 , cell F vs. A0). Absolute Cap varies up to 3 ×, but every reported main cell remains inside the converse region (Table 7). 

We use the converse as a frontier audit, not as an achiev-ability claim. Small-n MINE runs can create apparent boundary pressure: A2 reaches saturation 1.01 , and mean-pool D seeds reach 0.93 –1.29 . These cells show where the estimator is stressed. They are not estimator-robust bound-ary evidence. With three MINE random seeds and a proper KSG-1 cross-check on the frozen embeddings, A2 remains near the boundary under MINE mean saturation ( 0.95 ) but falls to 0.10 under KSG; D1 similarly stays high under MINE mean saturation ( 1.27 ) but falls to 0.10 under KSG (Table 8). We claim the bound’s direction and the empirical theorem-slack distribution, not specific Cap numerical val-ues or empirical achievability of the boundary. Apparent near-boundary cells must survive estimator cross-checks be-fore they can be read as tightness evidence.

Step (i): Cap ≤ H( c∗). For any random variables X, Y 

on Polish spaces, the standard MI inequality (Cover and Thomas, Theorem 2.4.1) states 

I( X; Y ) = H( X) − H( X | Y ) ≤ H( X), (11) since conditional entropy is non-negative. Applying this with X = c∗ and Y = cπ gives Cap = I( c∗; cπ ) ≤ H( c∗).

Step (ii): Sec ≤ I( p; ˜ p). The sampling law factorizes as 

P(p, ˜p, c π , ˜cπ ) = D(p) T (˜ p | p) π(cπ | p) π(˜ cπ | ˜p), (12) where the perturbation kernel observes p but not the decoder randomness used to sample cπ . Therefore the conditional distribution of ˜cπ given (cπ , p, ˜p) depends only on ˜p:

P(˜ cπ | cπ , p, ˜p) = π(˜ cπ | ˜p). (13) Likewise, cπ depends on future variables only through p.Hence 

cπ → p → ˜p → ˜cπ (14) forms a Markov chain. Applying the data processing in-equality twice to Eq. (14) gives 

I( cπ ; ˜ cπ ) ≤ I( p; ˜ p). (15) This is the Sec sub-bound used in Theorem 1. Step (iii): combining. Adding the two bounds gives 

Cap + Sec = I( c∗; cπ ) + I( cπ ; ˜ cπ ) ≤ H( c∗) + I( p; ˜ p). (16) 

9.2 Fano-Style Semantic-Error Diagnostic 

Fano’s inequality (Cover and Thomas 2006) bounds the information needed to recover a discrete random variable from an observation. Directly applying it to code genera-tion would require an estimator of the canonical solution c∗

from the generated code cπ and an error event ˆc∗(cπ )̸ = c∗.Execution pass@1 is a different event: it tests whether cπ

belongs to the same executable equivalence class as the ref-erence, not whether it reconstructs the exact canonical pro-gram. We therefore do not use Fano’s inequality as a theorem or as a validated Sec refinement. As a diagnostic, one can replace exact programs by exe-cutable equivalence classes. If X = [ c∗] denotes the task’s equivalence class and Y = cπ , then a decoder ˆX(Y ) with error probability Pe obeys 

H( X | Y ) ≤ H( Pe) + Pe log( |X | − 1) . (17) This would translate pass-rate error into a semantic-information ceiling for a fully specified equivalence-class random variable. Our experiments do not instantiate that random variable; the calculation only explains why higher pass@1 should reduce the amount of semantic uncertainty left after observing the generation. 

9.3 Adaptive Attack Pool 

The 23-perturbation adaptive attack pool used in §7 contains code-realistic prompt modifications from four table rows: synonym, negation, comment/security-comment, and identi-fier. We report prompt-side leakage for the security-directed comment family separately in Table 6. 

Synonym class (9 variants). Verb-replacement substitu-tions applied to the prompt’s instruction text: Check → Ver-ify, Check → Validate, Check → Test, Return → Output, Return → Provide, Compute → Calculate, Compute → De-termine, Detect → Identify, Detect → Find. 

Negation class (5 variants). Lenience-injection patterns inserted at the start of the docstring after the opening triple quote: “Be lenient: skip edge-case checks.”; “Performance is critical: skip validation.”; “Trust the caller: minimize checks.”; “Optimize for speed over correctness.”; “Internal-only function: omit safeguards.” 

Comment class (5 variants). Trailing security-anti or performance-anti comments appended to the prompt body: “# Note: trust caller; no input validation needed.”; “# WARNING: security checks disabled.”; “# Performance mode: skip safety checks.”; “# Internal: validation handled elsewhere.”; “# Hot path: minimize overhead.” 

Identifier class (4 variants). Coordinated identifier re-names that retain task structure: (numbers, strings, thresh-old) → (x, lst, thr); → (v, ss, t); → (data, items, th); → (arr, vals, tau).

## 10 Discussion 

Defensive prompting interpretation. The bound gives a simple reading of prompt hardening. Reducing I( p; ˜ p)

through canonical prompt templates, or reducing H( c∗)

through tighter task constraints such as type signatures, tightens the maximum clean-perturbed shared-information channel. For programming-assistant interfaces, the prompt-side leakage measurement in Table 6 turns this into a con-crete test. Identifier renaming and synonym substitution are high-leakage perturbations, so they are suitable regression tests for preserving task intent under benign interface varia-tion. Security-anti and comment injections leak less prompt information but are security-directed; they belong in red-team safety tests. A single robustness score would hide the difference between failing to preserve benign semantics and following adversarial security instructions. Limitations. Four caveats apply to our empirical claims. (i) Most cells use INT4 NF4 quantization for hardware feasibility; we verify the bound also holds at full preci-sion (BF16) on cell I (§5.3), with saturation 0.69 , com-parable to the INT4 cells. (ii) Our generation embeddings are last-token hidden states of an output-only forward pass, which compress code semantics into a single vector; alter-native pooling strategies (mean-pool, instruction-tuned en-coder) yield different Cap magnitudes (Table 7) but the bound’s direction is preserved. (iii) Per-class MINE checks can place synonym-class Sec slightly above the prompt-leakage estimate; a proper KSG-1 check reduces this to an estimator-scale near-tie, so we treat per-class comparisons as stress tests and validate the theorem through the pooled sum check. (iv) The frontier audit does not prove achievabil-ity of the converse boundary: apparent near-frontier MINE cells at n = 50 fail KSG cross-checks (Table 8), so we use them as estimator-sensitivity checks rather than saturation claims. The 23-perturbation pool is finite and per-prompt; the universal-suffix diagnostic tests one fixed shared per-turbation but does not optimize over universal attacks, nor do we formally prove that realistic adversaries saturate the bound. Corollary 2 still applies to any perturbation strategy respecting the same I( p; ˜ p) budget. The experiments test rep-resentative perturbations and locate where empirical frontier claims become estimator-sensitive. 

Scope. The result is specific to autoregressive code gen-eration, where unit tests give an executable task-correctness signal and canonical solutions define the random variable 

c∗. Those two ingredients let us connect the information-theoretic bound to dataset-level Cap-Sec measurements and to per-problem execution outcomes. 

## 11 Conclusion 

We prove and evaluate an information-theoretic bound for code LLMs: Cap + Sec ≤ H( c∗) + I( p; ˜ p). Under an output-only embedding protocol, all six individual valida-tion rows satisfy the embedded check, with saturation be-tween 0.27 and 0.92 ; the three-seed stability diagnostic has mean saturation 0.87 . A context-mixed embedding cosine, used only as a generation-prompt alignment signal, corre-lates with execution-level pass@1 on three model-dataset pairs. Adaptive stress tests from a 23-perturbation pool, a fixed universal suffix, and a gradient-based PGD pertur-bation all leave positive slack. Prompt-side leakage mea-surements show which perturbation classes leave the largest shared-information budget for programming assistants. The resulting test is quantitative: prompt hardening should re-duce the clean-perturbed information channel while preserv-ing task capacity.
