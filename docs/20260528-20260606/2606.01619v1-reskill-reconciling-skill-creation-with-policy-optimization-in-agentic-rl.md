## 摘要
智能体强化学习使LLM智能体能够从环境奖励中持续改进，然而由此产生的策略并未系统性地积累可跨任务泛化的可重用策略。模块化技能可以提供这种可重用策略，但现有的技能增强型强化学习方法将技能创建与策略优化分离，存在采用与不断演化的策略相冲突的技能的风险。受Anthropic的Skill Creator启发，我们提出了ReSkill，一种将技能演化与策略学习相协调的循环强化学习技能创建框架。ReSkill利用GRPO的组级结构，仅以微小的额外开销自然嵌入三种机制：(1) 基于断言的技能创建器，从过去经验中诊断失败，并提出有条件的、基于触发的技能修订；(2) 组内rollout采样，实现对技能版本的可控比较，捕捉哪个版本最能支持策略的持续学习；(3) 带有自适应折扣的汤普森采样，在策略演化过程中平衡技能版本选择的探索与利用。在多个领域中，ReSkill始终优于现有的基于记忆和技能的强化学习方法，在未见任务上提升最为显著。对技能生命周期的分析表明，随着策略的改进，技能会自动被创建、测试、改进和修剪，展示了协调的技能-策略共同演化。

## Abstract
Agentic reinforcement learning (RL) enables LLM agents to improve continuously from environment rewards, yet the resulting policies do not systematically accumulate reusable strategies that generalize across tasks. Modular skills can provide such reusable strategies, yet existing skill-augmented RL methods decouple skill creation from policy optimization, risking adopting skills that conflict with the evolving policy. Inspired by Anthropic's Skill Creator, we introduce ReSkill, an RL-in-the-loop skill creation framework that reconciles skill evolution with policy learning. ReSkill exploits the group-wise structure of GRPO to naturally embed three mechanisms with only marginal additional overhead: (1) an assertion-driven skill creator that diagnoses failures from past experience and proposes conditional, trigger-based skill revisions; (2) within-group rollout sampling that enables controlled comparison of skill versions, capturing which version best supports the policy's ongoing learning; and (3) Thompson Sampling with adaptive discounting to balance exploration and exploitation in skill version selection as the policy evolves. Across several domains, ReSkill consistently outperforms existing memory and skill-based RL methods, with the largest gains on unseen tasks. Analysis of the skill lifecycle shows skills being automatically created, tested, refined, and pruned as the policy improves, demonstrating reconciled skill-policy co-evolution.

## 1. 核心问题与整体含义（研究动机与背景）

**问题**：现有智能体强化学习（Agentic RL）方法虽然能使LLM智能体从环境奖励中持续改进，但学习到的策略难以系统性地积累可跨任务泛化的可重用策略。模块化技能（如Anthropic的Skill Creator）提供了封装策略知识的片段，但现有技能增强型RL方法将技能创建与策略优化视为两个独立过程，导致技能可能随着策略演化而变得不兼容甚至阻碍学习。关键在于：技能是否真正有益于当前策略，必须通过实际训练来检验，而非由外部创建者静态决定。

**动机**：受Anthropic的Skill Creator启发（该工具通过人工参与循环创建/测试技能），希望将技能创建循环嵌入RL训练过程，实现技能与策略的自动协调进化。

**含义**：提出一种新范式——技能与策略在同一个RL流程中协同进化，技能版本经过策略实际训练的测试、接受或拒绝，从而产生更稳健、更具泛化能力的智能体。

## 2. 方法论：核心思想、关键技术细节

**核心思想**：ReSkill利用GRPO的组级结构（每个训练步骤对同一任务采样G条轨迹），将技能版本的比较嵌入到同一组rollout中，实现三个角色（策略优化、失败诊断、技能评估）共享一次rollout，无需额外采样成本。通过断言驱动的技能创建、组内采样比较和自适应Thompson采样，实现技能与策略的在线协同。

**关键技术细节**：

- **组内技能测试（Within-Group Skill Testing）**：每个GRPO组内，不同rollout分配不同的技能版本（$S_{new}$或$S_{old}$），通过Thompson采样决定分配概率。所有rollout共用相同任务$q$和策略$\pi_\theta$，唯一变量是技能版本，确保可控比较。优化目标扩展为：
  $$J^{\text{ReSkill}}(\theta) = \mathbb{E}_{q\sim\mathcal{D}, v_i\sim\text{TS}(\alpha_v,\beta_v), \tau_i\sim\pi_{\theta_{\text{old}}}(\cdot|q,S_{v_i};\mathcal{T})}\left[\mathcal{L}^{\text{GRPO}}(\theta;\{\tau_i\}_{i=1}^G)\right]$$

- **强化学习循环中的技能创建（RL-in-the-Loop Skill Creation）**：使用经验库$\mathcal{R}$（存储最新训练轨迹及其技能版本标签和奖励）代替人工反馈。通过Assertion-Based Failure Grading对失败进行诊断：动态断言集$\mathcal{A}$对各轨迹进行规则检查，获得各断言通过率；LLM分析器结合通过率和代表性样本给出优先级排序的失败诊断，并更新断言集。History-Informed Skill Revision：给定当前技能库、失败诊断和以往提案的接受/拒绝历史，技能创建器提出候选版本$S_{new}$（包含ADD/MODIFY/DELETE操作）。

- **基于自适应折扣Thompson采样的技能版本分配**：将新旧技能视为两个臂（bandit），成功概率服从Beta分布。在每个评估周期开始时初始化$\text{Beta}(1,1)$。每步利用Monte Carlo估计$p_{new}>p_{old}$的概率，并裁剪到$[\varepsilon_{ts}, 1-\varepsilon_{ts}]$作为分配概率。为适应策略演化，引入自适应折扣：
  $$\alpha_v \leftarrow w_t \alpha_v + m_t,\quad \beta_v \leftarrow w_t \beta_v + (n_t - m_t),\quad w_t = (1 + n_t/M)^{-1}$$
  其中$M$为记忆参数，通过序列预测似然最大化自动估计（无需手动调整）。评估周期结束时基于折扣后的后验期望决定接受或拒绝$S_{new}$。

**算法流程**（文字描述）：
1. 初始化策略$\pi_{\theta_0}$、技能库$S$、经验库$\mathcal{R}$、Beta后验参数。
2. 对每个训练步骤：
   - 采样任务$q$；根据Thompson采样为每个rollout分配技能版本$v_i$。
   - 生成轨迹$\{\tau_i\}_{i=1}^G$并计算奖励。
   - 使用ReSkill目标更新策略（式(2)）。
   - 将轨迹加入经验库$\mathcal{R}$。
   - 更新Thompson采样后验（含自适应折扣）。
3. 每$K_e$步触发技能演化：
   - 接受或拒绝候选技能$S_{new}$。
   - 从经验库诊断失败，提出新的$S_{new}$。
   - 重置后验，开始新一轮测试。
4. 最终输出优化后的策略和技能库。

## 7. 优点（方法/实验设计亮点）

- **零额外rollout成本**：利用GRPO组结构使每次rollout同时服务于策略优化、失败诊断和技能评估，无需额外采样。
- **强化学习内嵌技能测试**：将技能版本测试与策略训练深度融合，而非解耦的离线评估，确保了技能与策略的实时对齐。
- **自适应Thompson采样**：针对策略演化设计中自适应折扣权重（$w_t$），平衡新旧证据权重；记忆参数$M$可通过预测似然最大化自动估计，避免手动调参。
- **断言驱动的失败诊断**：通过动态断言集全面分析整库失败模式，代替逐条轨迹诊断，提高了技能创建的针对性和效率。
- **丰富的消融与敏感性分析**：系统验证了每个组件（协同顺序、测试机制、证据聚合、断言分析器等）的贡献，增强了结论的可靠性。
- **跨域泛化测试**：不仅测试了多个域内的seen/unseen性能，还展示了训练后策略在无更新情况下仅靠技能适应新域的能力，证明了协同训练培养了通用技能跟随能力。

## 8. 不足与局限

- **进化频率敏感**：在ALFWorld（120步）上，当$K_e$从5升至20时性能下降约5%，提示进化频率需要根据训练总步数调整。论文建议未来可采用自适应进化调度。
- **技能调用负担**：基于触发的技能加载会增加模型上下文负担。论文观察到两种失败模式：(1) 小模型有时将技能名称误当作环境动作输出；(2) 模型在不适用时过度使用技能。限制了在更小模型上的应用。
- **技能库大小敏感**：ALFWorld在技能库大小4时表现欠佳（87.1% vs 89.8%），提示不充分的技能库可能覆盖不全。
- **通用性验证有限**：虽然测试了5个域，但主要聚焦于搜索和具身任务；对实时交互性更强、需要严格安全约束的场景（如机器人控制、自动驾驶）未验证。
- **技能创建依赖外部LLM**：默认使用Claude 4.5 Sonnet进行技能创建，虽然论文也测试了用基模型创建（仍优于其他RL基线），但外部LLM的API成本和使用限制可能影响实际部署。
- **未考虑技能间的冲突或冗余**：技能库保持8个左右，但当技能增多时，自动管理的冲突检测机制尚不完善。
