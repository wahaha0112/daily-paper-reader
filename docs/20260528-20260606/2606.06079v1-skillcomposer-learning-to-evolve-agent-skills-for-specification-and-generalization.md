## 摘要
智能体技能由可重用的策略组成，这些策略指导智能体的推理和行动，在推理时展现出提升模型能力的强大潜力。然而，当前的技能构建方法将问题视为一次性提取，忽略了一个基本矛盾：针对特定任务定制的技能无法迁移，而抽象化的技能往往提供不足的指导。我们将这种脆弱性归因于缺乏明确的技能规范化和泛化机制。为了解决这一差距，我们引入了SkillComposer，一个将技能构建分解为三个可学习操作：创建、改进和合并的框架。通过系统的拒绝采样方案训练，SkillComposer使语言模型能够在推理时自我进化技能，并支持三种部署模式：离线构建通用库、在线进行任务特定细化以及混合结合两者。在τ^2-Bench、LiveCodeBench v6和AppWorld上的全面实验表明，SkillComposer始终优于基线。我们的SkillComposer-4B将27B执行器在智能体任务上提升了高达+4.5，在代码任务上提升了+3.4，同时能够泛化到训练中未见过的领域和任务类型。分析表明，合并和改进操作解决的是正交的质量维度，并且技能组合是一种可迁移的元能力，为技能增强推理提供了一种实用方法。

## Abstract
Agent skills, which consist of reusable strategies that guide agent reasoning and action, have shown strong potential for improving model capability at inference time. However, current skill construction methods treat the problem as one-shot extraction, overlooking a fundamental tension: a skill tailored to the specific task fails to transfer, while the abstracted skill often provides insufficient guidance. We attribute this fragility to the absence of explicit mechanisms for skill specification and generalization. To address this gap, we introduce SkillComposer, a framework that decomposes skill construction into three learnable operations: create, improve, and merge. Trained via systematic rejection sampling recipe, SkillComposer enables language models to self-evolve skills at inference time and supports three deployment modes: offline for building generalized libraries, online for task-specific refinement, and hybrid for combining both. Comprehensive experiments on $τ^2$-Bench, LiveCodeBench v6, and AppWorld show that SkillComposer consistently outperforms baselines. Our SkillComposer-4B improves a 27B executor by up to +4.5 on agent tasks and +3.4 on code tasks, while generalizing across domains and task types unseen during training. Analysis reveals that merge and improve address orthogonal quality dimensions and that skill composition is a transferable meta-ability, providing a practical recipe for skill-augmented inference.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题**：当前智能体技能（agent skills）的构建方法采用一次性提取（one-shot extraction），导致一个根本矛盾：过于针对特定任务的技能无法迁移，而过度抽象化的技能则提供不足的指导。现有方法缺乏显式的**规范化**（specification）和**泛化**（generalization）机制。
- **研究动机**：希望使语言模型能够在推理时自主演化技能，同时兼顾任务特异性与跨任务泛化性，无需人工编写或依赖外部优化循环。
- **整体含义**：SkillComposer 将技能构建分解为三个可学习操作（创建、改进、合并），通过拒绝采样训练使模型获得自我演化技能的能力，并支持三种部署模式，为技能增强推理提供了一套实用且可扩展的方案。

## 2. 方法论

### 核心思想
- 技能被定义为一个三元组：名称（name）、描述（description，触发条件）、主体（body，过程化策略）。
- 将技能构建分解为三个可学习的操作，形成完整的技能生命周期：从原始轨迹创建 → 通过合并泛化 → 通过改进规范化。

### 关键技术细节
- **Skill Create**：从无技能引导的原始执行轨迹中提取可重用技能：  
  `s = SkillComposer_create(x, LLM(x))`
- **Skill Merge**：合并两个语义相似的技能（通过多视图相似度计算，综合名称、描述、主体三个维度的余弦相似度），产生更通用、更简洁的技能：  
  `s = SkillComposer_merge(s1, s2)`  
  相似度阈值 δ = 0.8，只有相似度超过阈值时才执行合并。
- **Skill Improve**：基于已有技能和在新任务上的执行轨迹，对技能进行迭代细化：  
  `s = SkillComposer_improve(x, s_o, LLM(x, s_o))`

### 训练方式：拒绝采样（Rejection Sampling）
- 使用 **delta pass rate** 作为质量信号：只有候选技能使执行器的 pass@1 相对于基线（无技能/原技能）提升超过阈值 ϵ（均为 0.4）时，才被保留为训练样本。
- 共合成约 7000 条 SFT 数据，使用 Qwen3.5-4B 作为技能编写器和执行器，数据来源包括 OpenCodeReasoning（代码任务）和 AutoForge 合成的类似零售域的智能体数据。
- 最终对 Qwen3.5-4B 进行 LoRA 微调，超参数：学习率 1e-6、批次大小 64、3 个 epoch、序列长度 65536、余弦学习率调度、warmup 比例 0.1。

### 三种部署模式
- **离线模式**：先在训练集上通过创建和合并构建通用技能库，推理时检索并自选择相关技能。
- **在线模式**：空技能库，每遇到一个任务先创建技能，再迭代改进 T 次（实验中 T=5）。
- **混合模式**：用离线库初始化，再在线细化各任务技能。

## 6. 主要结论与发现

1. **SkillComposer 一致优于所有基线**：在线模式在 LiveCodeBench 提升最多（+2.5 on 4B），混合模式在 τ²-Bench 最佳（+6.2 on 4B）。MemP 反而可能降低代码性能（-9.2）。
2. **SFT 带来实质提升**：训练后的模型相比未训练版本在 τ²-Bench 和 LiveCodeBench 均有 2-2.4 点提升。
3. **Merge 和 Improve 互补**：Merge 驱动泛化（离线库最大收益），Improve 驱动规范化（在线设置关键），两者解决正交质量维度。
4. **技能组合能力是可迁移元能力**：纯智能体训练也能提升代码任务（+1.5），跨任务类型转移有效。
5. **迭代改进优于同等预算的重复采样**：在相同推理轮次下，SkillComposer 的 pass@k 持续高于独立 pass@k，差距随轮次扩大（4B 上 k=5 时 73.71 vs 69.71）。
6. **跨模型泛化有效**：4B 编写的技能可有效提升 27B 执行器性能（+4.5 agent, +3.4 code）。
7. **跨域泛化**：仅从零售域训练，在航空和电信域取得显著提升。

## 7. 优点
