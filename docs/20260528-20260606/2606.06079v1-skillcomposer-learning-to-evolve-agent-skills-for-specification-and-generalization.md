## 摘要
代理技能由指导代理推理和行动的可重用策略组成，在推理时提升模型能力方面展现出巨大潜力。然而，当前的技能构建方法将问题视为一次性提取，忽视了一个根本性的矛盾：针对特定任务定制的技能难以迁移，而抽象化的技能往往提供的指导不足。我们将这种脆弱性归因于缺乏技能规范化和泛化的显式机制。为解决这一问题，我们引入了SkillComposer，一个将技能构建分解为三个可学习操作的框架：创建、改进和合并。通过系统性的拒绝采样方法训练，SkillComposer使语言模型能够在推理时自我进化技能，并支持三种部署模式：用于构建通用库的离线模式、用于任务特定优化的在线模式以及结合两者的混合模式。在τ²-Bench、LiveCodeBench v6和AppWorld上的全面实验表明，SkillComposer始终优于基线。我们的SkillComposer-4B将27B的执行器在代理任务上提升高达+4.5，在代码任务上提升+3.4，同时在训练中未见过的领域和任务类型上也能泛化。分析表明，合并和改进操作分别处理正交的质量维度，且技能组合是一种可迁移的元能力，为技能增强推理提供了实用方法。

## Abstract
Agent skills, which consist of reusable strategies that guide agent reasoning and action, have shown strong potential for improving model capability at inference time. However, current skill construction methods treat the problem as one-shot extraction, overlooking a fundamental tension: a skill tailored to the specific task fails to transfer, while the abstracted skill often provides insufficient guidance. We attribute this fragility to the absence of explicit mechanisms for skill specification and generalization. To address this gap, we introduce SkillComposer, a framework that decomposes skill construction into three learnable operations: create, improve, and merge. Trained via systematic rejection sampling recipe, SkillComposer enables language models to self-evolve skills at inference time and supports three deployment modes: offline for building generalized libraries, online for task-specific refinement, and hybrid for combining both. Comprehensive experiments on $τ^2$-Bench, LiveCodeBench v6, and AppWorld show that SkillComposer consistently outperforms baselines. Our SkillComposer-4B improves a 27B executor by up to +4.5 on agent tasks and +3.4 on code tasks, while generalizing across domains and task types unseen during training. Analysis reveals that merge and improve address orthogonal quality dimensions and that skill composition is a transferable meta-ability, providing a practical recipe for skill-augmented inference.

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：当前大语言模型（LLM）在代理任务中依赖“一次性提取”的技能构造方式，导致两种矛盾：针对特定任务定制的技能无法迁移到其他类似任务（缺乏泛化），而高度抽象的技能又无法为具体任务提供足够细致的指导（缺乏特化）。现有方法缺乏显式机制来平衡技能的**规范化（specification）**与**泛化（generalization）**。
- **整体含义**：作者提出技能构造应被视为一个可学习的演化过程，而非一次性的静态提取。通过将技能生命周期拆分为**创建（create）**、**改进（improve）**和**合并（merge）**三个可学习操作，语言模型能够在推理时自我演化技能库，从而同时实现特化与泛化。这为轻量级、可解释的智能体能力增强提供了新范式。

## 2. 方法论：核心思想、关键技术细节、算法流程

### 核心思想
- 将技能构造过程分解为三个可学习的操作，通过拒绝采样（rejection sampling）训练语言模型，使其具备在推理时自主创建、改进和合并技能的能力。
- 技能定义为三元组：**名称（name）**、**描述（description）**、**主体（body）**。主体为可重用的过程性知识。
- 提出**增量通过率（delta pass rate）**作为质量信号，过滤出有效的训练样本。

### 关键技术细节
- **Skill Create（创建）**：从无技能引导的原始轨迹中提取可重用技能：`s = SkillComposer.create(x, LLM(x))`。
- **Skill Merge（合并）**：将两个语义相似的技能合并为一个更泛化的技能。相似度采用多视角相似度计算（名称、描述、主体三部分的余弦相似度平均），仅高于阈值 δ 的合并：`sim(s1, s2) = 1/3 * (sim(n1,n2)+sim(d1,d2)+sim(b1,b2))`。
- **Skill Improve（改进）**：基于现有技能引导下的新轨迹，对技能进行迭代优化，使其更适应目标任务：`s = SkillComposer.improve(x, s_old, LLM(x, s_old))`。

### 训练流程（拒绝采样）
- 使用基础模型生成候选技能，计算使用该技能前后执行器的 pass@k 差值（增量通过率）。
- 仅当改善超过阈值 ϵ 时才保留训练样本。
  - **Create**：∆create = pass@1(LLM(x, s)) - pass@1(LLM(x)) ≥ ϵc
  - **Merge**：∆merge = 1/2 * Σ[pass@1(LLM(x_i, s)) - pass@1(LLM(x_i, s_i))] ≥ ϵm
  - **Improve**：∆improve = 1/2 * Σ[pass@1(LLM(x_i, s)) - pass@1(LLM(x_i, s_old))] ≥ ϵi
- 最终使用约 7,000 条监督微调数据训练 Qwen3.5-4B。

### 三种部署模式（算法流程）
1. **离线模式**：从训练集原始轨迹创建技能，然后迭代合并所有相似技能对，构建通用库。推理时检索 top-k 技能，由执行器自我选择。
2. **在线模式**：无需预建库，对每个新任务创建初始技能，然后循环 T 次：使用当前技能执行任务 → 根据轨迹改进技能。无预建库，适合流式场景。
3. **混合模式**：先用离线模式构建通用库，再对每个任务检索并在线改进，兼顾泛化与特化。
