## 摘要
当前智能体技能主要由自由形式的散文构成，要求智能体在每个会话中阅读、解释并重新推导如何行动。这带来了两个叠加成本：在实现密集型任务上可靠性降低，以及技能创建和改进的困难，因为编辑散文是一个脆弱的过程，人类和智能体都难以应对，特别是对于模型训练中代表性不足的领域特定程序性知识。智能体指令协议（AIP）通过将技能建模为有向执行图来解决这两个问题：离散步骤作为节点，由确定性脚本或自然语言描述支持，通过显式类型化的输入/输出边连接，并由经过模式验证的YAML规范管理。一个编译器元技能将现有人类编写的技能转换为这种形式。其好处是双重的。首先，将人类编写的技能编译为AIP，使Claude Sonnet在SkillsBench的27个真实智能体任务上的平均任务奖励从0.60提高到0.71，通过率从53%提高到67%——这是统计上显著的提升（Wilcoxon符号秩检验p=0.011），以13个平局赢得12个任务对2个失败，且通常耗时更少。该图为智能体提供经过验证的可运行单元，而不是要求它从自然语言重新推导代码、命令和工具调用。其次，在创建和改进方面，由于每个技能都经过模式验证、功能可测试且可逐节点寻址，因此可以精确地诊断和修复故障。两个已编写技能的故障被追溯到脚本层面。在调整AIP规范并重新编译后，两者均恢复且无回归（一个任务从0/5变为5/5），将技能改进转变为可测量的调优循环，而非散文重写。相同的图结构支持语料库级别的治理和技能内省，并为技能的强化学习提供了自然的动作空间。

## Abstract
Agent Skills today consist largely of free-form prose requiring the agent to read, interpret, and re-derive how to act in every session. This imposes two compounding costs: reduced reliability on implementation-heavy tasks, and difficulty in skill creation and improvement, since editing prose is a fragile process that both humans and agents struggle with, particularly for domain-specific procedural knowledge underrepresented in model training. The Agent Instruction Protocol (AIP) addresses both by modeling a skill as a directed execution graph: discrete steps as nodes backed by deterministic scripts or natural-language descriptions, connected by explicit typed input/output edges, and governed by a schema-validated YAML specification. A compiler meta-skill translates existing human-written skills into this form. The benefits are twofold. First, compiling human-written skills to AIP raised Claude Sonnet's mean task reward from 0.60 to 0.71 and pass rate from 53% to 67% across 27 real agent tasks from SkillsBench - a statistically significant gain (Wilcoxon signed-rank p = 0.011), winning 12 tasks to 2 with 13 ties - often in less wall-clock time. The graph delivers vetted, runnable units to the agent rather than asking it to re-derive code, commands, and tool calls from natural language. Second, on creation and improvement, because each skill is schema-validated, functionally testable, and addressable node-by-node, failures can be diagnosed and repaired precisely. Two authored-skill failures were traced to the script level. After adjusting the AIP spec and recompiling, both recovered with zero regressions (one task going from 0/5 to 5/5), turning skill improvement into a measurable tuning loop rather than a prose rewrite. That same graph structure supports corpus-level governance and skill introspection, and provides a natural action space for reinforcement learning over skills.

### 2. 论文提出的方法论：核心思想、关键技术细节、算法流程

- **核心思想**：将技能建模为**有向执行图**（directed execution graph），节点是离散步骤，边是显式类型化的输入/输出。

  - **节点类型**：

    - **自然语言描述节点**（description step）：用于需要推理、判断或人机交互的步骤，以自然语言说明。
  - **边**：显式的输入/输出连接，带有类型信息（如 `string`, `object`），使数据流可检查和验证。
  - **控制修饰符**：支持 `depends_on`（依赖排序）、`parallel`（并行）、`one_of`（选择分支）等 DAG 结构。
  - **元数据**：包括 `trigger_when`、`scope_and_approval`、`anti-patterns` 等，作为类型化卫星节点附加。
  - **格式**：整个图以**经过 Schema 验证的 YAML 规范**描述，存放在 SKILL.md 中，跟随原有的 Agent Skills 目录结构。
  - **编译器元技能**（compiler meta-skill）：一种特定的元技能，由 Claude Code Agent 执行，能够将现有人类编写的技能（或任务指令、文档等）转换为 AIP 格式。编译过程中进行 Schema 验证，强制处理歧义和类型错误。
- **算法流程（以文字描述）**：
  1. **输入**：人类编写的技能（自然语言散文或现有 SKILL.md）。
  2. **编译**：编译器元技能解析输入，提取步骤依赖和数据类型，生成有向执行图 YAML，并创建相应的脚本（scripts/）和参考资料（references/）。

### 6. 论文的主要结论与发现

- **主要结论**：将人类编写的技能编译为 AIP 有向执行图，能够显著提升智能体任务执行的平均奖励和通过率，同时赋能精确的故障诊断与修复。
- **具体发现**：
  - 在 27 个任务上，AIP 编译后平均任务奖励从 **0.599 提升至 0.705**（+0.106），通过率从 **53.3% 升至 67.4%**（Wilcoxon p=0.011），赢得 12 个任务对 2 个，13 个平局。

  - AIP 的图结构使技能可查询（语料库治理）并为强化学习提供有界、类型化的动作空间。

### 8. 不足与局限：包括实验覆盖、偏差风险、应用限制

- **格式-作者混杂**：编译后 AIP 既改变了表示格式，也改善了脚本质量，无法分离两个因素（未进行“相同脚本但以散文呈现”的控制实验）。
- **统计效力不足**：每任务仅 5 次试验，Wilcoxon 检验仅基于 12-14 个非平局对，限制了细粒度分析。
- **验证器二值化**：许多任务验证器为全对/全错，导致大量平局，降低奖励信号的区分能力。
- **子集不纯**：27 个任务中 3 个为早期 v0.3a2 版本，非分层采样，但 24 任务子集结果一致。
- **预算封顶任务**：两个任务（energy-unit-commitment 和 Civilization 6）因达到执行预算而无有效结果，实际影响未知。
- **单模型**：仅使用 Claude Sonnet，未验证其他模型（如 GPT-4o、Gemini、开源），尤其弱模型可能获益更大或更小，结果泛化性存疑。
- **编译器元技能模型**：作者使用 Claude Opus 4.7 进行编译，可能引入高质量脚本而非纯粹结构贡献；实际应用中若使用较弱模型编译，效果可能下降。
- **应用限制**：AIP 当前仍是“规范”而非“协议”，运行时代理仍需自行推理图遍历顺序，未被强制执行；对于更小的模型，依赖代理自身纪律可能仍是瓶颈。
