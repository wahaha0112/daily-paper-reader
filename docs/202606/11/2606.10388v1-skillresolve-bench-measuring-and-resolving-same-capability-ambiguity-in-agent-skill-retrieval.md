## 摘要
智能体技能库正成为可路由的软件资产：检索到的技能可以为智能体提供指令、脚本、资源绑定和执行假设。这使得技能检索不仅仅是广泛的相关性匹配。检索器可能找到正确的能力家族，却暴露了错误的同能力代表。我们将这种失败称为同能力执行风险检索。每个查询将一个有用的技能与一个查询特定的风险兄弟技能配对，该兄弟技能共享能力家族但可能导致执行指向过时资源、缺失前提条件或错误流程。我们引入了SkillResolve-Bench 1.0，这是一个可审计的基准测试，包含661对有用/风险技能对、源角色和准入证据、线索/泄漏检查、查询不相交分割，以及包含6,660个公共SkillRet候选的7,982个候选池。该基准报告了有用性排序以及有害兄弟率（HSR@K），即风险兄弟技能在前K位中的暴露情况。我们还提供了SkillResolve，一种参考方法，它解析活跃的候选家族，根据混淆的库负样本和合同配置文件线索对查询条件效用进行评分，并在最终的前K列表之前从每个家族中选择一个代表。在已发布的关系下，SkillResolve在保持HSR@3=0的同时，达到了Recall@3=0.766和NDCG@3=0.699。与SkillRouter相比，它将Recall@3提高了0.112，NDCG@3提高了0.165，同时将HSR@3从0.693降至0。如果没有代表选择，在相同的评分器下，HSR@3会上升到0.236，这表明家族内代表选择是将能力检索转化为更安全的程序暴露的机制。

## Abstract
Agent skill libraries are becoming routable software assets: a retrieved skill can contribute instructions, scripts, resource bindings, and execution assumptions to an agent. This makes skill retrieval more than broad relevance matching. A retriever can find the right capability family yet expose the wrong same-capability representative. We study this failure as same-capability execution-risk retrieval. Each query pairs a helpful skill with a query-specific risky sibling that shares the capability family but can lead execution toward a stale resource, missing precondition, or wrong procedure. We introduce SkillResolve-Bench 1.0, an auditable benchmark for this setting with 661 helpful/risky pairs, source-role and admission evidence, cue/leakage checks, query-disjoint splits, and a 7,982-candidate pool that includes 6,660 public SkillRet candidates. The benchmark reports helpful ranking together with harmful sibling rate (HSR@K), the top-K exposure of the risky sibling. We also provide SkillResolve, a reference method that resolves active candidate families, scores query-conditioned utility from confusable library negatives and contract-profile cues, and selects one representative from each family before the final top-K list. Under the released family relation, SkillResolve reaches Recall@3 0.766 and NDCG@3 0.699 while keeping HSR@3=0. It improves over SkillRouter by 0.112 Recall@3 and 0.165 NDCG@3 while reducing HSR@3 from 0.693 to 0. Without representative selection, HSR@3 rises to 0.236 under the same scorer, identifying within-family representative choice as the mechanism that turns capability retrieval into safer procedural exposure.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：在智能体技能库检索中，存在“同能力歧义”问题——检索器能够定位到正确的能力家族（capability family），但可能从该家族中选取了一个对当前查询有害的执行代表（risky sibling）。该有害代表与有用技能（helpful skill）共享相同的领域词汇和流程结构，但指向过时资源、缺失前提条件或错误操作，导致智能体执行时产生风险。
- **研究动机**：现有技能检索工作（如SkillRet、SRA-Bench）主要关注广义相关性匹配，忽略了同家族内不同代表之间的执行风险差异；而安全研究（如MalSkillBench、SkillGuard）侧重于恶意技能检测，但未解决检索阶段的无意暴露问题。实际公共技能库中，约47.3%的查询在前三结果中会暴露同一能力家族的非目标技能，其中36.6%同时包含有用技能和严格同家族兄弟技能，因此需要一个专门的可审计基准和方法来度量并缓解这种风险。
- **整体含义**：该工作将技能检索的目标从“找到相关能力”扩展为“找到正确的可执行代表”，强调在检索阶段就必须解决族内歧义，以避免将执行风险引入智能体上下文。

### 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：将同能力执行风险检索分解为三个步骤：能力解析（Capability Resolution）→ 查询条件效用评分（Utility Scoring）→ 代表选择（Representative Selection）。最终只保留每个活跃能力家族中效用最高的一个候选进入Top-K列表。
- **关键技术细节**：
  1. **任务形式化**：每个查询 \(q_i\) 关联一个有用技能 \(s^+_i\)、一个风险兄弟 \(s^-_i\)，以及一个基准家族关系 \(g^*\)。候选池包含其他无关和部分相关的公共技能（如SkillRet的6660个技能）。  
  2. **能力解析（Capability Resolver）**：给定查询和候选池，输出一组互不相交的候选分组 \(\{G_1, \ldots, G_m\}\)，每个分组内的候选被视为同一能力家族的替代代表。可使用基准关系、公开元数据/标题或文本聚类作为解析来源。  
  3. **效用学习（Utility Learning）**：训练一个线性评分器 \(F_\theta(q,s) = \alpha a(q,s) + (1-\alpha) \theta^\top \phi(q,s)\)。  
     - \(a(q,s)\) 为基于归因投票的库级相关性分数；  
     - \(\phi(q,s)\) 包含基础特征（TF-IDF、字符n-gram、倒数秩融合、路由视图分数等）和契约配置文件特征（contract-profile cues），后者对标资源绑定、前提条件、API/时间范围、输出模式、流程和标识符六个执行维度进行关键词和字面量检测与对比；  
     - 负样本来自查询条件混淆负例（confusable library negatives），即当前候选池中除有用技能和风险兄弟外，经基础归因投票排序靠前的候选（最多5个）；  
     - 损失函数为成对逻辑回归损失，训练目标是让有用技能的得分高于混淆负例。  
  4. **代表选择（Representative Selection）**：对每个解析出的分组 \(G\)，计算组内每个候选的效用 \(u_s = F_\theta(q,s)\)，选取 \(\hat{s}_G = \arg\max_{s \in G} u_s\) 作为该组代表。最终只对所有代表按效用排序输出Top-K列表。
- **算法流程**（Algorithm 1）：输入查询q、候选池、解析器、已训练评分组件，输出Top-K技能列表。先进行能力解析得到分组，对每个分组内候选计算效用，选出每组最高效用代表，再对这些代表排序取前K个。

### 6. 论文的主要结论与发现

1. **同能力风险普遍存在**：在SkillRet审计中，47.3%的查询在Top-3中暴露同一家族的风险兄弟，36.6%同时包含有用和风险兄弟。
2. **相关性导向的检索器无法避免风险**：BGE、RRF、SkillRouter在Recall@3=0.461~0.654的同时，HSR@3高达0.461~0.693，表明它们常常将两个兄弟都排在高位。
3. **SkillResolve有效消除了风险暴露**：在保持Recall@3=0.766、NDCG@3=0.699的同时，HSR@3=0。相比SkillRouter，Recall提高0.112，HSR降低0.693。
4. **代表选择是关键机制**：移除代表选择后，相同评分器的Recall@3仅下降0.004，但HSR@3从0暴涨至0.236，证明族内代表选择是控制风险的核心，而非单纯提高相关性评分。
5. **契约特征和混淆负例训练有辅助提升**：契约特征带来微小的Recall提升（0.008）；混淆负例比BM25负例在Recall@3上高出0.059。
6. **多种能力解析源均能实现HSR=0**：使用元数据/标题或文本聚类解析，在固定评分器下也能达到HSR@3=0，但形成更宽的分组，表明解析精度与风险控制之间需要权衡。
