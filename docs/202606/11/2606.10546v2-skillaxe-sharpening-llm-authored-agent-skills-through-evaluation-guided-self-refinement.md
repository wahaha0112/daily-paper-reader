## 摘要
技能文档（即指导大型语言模型智能体的结构化自然语言指令）对现代智能体框架至关重要，然而大型语言模型在编写实际可用的技能方面存在困难。在SkillsBench上，人类编写的技能使通过率提升16.2个百分点，而LLM编写的技能则没有带来可衡量的提升。我们提出SkillAxe，一个完全无监督的框架，使LLM能够迭代地诊断和优化自身技能。SkillAxe将技能质量分解为四个可解释维度（质量影响、触发精度、指令遵循与故障归因、解决方案路径覆盖），生成结构化改进简报，无需真实标签、测试套件或环境奖励。在SkillsBench上，与未经优化的LLM技能相比，SkillAxe将通过率相对提升28%，并缩小了与人类编写技能之间47%-67%的差距。我们在SpreadsheetBench上验证了该方法作为持续改进引擎的实用性，其中SkillAxe构建的技能库从过去的智能体轨迹中学习，仅使用22个技能就将通过率从16.0%提升至52.0%。

## Abstract
Skill documents, structured natural-language instructions that guide Large Language Model (LLM) agents, are critical to modern agent frameworks, yet LLMs struggle to write skills that actually work. On SkillsBench, human-authored skills improve pass rates by 16.2 percentage points, while LLM-authored skills provide no measurable gain. We introduce SkillAxe, a fully unsupervised framework that enables LLMs to iteratively diagnose and refine their own skills. SkillAxe decomposes skill quality into four interpretable dimensions (quality impact, trigger precision, instruction compliance with fault attribution, and solution-path coverage), producing structured improvement briefs that require no ground-truth labels, test suites, or environment rewards. On SkillsBench, SkillAxe improves pass rates by 28\% relative over unimproved LLM skills and closes 47--67\% of the gap to human-authored skills. We validate the approach as a continuous improvement engine in the wild on SpreadsheetBench, where a SkillAxe-built skill library learns from past agent trajectories and raises pass rate from 16.0\% to 52.0\% using only 22 skills.

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：LLM（大型语言模型）编写的结构化技能文档（skill documents）在实际执行任务时几乎无法提升智能体性能，而人类编写的技能文档能显著提升通过率（+16.2个百分点）。现有技能开发和评估主要依赖人工试错或粗粒度的任务级通过/失败信号，缺乏可操作、可归因的诊断反馈，导致系统性改进困难。
- **研究背景**：技能文档是现代LLM智能体框架的关键组件，用于编码领域知识、API使用模式和流程策略。然而，自动化的技能精炼（self-refinement）面临两大障碍：一是缺乏细粒度的失败归因（技能本身缺陷 vs. 智能体执行错误）；二是需要人类提供的测试套件或环境奖励才能评估技能质量。
- **整体含义**：本文旨在解决“如何让LLM在没有外部监督的情况下自主改进自身编写的技能文档”这一重要问题，通过设计一套完全无监督的诊断-改进框架（SkillAxe），使LLM能够像人类专家一样识别技能缺陷并进行针对性修正，从而缩小LLM生成技能与人类技能之间的性能差距。

## 2. 方法论：核心思想、关键技术细节

### 核心思想
SkillAxe 将技能质量分解为四个互补、可解释的维度，通过对比智能体“有技能”和“无技能”时的行为差异，提取结构化改进简报（improvement brief），指导LLM迭代重写技能。整个过程无需真实标签、测试套件或环境奖励，仅依赖任务指令和智能体输出。

### 关键技术细节
1. **质量影响（Quality Impact）**：评估技能对任务完成度的整体贡献。通过有/无技能的两次输出进行配对比较，得到方向（+1/-1/0）和幅度（0~1），综合为[-1,1]分数。负分表示技能损害了性能，需要进一步诊断。
2. **触发精度（Trigger Precision）**：判断技能是否在合适的任务上被激活。从技能描述中提取正向触发短语和负向（排除）短语，用上下文感知的词嵌入计算三个几何指标：
   - **覆盖广度**（Coverage Breadth）：正向短语间的平均余弦距离，衡量触发范围是否太窄。
   - **负向特异性**（Negative Specificity）：负向短语与其最近正向短语的距离，衡量排除是否充分。
   - **边界锐度**（Boundary Sharpness）：最小正负短语距离，揭示决策边界的模糊程度。
3. **指令遵循与故障归因（Instruction Compliance with Fault Attribution）**：将技能分解为可评估的规则（每个含严重度权重），针对每条规则评估：
   - **相关性**（ρ）：该规则是否适用于当前任务。
   - **遵循度**（a_i）：智能体实际执行情况（0~1）。
   - **规则质量**（g_i）：规则本身是否精确、可操作（0~1）。
   - **技能故障**（f_i）：失败归因于技能还是智能体（0~1）。
   - 综合计算技能得分 = Σ(w_i * g_i * c_i)/Σ(w_i)，其中 c_i = a_i + (1-a_i)*(1-f_i) 为故障调整后的信用分。该设计能区分“技能写得好但智能体没执行”和“技能本身模糊”两种情况，避免错误地修改有效规则。
4. **解决方案路径覆盖（Solution-Path Coverage）**：评估技能是否支持任务可能的多条执行路径。由LLM枚举合理的解决方案路径，计算每条路径与技能文本块的最大余弦相似度，然后取平均。低覆盖意味着技能只覆盖狭窄的行为空间。

### 整体流程（Phase 1-4）
- **Phase 1**：智能体分别在无技能和有技能条件下执行同一任务，得到输出对比。
- **Phase 2**：四个诊断模块计算上述指标，生成结构化改进简报。
- **Phase 3**：LLM根据简报重写技能。
- **Phase 4**：迭代收敛（论文中实验仅执行一次迭代）。

## 6. 主要结论与发现

1. **LLM自写技能无效**：在SkillsBench上，LLM-self技能几乎没有提升（32.5% vs 无技能26.7%），与人类技能的提升（51.9%）形成鲜明对比。
2. **SkillAxe显著提升**：

   - 提升主要由**执行可靠性（Coverage）** 驱动：覆盖率从49.4%升至72.7%，而完成任务的正确率（Quality）不变（57.1%）。技能主要提供了程序性知识（库使用、格式处理、避免崩溃），而非改善答案质量。

## 7. 优点

- **完全无监督**：无需人工标签、测试套件或环境奖励，仅依赖任务指令和agent输出，可广泛应用于任意agent部署场景。
- **可解释性**：四个诊断维度均具有语义解释性，改进建议可直接追溯到具体规则（如“规则太模糊” vs “agent未执行”），支持精准修改而非盲目重写。
- **故障归因能力**：将低遵循度细分为“技能责任”和“智能体责任”，避免错误修改有效规则，是该方法的核心创新。
- **效率与泛化**：在SpreadsheetBench上用68%更少的技能达到相同精度，且技能描述更清晰（激活率翻倍），表明自动改进能生成更紧凑、更易识别的技能库。
- **双层评估验证**：同时使用严谨的原生验证器和更灵活的公平评分器，揭示了测试套件偏见对结果的影响，增加了结论的可靠性。

## 8. 不足与局限

- **结构性错配检测缺失**：技能可能内在地教授完全错误的策略（如坚持错误的方法），但规则级评估无法发现这种结构性偏差，因为技能内部自洽且规则无明显违反。
- **技能交互未建模**：当前改进针对单个技能，忽略多个技能同时激活时可能存在的冲突或冗余，这在多技能场景中可能导致次优效果。
- **LLM评判者偏差**：指令遵循评估和公平评分都依赖LLM作为裁判，可能受位置偏差、校准误差或语义理解不足影响，尤其在处理复杂输出（如多页PDF、动态Excel）时可靠性需进一步验证。
- **单次迭代限制**：SkillsBench实验仅进行一次改进循环，未探索多轮迭代能否进一步缩小与人类技能的差距；人类技能仍有较大提升空间（原生质量75.5% vs SkillAxe 57.1%）。
- **实验规模有限**：SpreadsheetBench仅使用50个测试任务，且训练/测试拆分基于随机种子，可能引入偶然波动。此外，技能库构建的“FORK/IMPROVE/SKIP”路由机制依赖嵌入相似度阈值，未进行参数敏感性分析。
- **依赖强LLM**：方法依赖于高性能LLM（Claude Opus 4.5、GPT-5.4）作为评估和重写引擎，在较弱模型上的效果未知，可能无法迁移到小型开源模型。
