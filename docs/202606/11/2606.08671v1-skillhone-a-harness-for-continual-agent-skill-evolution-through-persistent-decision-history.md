## 摘要
智能体技能通过任务特定的流程、脚本和参考扩展了语言模型智能体，但它们所针对的任务和环境不断变化。现有方法在有限运行中改进技能，仅保留最终产物，丢弃了后续智能体解释先前修订、评估和拒绝的替代方案所需的决策历史。我们提出SkillHone，一个基于持久决策历史的持续智能体技能进化框架。SkillHone将技能修订与提供实践反馈的评估侧证据配对，记录诊断、修订、证据和结果的结构化历史。角色分离的子智能体在实践探针上运行候选技能，并带有修订后的报告，利用先前决策信息提出修订，从而无需重新发现过去的基本原理即可实现跨会话改进。我们在原始开放网络环境中对深度研究基准评估SkillHone，其中智能体没有集成搜索栈，必须通过可移植技能组织检索。我们与由商业检索服务支持的深度研究智能体进行比较。以Qwen3.6-35B-A3B作为评估时主干，生成的技能在GAIA上比深度研究智能体高出15.8分，在WebWalkerQA-EN上高出3.2分，同时也超过了先前的技能进化方法。

## Abstract
Agent skills extend language-model agents with task-specific procedures, scripts, and references, but the tasks and environments they target continually change. Existing methods improve skills in bounded runs and retain only the final artifact, discarding the decision history that later agents need to interpret prior revisions, evaluations, and rejected alternatives. We introduce SkillHone, a harness for continual agent skill evolution grounded in persistent decision history. SkillHone pairs skill revisions with evaluation-side evidence that supplies practice feedback, recording structured histories of diagnoses, revisions, evidence, and outcomes. Role-separated subagents run candidate skills on practice probes with redacted reporting and propose revisions informed by prior decisions, enabling cross-session refinement without rediscovering past rationale. We evaluate SkillHone on deep-research benchmarks in a raw open-web setting, where agents are not given an integrated search stack and must organize retrieval through portable skills. We compare against a deep-research agent backed by commercial retrieval services. With Qwen3.6-35B-A3B as the evaluation-time backbone, the resulting skills outperform the deep-research agent by 15.8 points on GAIA and 3.2 points on WebWalkerQA-EN, while also exceeding prior skill-evolution methods.

## 1. 论文的核心问题与整体含义（研究动机和背景）

智能体技能（Agent Skills）是语言模型智能体的重要扩展机制，它封装了任务特定的流程、脚本、参考和输出规范。然而，现实中的任务和环境不断变化（API变更、任务分布偏移、新失败模式出现），技能需要持续维护。现有多数方法（如Skill-Creator、Hermes-SE等）只在单次有限运行中改进技能，只保留最终产物（artifact），**丢弃了决策历史**——即导致修订的诊断、被拒绝的替代方案、评估证据及接受/拒绝的原因。这导致后续智能体无法理解以前优化的理由，容易重复旧修复、撤销有用变更，或在环境变化后无法有效延续改进。

**核心问题**：如何实现智能体技能的**持续跨会话进化**，使后续智能体能继承并利用完整的决策上下文，而不是仅得到一个优化后的快照。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 核心思想
SkillHone 是一个**面向智能体的框架**，它将技能视作**可演进的包**，与评估资产一起维护，并将**技能修订和评估证据都视为承载决策的记录**。通过持久决策历史，将诊断、候选修订、评估证据、结果链接起来，使后续智能体能审计先前变更、避免冗余编辑，并继续跨会话开发。

### 2.2 关键技术细节

#### 两个核心仓库
- **技能仓库**：存储当前技能包（SKILL.md、脚本、引用、模板等）。
- **技能-评估仓库**：存储实践探针（probes）、oracle目标、验证器、追踪、修订后的报告等评估资产。

#### 角色分离的子智能体（Subagent）
SkillHone 在运行时动态派遣**权限有界**的子智能体，分为两类：
- **优化侧（Optimization）**：可读写技能仓库，但只能访问修订后的评估报告，不能访问未修订的探针目标、验证器或追踪。
- **评估侧（Evaluation）**：可检查探针、目标和追踪，运行候选技能并产生修订后的报告，但不能写入技能仓库。

无固定多智能体系统，而是按需派遣。运行时调度器（Dispatcher）仅负责路由消息和记录决策，不直接编辑仓库。

#### 持久决策历史
每个开发步骤记录为一个决策元组：
```
h_t = (q_t, r_t, e_t, o_t)
```
其中 `q_t` 是诊断，`r_t` 是候选修订，`e_t` 是修订后的评估证据，`o_t` 是结果（接受/修订/拒绝/推迟）。  
决策历史 `H_t = {h_1, ..., h_t}` 被持久化，跨越会话。后续优化子智能体可根据新修订报告检索相关历史，避免重复诊断或冗余编辑。

#### 算法流程（文字说明）
初始技能 S0，技能仓库 Rs，评估仓库 Re。循环 t = 0..T-1：
1. 评估派遣运行当前技能 St 于 Re，输出修订报告 Ê_t。
2. 优化派遣检索 H_t，提出诊断 q_t 和修订 r_t。
3. 评估派遣返回针对 r_t 的修订证据 e_t。
4. 根据证据决定 o_t（接受/修订/拒绝/推迟）。
5. 若接受，则 S_{t+1} = Apply(S_t, r_t)，否则不变。
6. 更新 H_{t+1} = H_t ∪ {(q_t, r_t, e_t, o_t)}。
最终返回 S_T 和 H_T。

#### 优化与评估的绝缘
优化侧无法访问未修订的探针目标、验证器或追踪，防止评估反馈成为直接记忆目标。

## 3. 实验设计

### 3.1 基准与设置
- **任务领域**：深度研究（Deep Research）——信息检索类任务，需要代理组织搜索、导航、提取、验证和恢复。
- **基准数据集**：
  - **GAIA**（Mialon et al., 2024）：强调多步信息检索和事实性。
  - **WebWalkerQA-EN**（Wu et al., 2025）：英语分片，聚焦网页导航和信息提取。
- **两种评估设置**：
  1. **Cozy Search**：深度研究智能体使用商业检索服务，拥有预集成搜索栈。
  2. **Raw Open-Web**：无预集成搜索工具，智能体通过通用运行时和可移植技能组织检索，需要处理速率限制、不可用端点、页面格式变化等。

### 3.2 对比方法
所有 Raw Open-Web 方法共享相同的初始技能池（来源于 ClawHub 和 SkillHub 的社区技能，列表见附录）：
- **Existing-Skills**：直接加载技能，无优化。
- **Skill-Creator**：应用内置迭代技能优化。
- **Hermes-SE**：应用反思式技能优化。
- **SkillHone**：完整框架，包含角色分离子智能体、修订后反馈、持久决策历史。

### 3.3 开发与评估分离
- **开发控制器**：Claude Opus 4.6（用于读取反馈、诊断、修订技能）。
- **执行与评估主干**：Qwen3.6-35B-A3B（在开发和最终评分时运行技能，作为固定评估时间主干）。
