## 摘要
现代LLM智能体越来越依赖技能库来处理复杂任务，使得技能演化成为自我改进的主要驱动力。然而，孤立的单用户任务流缺乏构建全面技能所需的多样性。虽然跨用户协作可以克服这一数据瓶颈，但当前轨迹共享方法会损害用户隐私，并强加统一的全局库，无法适应客户端的异构性。我们提出FederatedSkill，一种用于协作智能体演化的隐私保护框架。FederatedSkill超越了原始轨迹共享，将语义技能差异（即对本地库的结构化补丁）作为通信的基本单元。在服务器端，一个演化智能体聚合这些补丁，动态建模客户端特定的能力边界，促进严格个性化的技能演化，而非次优的全局平均。在20个不同的智能体任务族上进行评估，FederatedSkill相比自我演化基线取得了显著提升，成功率最高提升44.4%，计算成本降低37.5%。

## Abstract
Modern LLM agents increasingly rely on skill libraries to handle complex tasks, making skill evolution a primary driver of self-improvement. However, isolated single-user task streams lack the diversity required to build comprehensive skills. While cross-user collaboration can overcome this data bottleneck, current trajectory-sharing approaches compromise user privacy and impose a uniform global library that fails to accommodate client heterogeneity. We introduce FederatedSkill, a privacy-preserving framework for collaborative agent evolution. Moving beyond raw trajectory sharing, FederatedSkill utilizes semantic skill diffs, structured patches over local libraries, as the fundamental unit of communication. On the server side, an evolution agent aggregates these patches to dynamically model client-specific capability boundaries, facilitating strictly personalized skill evolution rather than a suboptimal global average. Evaluated across 20 distinct agent task families, FederatedSkill demonstrates substantial gains over self-evolving baselines, achieving up to a 44.4% increase in success rate and a 37.5% reduction in computational cost.

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：现代LLM智能体通过维护技能库（skill library）来自我改进，但单一用户的任务流数据稀缺，导致技能库不完整。跨用户协作虽能缓解数据瓶颈，但现有轨迹共享方法存在两大障碍：  
  - **隐私泄露**：原始轨迹包含敏感内容（如网页隐私信息、机密数据），上传到外部服务器存在风险。  
  - **客户端异质性**：单一全局技能库无法适配不同模型家族、智能体框架和任务分布的个性化需求，导致次优性能。

- **整体含义**：本文旨在回答一个核心问题——用户如何在保护隐私的前提下协作演化技能，并同时获得针对自身需求的个性化技能库。通过将联邦学习思想引入智能体技能演化，FederatedSkill首次实现了隐私保护下的跨客户端协作技能进化。

## 2. 方法论

### 核心思想
- **语义技能差异（Semantic Skill Diff）**：客户端不上传原始轨迹，而是本地自演化后只上传结构化的技能补丁（patch），补丁包含对技能库的添加（ADD）、编辑（EDIT）和删除（DELETE）操作，类比Git提交。
- **服务器端演化智能体**：利用LLM构建的演化智能体（Evolution Agent）接收所有客户端的补丁，动态建模每个客户端的能力边界，生成**个性化更新**，而非全局平均。
- **部分可观测马尔可夫决策过程（POMDP）**：服务器仅能观测到客户端配置文件ρ和补丁δ，需推理底层能力状态，然后生成个性化更新Δ。

### 关键技术细节
- **客户端执行与补丁蒸馏**：
  - 客户端使用当前技能库执行任务，收集轨迹；本地映像器（patcher）将轨迹压缩、去敏，生成结构化补丁δ = (U, D, R, s)，其中U是文件更新（upserts），D是待删除路径，R是奖励，s是摘要。
  - 隐私设计：补丁仅包含泛化的技能语义，无原始交互文本；蒸馏在本地完成，服务器仅接收客户端模型认为可泛化的教训。
- **服务器端个性化演化（两阶段）**：
  - **阶段1：演化规划**：基于所有客户端补丁构建能力矩阵（记录每个客户端在每个工作流上的覆盖状态）、两层能力记忆（高层：家族共享；底层：客户端私有，记录模型特定失败模式），并生成可执行指令。
  - **阶段2：逐客户端库演化**：为每个客户端独立执行指令，吸收可迁移补丁，修复/重写技能以适配其配置文件。生成决策日志，更新低级记忆。

### 公式/算法流程（文字说明）
- 优化目标：最大化T轮内整体期望性能增益，约束条件为每轮仅观察到O_t = {(ρ_i, δ_i^t)}。
- 客户端性能：J_i(L) = E_{x~D_i, τ~π_i}[R_{i,x}(τ)]。
- 补丁生成：δ_i^t = g_i(L_i^t, B_i^t, ρ_i)。
- 库更新：L_i^{t+1} = Apply(L_i^t, Δ_i^t)，其中Δ_i^t由演化智能体M根据O_t生成。

## 3. 实验设计

- **Benchmark**：SkillFlow（Zhang et al., 2026d），包含20个不同的任务族，每个族内任务按难度递增排列，要求智能体顺序演化技能。初始化空技能库，评估平均任务完成率。
- **对比方法**：主要基线为**自我演化（Self-Evolution, SE）**，即每个客户端独立使用自己的轨迹演化技能，无任何协作。
- **实验设置**：使用三个不同骨干模型（Qwen3.6-Plus、GLM-5、Kimi K2.5）及不同智能体工具链（Claude Code、Qwen Coder、Kimi CLI），设置三种异质性场景：
  1. **同质**：所有客户端使用相同模型（GLM-5）+ 相同工具链（Claude Code）。
  2. **异质骨干**：不同模型 + 相同工具链（Claude Code）。
  3. **异质骨干+工具链**：不同模型 + 各自原生工具链（Qwen Coder、Claude Code、Kimi CLI）。
- **服务器演化智能体**：使用GLM-5 + Claude Code实现，按两阶段确定性管道运行。
- **额外评估**：成本分析（API费用）、消融研究（个性化 vs 全局库）、通信开销、隐私审计、演化动力学（技能库大小变化）。

## 6. 主要结论与发现

- **性能提升显著**：FederatedSkill相比自我演化基线，在成功率上最高提升44.4%（如Kimi K2.5在Production-Capacity-Planning上从44.4%提升到88.9%），平均提升约5.82个百分点（异质骨干设置）。
- **成本降低**：每解决任务成本降低11%~37%，主要归功于避免技能库膨胀带来的长上下文开销。
- **个性化必要性**：消融实验表明，使用全局库比个性化库平均低9.8~12.2个百分点，验证了服务器端个性化演化的关键作用。
- **隐私保护有效**：技能补丁仅泄露5.08%的敏感实体，而个性化更新后降至0.09%（与随机基线无统计学差异）。PII金丝雀测试零泄露。
- **跨模型/工具链泛化**：即使在异质骨干+工具链设置下（最大异质性），FederatedSkill仍然有效，虽然增益略低于单一异质性设置，表明语义补丁能超越生成环境泛化。

## 7. 优点

1. **隐私-效用权衡优秀**：通过语义补丁替代原始轨迹，实现强隐私保护的同时，通过服务器端个性化聚合获得了显著性能提升。
2. **高度个性化**：利用演化智能体动态建模每个客户端的能力边界，输出定制化的技能库，而非一刀切的全局模型，解决了联邦学习中经典的异质性难题。
3. **轻量通信**：补丁大小仅为KB级别（全benchmark约3.5MB），远低于参数级联邦学习的数百MB，适合边缘部署。
4. **跨模型/框架泛化**：实验表明技能级联邦可自然地推广到不同LLM和工具链，这是参数级联邦学习难以实现的。
5. **可审计性**：补丁为纯文本，服务器可审查；决策日志记录了每步修改的来源和理由。
6. **成本效率**：同时提升性能和降低推理成本，体现了实际部署价值。

## 8. 不足与局限

1. **假设可信环境**：框架假设服务器和客户端均为“诚实但好奇”，未考虑恶意客户端上传有毒补丁的场景，需要未来引入防御机制。
2. **客户端规模有限**：实验中仅3个客户端，大规模联邦（数十至数百）下的收敛行为、通信效率尚未验证。
3. **系统优化未探索**：文献明确表示将其留作未来工作，如更高效的补丁传输模式、带宽压缩等。
4. **部分负迁移**：异质补丁吸收偶尔导致性能下降（如Kimi在Distribution-Center-Auditing上下降25个百分点），主要由于硬编码的域映射表在新任务上误引导。作者建议未来通过合并时更严格的库清洁来缓解。
5. **无形式化隐私保证**：隐私审计为经验性验证，缺乏差分隐私等理论保障。作者提示不要过度信任绝对安全性。
6. **计算资源需求高**：由于需要运行多轮LLM驱动演化循环，复现需要大量API调用和模拟时间，可能限制社区复现和扩展。
7. **仅使用单一基准**：评估基于SkillFlow，其他任务或更开放场景下的泛化能力未知。
