## 摘要
基于技能的LLM代理越来越依赖长程序文档，但全文档提示会浪费令牌并稀释对执行至关重要的信息。我们将此场景研究为技能内检索，其目标是在给定查询的情况下，从已知技能文档中选择最小且足以执行的上下文。我们提出了SkillPager，这是一个两阶段框架，离线将每个Markdown技能解析为类型化的语义节点，并利用最大边际相关性（MMR）在线进行全局的、查询条件化的节点选择。在包含395个技能和1975个查询的基准测试上，SkillPager实现了78.89%的LLM判断上下文充分性，而详尽的全文档基线为82.23%，同时提示令牌减少了47.04%。粒度消融实验表明，将相同的检索算法应用于原始固定长度块时，达到了可比的81.77%充分性，但令牌成本增加了28.81%，这表明效率提升是由类型化语义粒度驱动的，而非仅由检索算法驱动。在基于图的基线中，SkillPager比最强基线高出12.16%。进一步的消融实验表明，当支持性内容保留在候选池中并通过自适应方式选择，而非通过静态启发式方法移除时，其效果最佳。这些结果将类型化文档内检索确定为基于技能的代理面临的一个独特访问问题。

## Abstract
Skill-based LLM agents increasingly rely on long procedural documents, but full-document prompting wastes tokens and dilutes information critical to execution. We study this setting as intra-skill retrieval, where the goal is to select a minimal, execution-sufficient context from a known skill document given a query. We present SkillPager, a two-stage framework that parses each Markdown skill into typed semantic nodes offline and leverages Maximal Marginal Relevance (MMR) to perform global, query-conditioned node selection online. On a benchmark of 395 skills and 1,975 queries, SkillPager achieves 78.89% LLM-judged context sufficiency, compared to 82.23% for the exhaustive full-document baseline, while reducing prompt tokens by 47.04%. A granularity ablation shows that applying the same retrieval algorithm to raw fixed-length chunks reaches a comparable 81.77% sufficiency but increases token cost by 28.81%, demonstrating that efficiency gains are driven by typed semantic granularity rather than the retrieval algorithm alone. Among graph-based baselines, SkillPager outperforms the strongest baseline by a margin of 12.16%. Further ablations show that supporting content is most effective when retained in the candidate pool and selected adaptively rather than removed by static heuristics. These results identify typed intra-document retrieval as a distinct access problem for skill-based agents.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：基于技能的LLM代理（Skill-based LLM agents）在运行时需要频繁访问长程序文档（Markdown技能文档）。直接注入全文档不仅浪费大量令牌（token），而且因文档中混合了可执行步骤、示例、参数说明、错误处理、背景概念等大量非执行内容，导致关键执行信息被稀释，降低执行性能。
- **研究背景**：现有工作要么进行离线固定压缩（如SkillReducer），要么依赖手工标注图结构（如ObjectGraph），均无法实现查询自适应的全局节点选择。因此，该论文将问题形式化为“技能内检索”（intra-skill retrieval）：给定一个已知技能文档和一个执行查询，从中构造一个紧凑的上下文，既满足任务执行的信息需求，又显著降低令牌开销。
- **整体含义**：这是首次将技能内检索作为独立问题提出，与跨技能路由和通用语料检索解耦，为技能代理的高效上下文构建提供了新视角。

### 2. 论文提出的方法论：核心思想、关键技术细节

#### 核心思想
- **两阶段框架SkillPager**：
  - **阶段一（离线）**：将原始Markdown技能文档解析为**类型化语义节点**（typed semantic nodes），形成检索就绪的表示。
  - **阶段二（在线）**：基于查询，对全部节点进行**全局MMR（最大边际相关性）选择**，动态构造紧凑且充分的执行上下文。

#### 关键技术细节

##### 阶段一：执行语义解析（Execution Semantic Parsing）
- **片段分割**：按句子边界分割，保持代码块完整；合并以冒号或条件词结尾的句子与后续内容；合并连接词片段（如or, and, e.g.）至前句；同一标题下的列表项分组。
- **节点分类（六种类型）**：
  - `step`：可执行指令/动作
  - `example`：使用演示、代码片段
  - `param`：配置参数说明
  - `precondition`：执行前需满足的条件
  - `error_handling`：故障处理/恢复指导
  - `concept`：解释性/背景性内容（非可执行）
  - 前五种为“可执行节点”，`concept`为“非可执行节点”，但仍保留在候选池中供自适应选择。
- **边推断**（仅用于图基线比较，SkillPager在线阶段不使用）：
  - `sequence`：文档顺序相邻节点
  - `semantic`：嵌入余弦相似度 > 0.85 的节点对
  - `reference`：节点提到另一个节点标识符
  - `condition`：从前提节点指向其约束的步骤
- **缓存**：每个技能的节点集、节点嵌入、边集离线计算并持久缓存（395个技能共耗时9.83小时，4个并行worker，中位数约3.2分钟/技能），在线阶段无需重复LLM调用。

##### 阶段二：查询自适应MMR导航
- **MMR评分**：每次迭代选择最大化下式的节点：
  \[
  MMR(n) = \lambda \cdot \text{sim}(e_q, e_n) - (1-\lambda) \cdot \max_{s \in S} \text{sim}(e_s, e_n)
  \]
  其中\(e_q, e_n, e_s\)分别为查询、候选节点、已选节点的归一化嵌入，\(\lambda\)控制相关性和多样性的权衡，论文取\(\lambda=0.7\)。
- **早停**：当最佳候选节点边际价值为负（MMR < 0）时停止迭代。
- **动态预算**：两档预算策略：
  - 技能节点数 ≤ 100：\(k=20\)
  - 技能节点数 > 100：\(k=60\)
- **上下文组装**：将选中的节点按原始文档顺序重新排序后拼接成最终上下文。

### 3. 实验设计：数据集、基准与对比方法

#### 数据集：IntraSkill-Bench
- 来源：基于SkillRouter-Eval-Core数据集的easy分区。
- 组成：
  - 真实标注技能（ground-truth）：195个（排除`gt/licenses`空文件）
  - 池技能（pool）：从78,165个记录中分层采样200个（按7个命名空间：other, development, data, design, devops, testing, documents），随机种子42。
- 共395个技能，每个技能生成5个LLM查询（使用DeepSeek-V4-Flash），总查询数1,975。
- 技能文档长度：166~93,951字符（中位数4,163），解析后共22,774个语义节点（平均57.7节点/技能，中位数38）。
- 节点类型分布：concept占49.9%，param 22.7%，step 11.5%，example 11.1%，precondition 2.5%，error_handling 2.2%。

#### 评估协议
- **指标**：上下文充分性（Context Sufficiency）——由LLM法官（DeepSeek-V4-Pro）判断所选上下文是否包含执行该查询所需的关键信息。每个判断重复3次，多数投票。
- **人类验证**：96个查询-上下文对，82.29%一致率，Cohen's κ=0.646。
- **置信区间**：Bootstrap 95% CI（10,000次重采样）。

#### 对比方法
- **全文档提示**（Full-document prompting）：所有节点全部注入，作为参考基线。
- **贪婪图遍历**（Greedy graph traversal）：从入口节点开始贪婪跟随图边，直至增益阈值。
- **Top-k + 依赖补全**（Top-k + dependency completion）：先选Top-k相似节点，再添加其图前驱节点。
- **Naive chunk + MMR**：将文档切分为256 token固定长度块，应用相同MMR选择（控制检索粒度的影响）。
- 前三者均基于Stage 1相同的节点表示和嵌入，仅节点选择策略不同。

### 6. 论文的主要结论与发现

- **SkillPager在充分性接近全文档基线（78.89% vs 82.23%）的同时，令牌减少47.04%**，实现了接近的充分性但成本减半。
- **效率提升主要源于类型化语义节点粒度，而非MMR算法本身**：相同MMR算法应用于固定块时充分性相近（81.77%），但令牌增加28.81%。
- **全局MMR检索优于所有基于图的局部遍历基线**，比最强图基线（贪婪图遍历）高出12.16%。
- **概念节点应自适应保留而非静态过滤**：adaptive策略（86.67%）优于exec_only（78.26%）和密度阈值策略（62-63%），证明支持性内容在需要时才被选择，静态移除会损害充分性。
- **动态预算策略有效**：两档预算（k=20/60）在性能和效率之间取得Pareto最优。

### 7. 优点

1. **问题形式化清晰**：首次将技能内检索定义为独立问题，与跨技能路由和通用语料检索区分。
2. **两阶段架构合理**：离线解析 + 在线全局检索，兼顾效率与灵活性；离线缓存降低在线LLM调用，适合稳定仓库场景。
3. **类型化节点设计**：六种语义类型使候选池带角色信息，支持角色感知的多样性覆盖，优于纯语义相似度的块级方法。
4. **自适应概念处理**：不预设移除或保留，由MMR动态决定，避免静态启发式的缺陷。
5. **实验充分扎实**：多基线对比、多消融实验、人工验证、Bootstrap CI，结论可靠。
6. **实用性强**：令牌减少近半，充分性损失小，可直接部署在技能代理系统中。

### 8. 不足与局限

1. **评估仅限easy分区的合成查询**：未使用更难的分区或真实用户日志，结果泛化性存疑；合成查询可能引入嵌入空间偏差。
2. **仅衡量上下文充分性，未评价端到端执行成功率**：虽然有人类验证，但LLM法官仍可能遗漏执行中的细节错误。
3. **假设技能文档已知**：未考虑路由错误或多技能组合场景，实际代理中可能需跨技能上下文拼接。
4. **离线预处理有一次性成本**：对快速迭代或新增技能频繁的场景，每次解析约3.2分钟（中位数）可能成为瓶颈。

7. **未对比token级压缩方法（如LLMLingua）**：作者承认适用场景不同，无法直接友好比较。
