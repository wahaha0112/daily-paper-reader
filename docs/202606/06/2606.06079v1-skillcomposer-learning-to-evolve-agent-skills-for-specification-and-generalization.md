## 摘要
智能体技能由指导智能体推理与行动的可复用策略组成，在推理时提升模型能力方面展现出巨大潜力。然而，当前的技能构建方法将问题视为一次性提取，忽略了一个根本矛盾：为特定任务定制的技能难以迁移，而抽象化的技能又往往缺乏足够指导。我们将这种脆弱性归因于缺乏明确的技能规范与泛化机制。为解决这一问题，我们提出SkillComposer框架，将技能构建分解为三个可学习操作：创建、改进与合并。通过系统性拒绝采样方法训练，SkillComposer使语言模型能在推理时自我演化技能，并支持三种部署模式：用于构建通用库的离线模式、用于任务特定优化的在线模式以及结合两者的混合模式。在τ²-Bench、LiveCodeBench v6和AppWorld上的全面实验表明，SkillComposer始终优于基线方法。我们的SkillComposer-4B将27B执行器在智能体任务上提升高达+4.5，在代码任务上提升+3.4，同时能泛化到训练期间未见过的领域和任务类型。分析显示，合并与改进操作处理正交的质量维度，且技能组合是一种可迁移的元能力，为技能增强推理提供了实用方案。

## Abstract
Agent skills, which consist of reusable strategies that guide agent reasoning and action, have shown strong potential for improving model capability at inference time. However, current skill construction methods treat the problem as one-shot extraction, overlooking a fundamental tension: a skill tailored to the specific task fails to transfer, while the abstracted skill often provides insufficient guidance. We attribute this fragility to the absence of explicit mechanisms for skill specification and generalization. To address this gap, we introduce SkillComposer, a framework that decomposes skill construction into three learnable operations: create, improve, and merge. Trained via systematic rejection sampling recipe, SkillComposer enables language models to self-evolve skills at inference time and supports three deployment modes: offline for building generalized libraries, online for task-specific refinement, and hybrid for combining both. Comprehensive experiments on $τ^2$-Bench, LiveCodeBench v6, and AppWorld show that SkillComposer consistently outperforms baselines. Our SkillComposer-4B improves a 27B executor by up to +4.5 on agent tasks and +3.4 on code tasks, while generalizing across domains and task types unseen during training. Analysis reveals that merge and improve address orthogonal quality dimensions and that skill composition is a transferable meta-ability, providing a practical recipe for skill-augmented inference.

### 1. 核心问题与整体含义（研究动机和背景）

当前智能体技能构建方法多采用一次性提取（one-shot extraction），面临根本性矛盾：  
- **任务特定技能**：针对具体任务定制，性能好但难以迁移到其他任务。  
- **抽象化技能**：泛化能力强，但提供的指导往往不够具体、有效。  

这种“规范与泛化”的缺失导致技能质量脆弱。现有方法依赖人类编写或从成功轨迹中提取，成本高昂且难以规模化。作者提出 **SkillComposer**，旨在通过显式的可学习操作（创建、改进、合并）让语言模型在推理时自主演化技能，同时实现规范化和泛化。

### 2. 方法论

**核心思想**：将技能构建分解为三个互补的、可学习的操作，并通过拒绝采样训练强化模型执行这些操作的能力。  

**关键技术细节**：  
- **技能定义**：每个技能 \( s = (name, description, body) \)，其中 description 描述触发条件，body 为具体步骤。  
- **三种操作**：  
  - **Skill Create**：从原始执行轨迹中提取可复用技能。  
  - **Skill Improve**：基于新轨迹对现有技能进行精炼，推动规范化。  
  - **Skill Merge**：合并语义相似（多视图相似度 > 阈值δ）的技能对，推动泛化。  
- **训练方法**：通过拒绝采样筛选高质量的监督数据，过滤信号为**增量通过率（delta pass rate）**，即候选技能相对于基线的性能提升需超过阈值 ϵ。  
  - Create：比较带/不带技能在同一任务上的 pass@1。  
  - Merge：比较合并后技能与两个原始技能分别在各自任务上的 pass@1 均值。  
  - Improve：比较改进后技能与原始技能在源任务和目标任务上的 pass@1 均值。  
- **三种部署模式**（Algorithm 1）：  
  - **Offline**：从训练集创建并合并技能，构建通用库，推理时检索。  
  - **Online**：每任务在线创建并迭代改进，无需预训练库。  
  - **Hybrid**：用离线库初始化，再在线精炼。  

**伪代码流程**（文字说明）：  
1. 根据模式初始化技能库（离线/混合时先创建再合并）；  
2. 对每个目标任务，根据模式获取初始技能（离线检索、在线从零创建、混合检索）；  
3. 迭代 \( T \) 轮：使用当前技能指导执行，获得轨迹，再通过 Skill Improve 更新技能。

### 6. 主要结论与发现

1. **SkillComposer 一致优于所有基线**，混合模式在 agent 任务上最优，在线模式在代码任务上最优。  
2. **合并操作驱动泛化**，改进操作驱动规范化**，二者互补，离线库中合并最重要，改进更适合在线。  
3. **技能组合能力是任务间可迁移的元能力**：仅用 agent 数据训练仍能提升代码性能。  
4. **迭代演化比重复采样更有效**：相同推理预算下，SkillComposer 的增益随轮数增加而扩大。  
5. **跨模型泛化**：用 4B 训练的技能可有效提升 27B 执行器性能。  
6. **离线库在困难任务上更有价值**，但在简单任务上可能因引入无关技能而降低性能。

### 7. 优点

- **问题分解清晰**：将技能构建分解为三个可学习操作，分别对应规范与泛化，设计优雅。  
- **训练方法实用**：利用 delta pass rate 作为拒绝采样信号，无需人工标注，可自动筛选高质量技能。  
- **多种部署模式**：离线/在线/混合适应不同场景，灵活性高。  
- **泛化能力突出**：跨模型尺度、跨领域、跨任务类型均有效，且技能组合能力可迁移。  
- **分析深入**：通过消融、t-SNE 可视化、迭代比较等揭示了各操作的具体作用和演化规律。

### 8. 不足与局限

- **计算成本高**：拒绝采样需对每个候选技能执行多次推理以计算 delta pass rate，扩展性受限。  
- **模型覆盖有限**：仅使用 Qwen3.5-4B/27B，未在 GPT、Llama 等架构上验证。  
- **离线库构建依赖训练集覆盖**：代码库仅用 500 样本，泛化能力受限于数据多样性。  
- **混合模式在简单任务上表现不如在线模式**，说明检索技能可能引入噪声。  
- **训练数据合成**：agent 任务数据通过 AutoForge 合成，可能引入分布偏差。  
- **未讨论技能库的持续更新与记忆遗忘**，实际应用中库可能不断增长但缺乏管理机制。
