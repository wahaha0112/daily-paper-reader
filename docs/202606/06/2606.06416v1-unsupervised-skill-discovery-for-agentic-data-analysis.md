## 摘要
推理时技能增强通过注入可重用的程序化知识，无需更新模型参数，为改进数据分析智能体提供了一种轻量级方法。然而，发现有效的数据分析技能仍然具有挑战性，因为可靠的监督成本高昂，且成功标准因分析形式而异。这引出了一个关键问题：如何仅从无标签探索中发现可重用的数据分析技能。我们提出DataCOPE，一种用于数据分析智能体的无监督验证器引导的技能发现框架。DataCOPE从探索轨迹中提取验证信号，并利用这些信号来表征轨迹之间的相对质量或一致性。它迭代地协调用于轨迹生成的数据分析智能体、用于信号提取的无监督验证器以及用于对比技能蒸馏的技能管理器。对于报告式分析，我们将验证器实例化为自适应检查表验证器，该验证器推导任务特定标准，通过可验证覆盖率为报告评分，并迭代优化检查表。对于推理式分析，我们将其实例化为答案一致性验证器，该验证器根据答案一致性对轨迹分组，并将自一致性作为辅助信号。我们在Deep Data Research的报告式分析和DABStep的推理式分析上评估了DataCOPE。在两种设置下，DataCOPE在保留测试集上持续优于基线。在四种模型设置下平均，DataCOPE在报告式和推理式任务上分别将平均得分提高了9.71%和32.30%。

## Abstract
Inference-time skill augmentation provides a lightweight way to improve data-analytic agents by injecting reusable procedural knowledge without updating model parameters. However, discovering effective skills for data analysis remains challenging, as reliable supervision is expensive and success criteria vary across analytical formats. This raises the key question of how to discover reusable data-analysis skills from unlabeled exploration alone. We propose DataCOPE, an unsupervised verifier-guided skill discovery framework for data-analytic agents. DataCOPE derives verifier signals from the exploration trajectories and uses them to characterize relative quality or aggreement among trajectories. It iteratively coordinates a Data-Analytic Agent for trajectory generation, an Unsupervised Verifier for signal extraction, and a Skill Manager for contrastive skill distillation. For report-style analysis, we instantiate the verifier as an Adaptive Checklist Verifier that derives task-specific criteria, scores reports by verifiable coverage, and iteratively refines the checklist. For reasoning-style analysis, we instantiate it as an Answer Agreement Verifier that groups trajectories by answer agreement and uses self-consistency as an auxiliary signal. We evaluate DataCOPE on report-style analysis from Deep Data Research and reasoning-style analysis from DABStep. Across both settings, DataCOPE consistently improves held-out performance over baselines. Averaged across four model settings, DataCOPE improves the mean score by 9.71% and 32.30% on report-style and reasoning-style tasks respectively.

### 一、核心问题与整体含义（研究动机和背景）

- **问题**：数据分析智能体（Data-Analytic Agent）在推理时注入可复用的程序化知识（技能）可以轻量级提升性能，但如何从**无标签探索轨迹**中自动发现这些技能是主要挑战。主要原因：
  1. 可靠监督需要高代价的人工标注（理解任务、检查数据、评估报告正确性）。
  2. 不同分析形式（报告式 vs. 推理式）的成功标准差异大，难以统一。
- **整体含义**：提出一种无需地面真值答案、成功标签或人类注释的无监督技能发现方法，在保持模型参数不变的情况下提升智能体的泛化能力。

### 二、方法论：核心思想、关键技术细节

- **核心思想**：通过**无监督验证器**从智能体自身探索轨迹中提取相对质量或一致性的信号，利用对比信号蒸馏出可迁移的技能，并迭代优化。
- **框架组成**：
  - **Data-Analytic Agent**（数据分析智能体）：基于 ReAct 范式与环境交互，生成轨迹。
  - **Unsupervised Verifier**（无监督验证器）：从轨迹中提取非特权信号（如相对分数、答案聚类），不依赖真实标签。
  - **Skill Manager**（技能管理器）：对比分组后的轨迹，蒸馏出通用分析流程、策略和错误规避规则，更新技能文档（SKILL.md）。
- **关键技术细节**：
  1. **自适应检查表验证器（Adaptive Checklist Verifier）**（报告式任务）：
     - 利用 Checklist Agent 生成任务特定的检查项列表（如“报告需要包含哪些分析洞见”）。
     - 基于检查项覆盖率对报告打分，将高分/低分轨迹分为正/负组。
     - 交替优化：先提升报告技能，当分数不再提高时，反转对比方向优化检查表技能（防止过拟合）。
  2. **答案一致性验证器（Answer Agreement Verifier）**（推理式任务）：
     - 对每个任务的多个轨迹进行答案聚类，取代表性轨迹。
     - 利用自一致性（self-consistency）作为辅助不确定性信号，过滤饱和簇。
     - 对比不同簇的代表性轨迹，识别分歧推理模式并蒸馏技能。
- **迭代流程**：
  - 初始技能为空 → 智能体采样N条轨迹 → 验证器分组 → 技能管理器蒸馏新技能 → 注入智能体再采样… → 最终技能固定用于测试。

### 六、主要结论与发现

1. **DataCOPE 持续优于所有基线**：报告式任务平均 Overall Avg. 从 47.39% 提升至 57.10%（+9.71%）；推理式任务平均 All 得分从 29.14% 提升至 61.44%（+32.30%），尤其 Hard 子集提升显著。
2. **技能可跨模型迁移**：使用 GPT-5.2 或 DeepSeek-V4-Pro 作为数据代理产生的技能，仍能提升其他模型（如 Qwen3.5）的表现。
3. **无监督验证器组件至关重要**：去除检查表或答案聚类后性能大幅下降，证明非监督信号是有效技能发现的关键。
4. **迭代优化有效但非单调**：早期迭代提升大，后期可能产生无效更新（如报告式任务中第三轮可能下降），可通过验证器分数诊断。
5. **标签效率高**：在报告式任务中，零标签的 DataCOPE 甚至超过添加少量监督轨迹的基线；在推理式任务中接近使用2-3条监督轨迹的效果。

### 七、优点

1. **完全无监督**：无需任何地面真值答案、成功标签或人工标注，极大降低数据成本。
2. **任务自适应**：针对两种典型分析形式（开放式报告 + 固定答案推理）分别设计了专用验证器，适应性强。
3. **轻量级注入**：不改变模型参数，仅注入技能文档，部署灵活，token 消耗下降显著（最高降低 73.4%）。
4. **跨模型泛化**：从弱模型（Qwen3.5）学到的技能也能提升强模型（Claude Sonnet 4.6）的表现，验证了技能的通用性。
5. **迭代双重优化**：报告式任务通过“报告技能-检查表技能”交替优化，防止验证器过拟合，设计巧妙。

### 八、不足与局限

1. **依赖验证器设计**：验证器的质量直接影响技能发现效果，对新型分析形式可能需要重新设计验证器。当前仅研究报告和推理两种，未覆盖更复杂的数据分析（如交互式可视化）。
2. **探索轨迹采样成本**：推理式任务每实例需采样10条轨迹，随着任务数量增加，探索阶段总 token 消耗可能较大（论文承认但认为对比基线仍更优）。
3. **迭代非单调性**：后期迭代可能无效甚至降低性能，需要额外的终止策略（如基于验证器分数的 early stopping）。
4. **推理任务中的自一致性不保证正确性**：当多数轨迹误入同一错误答案时，自一致性反而强化错误。论文通过答案聚类缓解，但未完全解决。
5. **评估依赖外部 judge 模型**：报告式任务的准确率使用 GPT-5-mini 自动评测，可能引入 judge 偏差；推理式任务使用固定答案匹配，相对客观。
6. **未开源代码或技能库**：实验可复现性受限（论文未明确说明是否公开代码）。
7. **模型依赖**：技能管理器使用 Claude Code（商业闭源模型），若用户无法访问该模型则无法完整复现框架。
