## 摘要
随着LLM智能体采用大规模技能库，选择合适的子集成为一个结构性问题而非相似性匹配问题：技能之间存在依赖、冲突、特化或重复关系，这种结构在完全枚举和嵌入相似性中均不可见。我们提出SkillDAG，将技能间关系建模为类型化有向图，并将其作为推理时可被智能体调用的结构化检索接口暴露给LLM智能体，在执行期间查询和演化，而非嵌入固定的检索流水线：每次搜索返回向量匹配、类型边邻居和冲突信号，并通过“提议-提交”协议让智能体注册执行验证过的边，从而使图在多个回合中积累结构。在ALFWorld和SkillsBench上使用MiniMax-M2.7，SkillDAG达到67.1%的成功率和27.3%的奖励，超过最强报告的Graph-of-Skills基线分别+12.8和+8.6个百分点；该优势迁移至gpt-5.2-codex，且在大规模查询下SkillsBench内在Ret@K从65.5提升至78.2。这些增益可追溯至可隔离的机制：在池子扩大10倍时仍保持鲁棒的候选排序（而固定种子扩散流水线则退化），以及集合单调的在线编辑，可在不驱逐先前命中点的情况下扩大真实召回率。

## Abstract
As LLM agents adopt large skill libraries, selecting the right subset becomes a structural problem rather than a similarity-matching one: skills depend on, conflict with, specialize, or duplicate one another, a structure invisible to both full enumeration and embedding similarity. We present SkillDAG, which models inter-skill relationships as a typed directed graph and exposes it to an LLM agent as an inference-time, agent-callable structural retrieval interface, queried and evolved during execution rather than baked into a fixed retrieval pipeline: each search returns vector matches, typed-edge neighbors, and conflict signals, and a propose-then-commit protocol lets the agent register execution-backed edges so the graph accumulates structure across episodes. On ALFWorld and SkillsBench with MiniMax-M2.7, SkillDAG reaches 67.1% success and 27.3% reward, exceeding the strongest reported Graph-of-Skills baseline by +12.8 and +8.6 points; the advantage ports to gpt-5.2-codex, and intrinsic SkillsBench Ret@K rises from 65.5 to 78.2 under matched queries. These gains trace to isolable mechanisms: candidate ranking that stays robust as the pool grows 10x where a fixed seeding-diffusion pipeline degrades, and set-monotone online edits that enlarge ground-truth recall without evicting prior hits.

# SkillDAG: 面向大规模LLM技能选择的自演化类型技能图 — 详细总结

## 1. 核心问题与整体含义（研究动机和背景）

- **问题**：随着LLM智能体依赖外部技能库（skill library）来扩展能力，技能库规模增长到数千条，技能选择（skill selection）成为瓶颈。传统方法要么将整个库拼接到提示中（小规模可行，但token成本高且“lost in the middle”），要么通过余弦相似度或BM25进行扁平检索（top-K）。然而，这两种方式都隐藏了技能之间的结构关系：依赖、冲突、特化、重复。例如，一个高相似度的技能可能是任务本身，但它的必要前置技能（如解析器、转换器）却被忽略；两个技能可能互相干扰或浪费上下文预算。
- **现有工作的不足**：SkillNet构建了大规模技能图但仅用于平台组织而非运行时路由；Graph of Skills (GoS) 在推理时通过PageRank生成捆绑包，但图是离线的、固定的，且将结果作为不透明的上下文交给智能体，智能体无法询问原因、撤回或添加关系。
- **整体含义**：本文提出将技能图本身作为智能体可调用的结构化检索接口，让LLM直接推理图结构，并在执行中通过证据驱动的编辑使图自演化，从而解决大规模技能库下的选择鲁棒性问题。

## 2. 方法论：核心思想、关键技术细节、算法流程

### 2.1 核心思想
- **反直觉设计**：不将类型化图隐藏在固定检索流水线内部，而是暴露为智能体可调用的接口（search/show/propose-edge/edit-edge），让LLM在推理时直接查询、检查和修订图。
- **将关系类型提升为面向智能体的语义**：不再只有相似度标量，而是五种具体类型：depends_on（依赖前置）、specializes（特化版本）、composes_with（协同使用）、similar_to（功能冗余）、conflicts_with（冲突避免）。
- **在线自演化**：通过提议-提交协议，智能体可以在执行过程中注册经过执行验证的边，同时受结构不变量（无环、无矛盾、可逆性）保护。

### 2.2 关键技术细节

#### (a) 类型化技能关系图
- 图 \( G = (V, E, \tau) \)，V = 技能集，E = 边，τ 将每条边映射到五种类型之一。
- 两个操作约束：
  - conflicts_with 不作为导航边，仅用于排除共选；
  - depends_on 和 specializes 构成有向无环骨干（DAG）。
- 图2给出了一个6节点子图实例。

#### (b) 代理可调用的结构化检索接口
- 一次 `search(q, K, D)` 调用返回三个独立字段：
  - **matches**：查询-节点嵌入余弦的top-K（语义匹配）；
  - **neighbors**：从matches出发，沿四种可遍历边类型做广度优先遍历（深度D）到达的技能（含边类型和距离）；
  - **conflicts**：与任意match通过conflicts_with边相连的技能（用于排除）。
- 可选 `show` 获取技能正文，`propose-edge` 预览变更，`edit-edge` 提交变更。
- 解耦的优势：智能体可在上下文紧张时丢弃某一字段，按自己节奏多次调用，并留下推理痕迹。

#### (c) 冷启动图构建
- **两视图嵌入策略**（图3）：
  - \( e_{\text{self}}(v) \)：技能做什么（标识、描述、正文预览）；
  - \( e_{\text{needs}}(v) \)：技能需要什么（LLM想象调用场景并总结前置条件，使用HyDE风格生成一句摘要并嵌入）。
- 候选对来自两个排名：self-self 和 needs-self，超过自适应阈值（\( \max(0.35, \min(0.75, \mu+\sigma)) \)）的对送LLM分类器（gpt-5-nano）分配类型（none则丢弃）。
- 设计原理：self-description相似性会系统性地错过跨功能对（如冷却技能和取物技能描述不同，但冷却需要“手中物体”），needs视图可以桥接这类关系。
- 注意：conflicts_with完全保留给在线阶段，因为冲突证据只能来自执行，无法静态推断。

#### (d) 在线图演化
- 每回合循环（图1）：智能体通过search/show获取结构证据，执行动作，观察到结果，如果有证据支持图编辑，则调用`propose-edge`预览（展示现有边和历史），再调用`edit-edge`真正提交。
- 提交时通过三个结构不变量：
  - **无环**：depends_on/specializes不能形成有向环；
  - **无矛盾**：同一对技能不能同时拥有conflicts_with和正向边（如depends_on）；
  - **可逆性**：追加只读日志支持按最近时间回滚。
- 不设统计阈值或人工审查，智能体单次执行观察即可提交，目的是加快图演化速度。

## 3. 实验设计

### 3.1 数据集与场景

## 6. 主要结论与发现

1. **SkillDAG显著优于GoS**：在MiniMax-M2.7上，ALFWorld成功率从54.3→67.1（+12.8），SkillsBench奖励从18.7→27.3（+8.6）；在gpt-5.2-codex上，ALFWorld持平（93.6%），SkillsBench仍领先（34.4→36.8），说明当骨干推理能力足够强时，路由辅助收益变小。
2. **内在检索增益独立于下游执行**：将相同查询通过SkillDAG和GoS的检索管道比较，SkillDAG的matches字段（纯余弦）在所有规模上均胜出（Ret@K从65.5→78.2），证明结构接口本身提升了召回精度。
3. **在线编辑持久且集合单调**：训练的编辑在测试时仍有效（图4a），编辑后图召回的地面真值技能数增加且无丢失（表2），因为检索取并集。
4. **跨规模鲁棒**：池从200扩大到2000，SkillDAG的Ret@5仅下降3.5点（78.2→74.7），而GoS大幅下降（73.6→60.9）。
5. **失效模式**：主要失败是循环动作（8/11）和步骤耗尽（2/11），而非技能选择错误，说明图提供了正确技能但智能体在地面层面（动作映射、探索策略）仍有不足。

## 7. 优点

- **创新性接口设计**：将图从固定检索算法的底物提升为智能体推理的直接工具，使结构证据可被解释、选择性利用和动态修改。
- **两视图冷启动**：通过needs视图捕获跨功能依赖，这是单视图相似度系统性遗漏的关键，实用且高效。

- **实验细化**：不仅报告端到端奖励，还分离了内在检索、跨规模鲁棒性和编辑迁移，揭示了增益来源。
- **开源代码与数据**：提供GitHub仓库，促进复现。
