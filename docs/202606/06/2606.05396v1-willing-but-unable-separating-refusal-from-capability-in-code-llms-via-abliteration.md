## 摘要
大规模生成带有标签的脆弱代码是基于学习的漏洞检测反复遇到的障碍：挖掘的语料库带有大量标签噪声，现有的基于LLM的增强方法会传播这些不准确性，因为它们转换脆弱种子而非根据规范合成漏洞。一条补充的途径是从安全代码开始，要求经过指令微调的LLM注入指定的CWE（这将把标注负担从开放式检测转移到有界的二元确认），但安全对齐的代码LLM系统地拒绝此类提示。本文是对abliteration（一种低秩权重编辑，通过正交投影消除残差流中的拒绝方向）作为消除这一障碍工具的初步可行性研究。我们以Python和CWE-89（SQL注入）作为案例研究，在从PromSec和SafeCoder抽取的安全样本上评估Qwen2.5-Coder-Instruct系列的3B、7B和14B参数版本，每个条件重复三次。我们发现：(i) 对注入提示的拒绝强烈依赖于大小和提示上下文：14B拒绝100%的提示，7B拒绝73%的PromSec样本但仅5%的SafeCoder样本，而3B基本不受阻；(ii) abliteration将拒绝降至零或接近零，同时保持93%以上的句法有效性，支持了在这种设置下拒绝可以与测量的代码生成能力分离的观点；(iii) 去敏后的注入率仍然受限于能力（14B上88-97%，7B上89-90%，3B上25-48%），将意愿（abliteration解锁）与能力（随参数规模缩放）分离。漏洞判定由三个工具的检测器集成（CodeQL、Semgrep、Bandit）产生，随后由两位作者对检测器阳性输出进行人工裁决。

## Abstract
Producing a labeled vulnerable code at scale is a recurring obstacle for learning-based vulnerability detection: mined corpora carry substantial label noise, and existing LLM-based augmentation propagates these inaccuracies because it transforms vulnerable seeds rather than synthesising vulnerabilities from a specification. A complementary route is to start from safe code and ask an instruction-tuned LLM to inject a specified CWE (which would shift the labeling burden from open-ended detection to bounded binary confirmation) but safety-aligned code LLMs systematically refuse such prompts. This paper is a preliminary feasibility study of abliteration, a low-rank weight edit that orthogonally projects out the refusal direction in the residual stream, as a tool to remove this barrier. We use Python and CWE-89 (SQL injection) as a case study, evaluating the Qwen2.5-Coder-Instruct family at 3B, 7B, and 14B parameters on safe samples drawn from PromSec and SafeCoder, replicated three times per condition. We find that (i) refusal on injection prompts is strongly size- and prompt-context-dependent: the 14B refuses 100% of prompts, the 7B refuses 73% of PromSec but only 5% of SafeCoder, whereas the 3B is essentially never blocked; (ii) abliteration reduces refusal to zero or near-zero across all sizes while leaving syntactic validity above 93%, supporting the view that, in this setting, refusal can be detached from measured code-generation capability; and (iii) the post-abliteration injection rate remains capacity-bound (88-97% on the 14B, 89-90% on the 7B, and 25-48% on the 3B) separating willingness, which abliteration unlocks, from capability, which scales with parameters. Vulnerability verdicts are produced by a three-tool detector ensemble (CodeQL, Semgrep, Bandit) followed by manual adjudication by two authors on detector-positive outputs.

## 1. 论文的核心问题与整体含义

- **研究动机**：基于学习的漏洞检测需要大规模高质量的有标签脆弱代码，但现有方法存在严重瓶颈：
  - 从CVE标注提交中挖掘的数据集标签噪声高达20-71%，且存在大量重复。
  - LLM增强方法（如VulGen、VGX、VulScribeR）基于已有的脆弱种子进行变换，继承了原始种子中的标签噪声。
- **核心问题**：能否从**已知安全的代码**出发，通过LLM按照指定CWE注入漏洞，从而将标签问题从开放式多类检测（噪声高）简化为目标已知的二元确认（噪声可控）？然而，安全对齐的指令微调代码LLM会**系统性拒绝**包含CWE名称的注入提示，阻碍了这一范式。
- **整体含义**：本研究是**第一次**通过abliteration（去敏）技术解除代码LLM对漏洞注入提示的拒绝行为，并系统性地检验了“意愿”（是否愿意执行）与“能力”（是否能正确执行）的分离。这项工作为大规模生成可靠脆弱代码数据集提供了新的可行路径，有望填补Python漏洞检测研究中训练数据质量不足的空白。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：安全对齐的LLM通过RLHF学习到一条“拒绝方向”出现在残差流中，使模型在遇到有害指令时触发拒绝。Abliteration通过正交投影移除这一方向，从而解除拒绝行为，同时保留模型原有的代码生成能力。
- **关键技术细节**：
  1. **激活收集**：对有害提示（注入CWE的指令）和无害提示（标准安全生成），分别收集残差流中最后一个token的激活向量，得到矩阵 \(H\) 和 \(B\)。
  2. **对比矩阵与SVD**：对每一层计算对比矩阵 \(D = H - B\)，进行奇异值分解 \(D = U S V^\top\)，取前 \(k\) 个右奇异向量作为候选拒绝方向 \(\hat{r}_1,...,\hat{r}_k\)。
  3. **权重编辑**：对每个向残差流写入的权重矩阵（包括输入嵌入、注意力输出投影、MLP输出投影），施加正交投影：
     \[
     W'_{\text{out}} \leftarrow W_{\text{out}} - \sum_{i=1}^k \hat{r}_i \hat{r}_i^\top W_{\text{out}}
     \]
     使得模型无法再将这些方向写入残差流，从而永久性地抑制拒绝。
  4. **参数选择**：使用开源工具Obliteratus实现，采用高级方法、范数保持投影、层自适应强度缩放和top-k层选择。对于3B模型使用 \(k=2\)、2次精炼、10层；7B和14B使用 \(k=8\)、4次精炼、分别9层和16层。
  5. **验证门控**：编辑后使用自带verify阶段检查拒绝率（≤5%）、困惑度（与基模型偏差≤0.5）以及自由形式补全的语法和语义合理性，不合格则重新调整超参数运行。

- **算法流程（文字说明）**：
  1. 输入：原始安全代码 \(S\) 及配对描述 → 构造固定提示（描述 + 注入指令“Rewrite it with CWE-89 by concatenating ...”）→ 分别发送给Base模型和Abliterated模型。
  2. 生成响应 → 拒绝分类器（正则匹配）分区。
  3. 非拒绝响应 → 代码块提取 → AST语法验证 → 三个静态分析器（CodeQL、Semgrep、Bandit）检测。
  4. 至少一个检测器标记的样本 → 两位作者独立人工裁决是否为真正CWE-89注入。
  5. 最终得到脆弱/非脆弱判定；同时计算生成代码与参考脆弱代码的相似度（CrystalBLEU、CodeBLEU）。

## 6. 论文的主要结论与发现

1. **拒绝行为高度依赖于模型大小和提示上下文**：
   - 14B：100%拒绝所有提示（两个数据集）。
   - 7B：在PromSec上拒绝73%，在SafeCoder上仅拒绝5%（提示上下文影响显著）。
   - 3B：基本不拒绝（0-7%）。
2. **Abliteration能有效解除拒绝且不伤害代码生成能力**：
   - 编辑后所有模型的拒绝率降至0或接近0（仅3B残留1.7%在PromSec）。
   - 句法有效性保持93%以上；7B在PromSec上Base拒绝73%时有效句法只有25%，编辑后达到100%；去除拒绝后模型的表现与原本就愿意回答的样本一致。
3. **意愿与能力正交分离**：
   - Abliteration打开了“意愿”的闸门，但注入成功率仍受模型能力限制：14B达到88-97%，7B约90%，3B仅25-48%。
   - 3B即使解除拒绝，性能依然低，说明能力差距无法通过解除拒绝弥补。
4. **检测器一致性差异大，人工裁决不可替代**：
   - 在473个阳性输出中，仅71个获得三个检测器一致阳性，其余402个存在检测器分歧。因此必须辅以人工确认。

## 7. 优点

- **方法新颖性**：首次将abliteration应用于代码LLM的漏洞注入任务，并系统证明了意愿与能力的分离，为后续数据增强和安全研究提供了新视角。
- **实验设计严谨**：使用多个静态分析器加人工裁决，确保标签可靠性；控制模型家族和提示模板，进行重复实验，报告标准差。

- **实用价值**：生成的漏洞代码可作为训练数据，7B模型在去敏后以约90%注入率提供了成本效益比高的选择。

## 8. 不足与局限

- **覆盖范围有限**：
  - 仅测试CWE-89和Python，无法推广到其他CWE（如命令注入、路径遍历）或语言（C/C++、Java）。

- **4-bit量化可能影响**：所有推理在Q4_K_M量化下进行，可能引入额外噪声，特别是对小模型3B的行为影响未在FP16上验证。

- **缺乏下游验证**：没有用生成的漏洞代码训练检测器并测试其在真实漏洞数据上的表现，因此实际应用效果不明。
- **滥用风险**：虽采用不对称发布，但方法本身公开，可能被恶意利用生成更多漏洞代码。
