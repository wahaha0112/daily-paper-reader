## 摘要
现代大语言模型智能体日益依赖技能库来处理复杂任务，使得技能演化成为自我提升的主要驱动力。然而，孤立的单用户任务流缺乏构建全面技能所需的多样性。尽管跨用户协作可以克服这一数据瓶颈，但当前的轨迹共享方法会损害用户隐私，并强加一个无法适应客户端异质性的统一全局库。我们提出了FederatedSkill，一种用于协作智能体演化的隐私保护框架。超越原始轨迹共享，FederatedSkill利用语义技能差异（即局部库上的结构化补丁）作为通信的基本单元。在服务器端，一个演化智能体聚合这些补丁，动态建模客户端特定的能力边界，促进严格的个性化技能演化，而非次优的全局平均。在20个不同的智能体任务族上评估，FederatedSkill相对于自我演化基线展现出显著提升，成功率最高提升44.4%，计算成本降低37.5%。

## Abstract
Modern LLM agents increasingly rely on skill libraries to handle complex tasks, making skill evolution a primary driver of self-improvement. However, isolated single-user task streams lack the diversity required to build comprehensive skills. While cross-user collaboration can overcome this data bottleneck, current trajectory-sharing approaches compromise user privacy and impose a uniform global library that fails to accommodate client heterogeneity. We introduce FederatedSkill, a privacy-preserving framework for collaborative agent evolution. Moving beyond raw trajectory sharing, FederatedSkill utilizes semantic skill diffs, structured patches over local libraries, as the fundamental unit of communication. On the server side, an evolution agent aggregates these patches to dynamically model client-specific capability boundaries, facilitating strictly personalized skill evolution rather than a suboptimal global average. Evaluated across 20 distinct agent task families, FederatedSkill demonstrates substantial gains over self-evolving baselines, achieving up to a 44.4% increase in success rate and a 37.5% reduction in computational cost.

## 1. 核心问题与整体含义（研究动机与背景）

- **研究动机**：现代大语言模型（LLM）智能体依赖可复用的**技能库**来处理复杂任务，技能演化（通过添加、修改、删除技能）是智能体自我提升的主要方式。但单个用户的任务流覆盖范围窄，数据多样性不足，导致智能体在面对新任务时缺乏成功经验。
- **现有方案的缺陷**：跨用户协作能打破数据瓶颈，但当前主流方法共享原始执行轨迹（trajectory），存在两大根本问题：
  - 隐私风险：原始轨迹可能包含敏感信息（如网页上的私人数据、电子表格中的机密内容），用户无法安全上传。
  - 异质性挑战：全局统一的技能库无法适应不同用户（不同基础模型、不同智能体框架、不同任务分布）的个性化需求。
- **整体目标**：提出一个既能保护隐私又能实现个性化技能协作演化的框架，使不同客户端在交换最小化信息的前提下，获得各自最优的技能库。

## 2. 论文提出的方法论：核心思想与关键技术细节

### 核心思想
- 借鉴联邦学习（Federated Learning）中“传输模型更新而非原始数据”的思路，FederatedSkill 传输**语义技能差异（semantic skill diff）**——即客户端对本地技能库所做的结构化补丁（add/edit/delete操作），而不是原始轨迹。
- 服务器端有一个**演化智能体**，通过分析所有客户端上传的补丁，动态推断每个客户端的能力边界，并为每个客户端生成**个性化**的技能更新，避免使用次优的全局平均库。

### 关键技术细节
1. **客户端侧**：
   - **本地执行**：客户端智能体基于当前技能库执行任务，生成轨迹。
   - **补丁蒸馏（Patch Distillation）**：使用与执行模型相同的本地LLM，将轨迹压缩为结构化补丁 δ_i^t，包含：
     - U_i^t：文件更新字典（新增或修改的技能文件）。
     - D_i^t：建议删除的文件路径列表。
     - R_i,x(τ)：任务奖励。
     - s_i^t：自然语言摘要（审计用）。
   - **隐私保护设计**：原始轨迹、验证器输出、中间文件全部留在本地；补丁只包含库级语义，且明确提示丢弃任务特定值、ID等；路径验证防止目录穿越。

2. **服务器侧**：
   - 问题建模为**部分可观测马尔可夫决策过程（POMDP）**：服务器只能观测到客户端补丁和静态配置，需推断客户端能力边界。
   - **阶段1：演化规划**：
     - 构建**能力矩阵** C_t：行是任务工作流，列是客户端，单元格状态为"covered"、"absorbing"、"broken"、"gap"。
     - 维护**两级能力记忆**：高层（家族共享）记录全局未解决问题的模式；低层（每个客户端私有）记录模型/框架特定的失败模式。
     - 生成**演化指令**：针对每个客户端的缺口（gap/broken/absorbing），指示下一步动作。
   - **阶段2：个性化库演化**：
     - 为每个客户端独立执行指令，吸收可转移的补丁、修复或重写技能以适应该客户端的配置（ρ_i）。
     - 输出更新后的库 L_i^{t+1} 和可审计的决策日志。

3. **通信单元**：仅传输轻量级JSON补丁（通常几十到几百KB），而非原始轨迹，通信成本极低（20个任务族总计约3.5MB）。

## 3. 实验设计

### 使用的数据集/场景与基准
- **基准**：SkillFlow（Zhang et al., 2026d），一个专门评估智能体终身技能演化的基准，包含20个多样化的任务族，每个族内任务难度递增，智能体需从空技能库开始顺序学习。
- **客户端配置**：
  - 三种客户端设置：同质（所有客户端相同：GLM-5 + Claude Code）、异质骨干（不同模型：Qwen3.6-Plus, GLM-5, Kimi K2.5 + 相同Claude Code框架）、异质骨干+框架（各模型搭配各自本地框架：Qwen Coder, Claude Code, Kimi CLI）。
- **对比方法**：
  - **Self-Evolution（SE）**：独立自我演化基线，每个客户端仅使用自己的轨迹演化技能库，无协作。
  - **Global**（消融）：保留补丁共享协议，但服务器生成单一全局技能库，无个性化（作为FederatedSkill的剥离版本）。

### 实验数量
- **主要实验**：在三种设置下，对20个任务族分别评估SE和FederatedSkill，报告每个任务族的成功率。
- **消融实验**：在5个代表性任务族上对比FederatedSkill vs. Global，验证个性化必要性。
- **额外分析**：
  - 演化动力学（技能库大小随轮次变化）。
  - 成本分析（每试次成本和每解决任务成本）。
  - 通信成本（每任务族补丁总字节）。
  - 统计显著性（对5个族进行多轮SE基线，计算FederatedSkill相对于SE的改善及置信区间）。
  - 隐私审计（敏感实体泄露率SELR，重构攻击，PII金丝雀测试）。

## 6. 论文的主要结论与发现

- **性能提升**：FederatedSkill在所有三种客户端设置下均持续优于SE自演化基线，同质设置下平均成功率从37.4%提升至45.8%；异质骨干+框架设置下，成功率提升最高达44.4%（如Kimi K2.5在Production Capacity Planning上）。
- **成本降低**：每个已解决任务的成本降低高达37.5%（Kimi K2.5）；每试次成本也下降7%-24%。原因是个性化演化避免了SE的库膨胀导致的提示过长。
- **库管理改善**：FederatedSkill将技能库大小稳定在1.0-1.6个技能/家族（SE下Qwen/Kimi膨胀至2.0-2.5），通过跨客户端去重和保守准入实现。
- **隐私保护有效**：敏感实体泄露率(SELR)在传入补丁中仅5.08%，在个性化更新返回中仅0.09%（与无关家族基线0.09%无异）；PII金丝雀全部零泄露；重构攻击得分接近下界。
- **个性化必要性**：消融实验证明，全局库相比个性化库平均性能低12.2%。

## 8. 不足与局限

- **规模受限**：实验仅用3个客户端，未验证大规模（如数十/上百客户端）下的扩展性和涌现行为。作者也承认此局限性。
- **系统优化缺失**：论文专注于算法范式，未探索带宽更高效的补丁传输方案或异步轮次等工程优化。
