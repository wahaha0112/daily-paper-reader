## 摘要
智能体技能库正成为可路由的软件资产：检索到的技能可以为智能体提供指令、脚本、资源绑定和执行假设。这使得技能检索不仅仅是广泛的相关性匹配。检索器可以找到正确的能力家族，却可能暴露错误的同能力代表。我们将这种失败研究为同能力执行风险检索。每个查询将一个有用的技能与一个查询特定的风险兄弟技能配对，该技能共享能力家族但可能导致执行到过时资源、缺失前置条件或错误流程。我们引入了SkillResolve-Bench 1.0，这是一个针对该设置的可审计基准，包含661个有用/风险对、源角色和接纳证据、线索/泄漏检查、查询不相交分割，以及一个包含6,660个公共SkillRet候选的7,982个候选池。该基准报告有帮助排名以及有害兄弟率（HSR@K），即风险兄弟技能在前K个中的暴露率。我们还提供了SkillResolve，一种参考方法，用于解析活跃候选家族，从易混淆的库负样本和合同轮廓线索中评分查询条件效用，并在最终前K列表之前从每个家族中选择一个代表。在已发布的关系下，SkillResolve的Recall@3达到0.766，NDCG@3达到0.699，同时保持HSR@3=0。相比于SkillRouter，Recall@3提升0.112，NDCG@3提升0.165，同时将HSR@3从0.693降至0。如果没有代表选择，在相同评分器下HSR@3上升到0.236，这表明家族内代表选择是将能力检索转化为更安全程序暴露的机制。

## Abstract
Agent skill libraries are becoming routable software assets: a retrieved skill can contribute instructions, scripts, resource bindings, and execution assumptions to an agent. This makes skill retrieval more than broad relevance matching. A retriever can find the right capability family yet expose the wrong same-capability representative. We study this failure as same-capability execution-risk retrieval. Each query pairs a helpful skill with a query-specific risky sibling that shares the capability family but can lead execution toward a stale resource, missing precondition, or wrong procedure. We introduce SkillResolve-Bench 1.0, an auditable benchmark for this setting with 661 helpful/risky pairs, source-role and admission evidence, cue/leakage checks, query-disjoint splits, and a 7,982-candidate pool that includes 6,660 public SkillRet candidates. The benchmark reports helpful ranking together with harmful sibling rate (HSR@K), the top-K exposure of the risky sibling. We also provide SkillResolve, a reference method that resolves active candidate families, scores query-conditioned utility from confusable library negatives and contract-profile cues, and selects one representative from each family before the final top-K list. Under the released family relation, SkillResolve reaches Recall@3 0.766 and NDCG@3 0.699 while keeping HSR@3=0. It improves over SkillRouter by 0.112 Recall@3 and 0.165 NDCG@3 while reducing HSR@3 from 0.693 to 0. Without representative selection, HSR@3 rises to 0.236 under the same scorer, identifying within-family representative choice as the mechanism that turns capability retrieval into safer procedural exposure.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：智能体技能库正成为可路由的软件资产，技能不仅包含指令和脚本，还包括资源绑定、执行假设等。现代技能检索不再是简单的“相关性匹配”，检索到的技能会直接影响智能体的规划与执行。然而，当前检索系统常能正确识别出正确的能力家族（如“雷达信号处理”），却在该家族内暴露了错误的成员——例如一个技能指向正确的处理流程但引用了过时的数据资源，另一个技能流程正确但缺少必要的前置条件。这种“同能力歧义”会导致执行失败，而传统检索指标（如Recall）无法捕捉这一风险。
- **研究动机**：现有基准（如SkillRet、SRA-Bench）只关注“是否找到有用技能”，未考虑同家族内不同变体的执行风险。同时，安全相关工作（MalSkillBench、SkillGuard）聚焦恶意技能检测，但忽略了在检索阶段就应避免暴露有风险的同族变体。本文旨在**量化并解决**这种“检索到正确能力却暴露错误代表”的失败模式。
- **核心问题**：如何设计检索方法，在保持有用技能高召回的同时，避免在同一能力族中暴露针对当前查询有执行风险的兄弟技能？

## 2. 方法论：核心思想、关键技术细节

### 2.1 整体框架：SkillResolve

- **核心思想**：将技能检索分解为三个步骤：① **能力解析（Capability Resolution）**：识别哪些候选技能应被视为同一能力族的替代代表；② **条件效用评分（Query-conditioned Utility Scoring）**：为每个技能计算对当前查询的效用；③ **代表选择（Representative Selection）**：在每个族内只保留效用最高的一个代表，然后对这些代表进行全局Top-K排序。
- **关键假设**：同一族内的技能在语义上高度相似，但执行后果不同。通过将选择问题从独立排序转化为族内效用竞赛，从而避免同时暴露有用和风险技能。

### 2.2 具体技术细节

- **能力解析器 ρ**：输入查询q和候选池C(q)，输出一组活跃组Π_q = {G1, G2, ..., Gm}，每组内的技能被视作同一能力的替代代表。可以是基于公开的族关系（论文中的基准关系）、元数据/标题、或文本聚类。
- **效用评分器 F_θ**：学习一个线性模型，特征分为两部分：
  - **基础特征 φ_base**：包含词TF-IDF、字符TF-IDF、互斥秩融合（RRF）、路由视图得分、归属投票得分、以及基于线索清洗后的文本分类器得分。
  - **契约特征 φ_contract**：从查询和技能文本中提取六个执行面特征：资源绑定、前置条件、API/时间范围、输出模式、流程、标识符。通过关键检测计算重叠、覆盖、对比标志等。
  - 最终得分：F_θ(q,s) = α * a(q,s) + (1-α) * h_θ(q,s)，其中h_θ = θ^T φ，a是归属投票基础得分，α在验证集上选择。
- **训练目标**：对每个训练查询，正例为有用技能s⁺，负例为从候选池中挖掘的“易混淆库负样本”（confusable library negatives）：这些技能不是随机不相关项，而是与查询语义接近但未被接纳为有用技能的其他技能。使用成对逻辑损失：
  L(θ) = Σ_i Σ_{s∈H_i} log(1 + exp(-Δ_i(s))) + λ||θ||²₂，其中Δ_i(s) = F_θ(q_i, s⁺_i) - F_θ(q_i, s)
- **代表选择**：对每个组G，计算组内每个技能的效用分数，选出最高者作为该组唯一代表。最终Top-K列表由所有组的代表按其效用分数排序得到。
- **算法流程**：见论文Algorithm 1，输入查询、候选池、解析器ρ、学习好的评分组件和预算K，输出风险可控的Top-K列表。

- **基准关系**：发布了一个族关系文件，包含7,321个组（661个大小为2的有用/风险组，6,660个独立SkillRet组），用于控制组内代表选择评估。

- **Recall@K、NDCG@K**：度量有用技能是否被检索到且排名高。

## 6. 主要结论与发现

1. **同能力歧义是技能检索中的关键失败模式**：通用相关性检索器（SkillRouter、BGE）在Recall@3 0.5~0.65的同时，HSR@3高达0.46~0.69，表明频繁暴露错误代表。
2. **SkillResolve能同时提升有用技能召回并消除风险暴露**：Recall@3 0.766、HSR@3=0，相比SkillRouter Recall提升0.112、HSR下降0.693。
3. **代表选择是控制风险暴露的关键机制**：去除代表选择后，相同评分器下HSR从0升至0.236，而Recall几乎不变（0.762 vs 0.766）。
4. **易混淆库负样本优于简单BM25负样本**：在相同评分器下Recall@3提升0.059。
5. **公共族源（元数据/标题）也可达到零暴露**，但以更粗的族粒度（合并更多候选）为代价。

## 8. 不足与局限

- **基准规模有限**：仅661个标注对和7,982个候选，相比实际智能体技能库（可能数万至百万）仍有差距，泛化性未验证。
