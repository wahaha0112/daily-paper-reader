## 摘要
针对LLM智能体的技能自进化方法旨在将执行轨迹转化为可复用的技能文档，但当前流程通常每个任务仅学习一条轨迹，在检查之前合并候选技能补丁，并在推理前加载整个技能语料库。我们提出SkillCAT，一个无需训练的框架，将该过程分为三个阶段。对比因果提取（CCE）为每个任务采样多条轨迹，并比较同任务的成功/失败对，以识别解释结果差异的证据。评估增强进化（AAE）在源任务克隆上回放每个候选补丁，并在层级技能补丁合并前仅保留改善或维持任务结果的补丁。拓扑感知任务执行（TTE）将进化后的技能编译为可路由的子技能拓扑，因此推理仅加载与任务相关的能力节点。我们在常见智能体基准测试（包括SpreadsheetBench、WikiTableQuestions和DocVQA）上评估SkillCAT，并进一步测试跨模型和分布外泛化能力。在这些设置中，SkillCAT将基线平均得分提升高达40.40%，展示了无需模型训练的可靠技能进化。

## Abstract
Skill self-evolution methods for LLM agents aim to turn execution trajectories into reusable skill documents, but current pipelines typically learn from one trajectory per task, merge candidate skill patches before checking them, and load the full skill corpus before inference. We propose SkillCAT, a training-free framework that separates this process into three stages. Contrastive Causal Extraction (CCE) samples multiple trajectories for each task and compares same-task success/failure pairs to identify evidence that explains outcome differences. Assessment-Augmented Evolution (AAE) replays each candidate patch on source-task clones and keeps only patches that improve or preserve task outcomes before hierarchical skill patch merging. Topology-Aware Task Execution (TTE) compiles the evolved skills into a routable sub-skill topology, so inference loads only the capability nodes relevant to the task. We evaluate SkillCAT on common agent benchmarks, including SpreadsheetBench, WikiTableQuestions, and DocVQA, and further test cross-model and out-of-distribution generalization. Across these settings, SkillCAT raises the average score over baselines by up to 40.40%, demonstrating reliable skill evolution without model training.

## 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：LLM 智能体在执行复杂任务时通常依赖外部技能文档（如指令、工具规则、任务经验）。早期技能库由人工编写，近期工作转向从智能体执行轨迹中自动提取和进化技能（即技能自进化）。然而现有方法（如 Trace2Skill）存在三个关键缺陷：
  1. **单轨迹偏差**：每个任务仅从一条轨迹中提取证据，成功轨迹可能源于偶然策略，失败轨迹也未必定位根本原因。
  2. **未验证的合并**：候选技能补丁直接合并到全局技能库，未独立检查其对源任务的影响，导致低质量或有害补丁混入。
  3. **上下文过载**：合并后的技能持续增长，推理时向智能体注入全部技能内容，增加提示长度并干扰任务相关规则。
- **整体目标**：提出一个无需额外模型训练的框架 SkillCAT，通过三阶段解耦设计，分别解决上述三个问题，实现可靠、高效的技能自进化，提升智能体在未见任务上的表现并控制推理时上下文长度。

## 2. 方法论：核心思想、关键技术细节与流程

### 核心思想
SkillCAT 将技能生命周期划分为三个阶段：对比因果提取（CCE）、评估增强进化（AAE）、拓扑感知任务执行（TTE）。前两阶段离线进行技能学习，第三阶段在线部署。

### 关键技术细节

#### 2.1 对比因果提取（CCE）
- **对比对构建**：对每个任务使用多个随机种子（默认5个）生成多条轨迹，若同时存在成功与失败轨迹，则各随机抽样一条构成成功-失败对比对 `(τ⁺ᵢ, τ⁻ᵢ)`，确保任务难度和输入一致。
- **因果分水岭识别**：找到两条轨迹中第一个动作分歧的时间步 `wᵢ = min {t: α⁺ₜ ≠ α⁻ₜ}`，作为因果分水岭。
- **记录提取**：提取器 `E` 围绕该分水岭写入候选经验记录 `rᵢ`，包含局部证据、推测的失败原因和可编辑的技能教训，而非总结完整轨迹。若任务全成功或全失败，则启用后备机制应用单轨迹提取器。

#### 2.2 评估增强进化（AAE）
- **源任务回放评估**：将每个候选补丁 `pⱼ` 作为临时技能，在源任务克隆上回放，记录基线结果 `yⱼ` 和回放结果 `ŷⱼ`（0/1），并根据四种结果转移计算评估分数 `aⱼ`：
  - (失败→成功): 3.0
  - (成功→成功): 2.0
  - (失败→失败): 1.0
  - (成功→失败): 0.0
  对于源自对比对的补丁，以成功的轨迹为基线，回放成功视为成功→成功，回放失败视为成功→失败。
- **分数阈值筛选**：仅保留 `aⱼ ≥ 2.0` 的补丁，排除修复失败或破坏已有成功的补丁。
- **层级合并**：按分数层级从低到高分组，使用类似 Trace2Skill 的合并操作符 `μ` 逐步合并：`S^(ℓ) = μ(S^(ℓ-1), P^(ℓ)_θ)`，最终得到进化后的全局技能 `S*`。

#### 2.3 拓扑感知任务执行（TTE）
- **拓扑构建**：离线解析 `S*` 的 Markdown 层级：一级内容作为常驻核心技能 `S°`，二级内容作为可路由节点集合 `V`，每个节点保留正文和路由元数据（标题、关键词、摘要、依赖）。
- **LLM 路由与技能组装**：根据任务描述 `c` 和预算 `k`，LLM 路由器 `ρ` 选择最多 `k` 个相关主节点，然后经过确定性扩展（验证ID、添加锚点、扩大依赖）得到最终节点集 `Vc`。最后组装：`Sc = S° ⊕ ⊕_{v∈Vc} Bv`，即核心技能拼接所选节点的正文。
- 特点：不重新生成技能文本，仅改变加载规则，减少无关内容。默认使用 `llm_graph_router`，`top_k=7`。

- SkillCAT 在**所有基准测试上平均分提升最高达 40.40%**，在 SpreadsheetBench Vrf 上较 Trace2Skill +Combined 提升 25.83 个百分点（Qwen3.5-35B-A3B Deepening）。

## 7. 优点

- **无训练**：完全基于 LLM 推理和代码逻辑，无需梯度更新或额外模型参数，易于部署和使用。
- **模块化设计**：三个阶段相互独立，可分别替换或消融，便于分析和改进。
- **对比因果提取**：利用同任务成功/失败对比，显著降低单轨迹偏差，提取更具因果性的证据。
- **源任务回放验证**：通过克隆测试验证每个补丁的实际效果，防止有害补丁污染全局技能，稳定性高。
- **拓扑感知路由**：将技能组织为带元数据的节点，仅加载任务相关子集，避免冗长无关上下文，同时保持进化规则的完整性。
- **广泛验证**：覆盖文本和图像任务、分布内外、跨模型多种场景，实验设计全面，结论可靠。

## 8. 不足与局限

- **采样成本**：CCE 需要为每个任务生成多条轨迹（默认5个），且需运行 128 个并行推理，在大规模任务集上可能产生较高的 API 或计算开销。
- **种子数敏感**：实验显示性能在 5 个种子时最佳，更多种子反而下降，说明对比对的受益存在上限，且种子数的选择需调优。
- **回放评估依赖克隆**：AAE 仅在源任务克隆上验证补丁，可能无法完全反映补丁在新任务上的泛化效果，存在过拟合风险。
- **路由稳健性**：TTE 的元数据提取和 LLM 路由质量受提示和模型能力影响，若元数据不全或路由判断错误，可能导致关键技能丢失。实验中未深入分析路由失败案例。
- **领域局限性**：实验仅涵盖电子表格操作、表格 QA 和文档 VQA 三类任务，对于更广泛的智能体应用（如编程、机器人控制等）是否仍然有效尚需验证。
- **未考虑持续学习**：当前框架假设技能进化基于固定的任务集，未设计增量更新机制（例如新任务持续加入时如何动态调整技能拓扑）。
- **可解释性不足**：虽然对比因果提取提示了关键分水岭，但最终技能文档合并和路由的内部决策主要依赖 LLM，黑箱性质影响调试与可信度。
