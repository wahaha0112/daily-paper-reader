## 摘要
智能体技能库正成为可路由的软件资产：检索到的技能可以为智能体贡献指令、脚本、资源绑定和执行假设。这使得技能检索不仅仅是广泛的相关性匹配。检索器可以找到正确的能力家族，却暴露出错误的同能力代表。我们将这种失败研究为同能力执行风险检索。每个查询将一个有用的技能与一个查询特定的风险兄弟技能配对，该兄弟技能共享能力家族，但可能导致执行指向过时的资源、缺失的前提条件或错误的程序。我们引入了SkillResolve-Bench 1.0，这是一个针对此设置的可审计基准，包含661对有用/风险技能对、源角色和接纳证据、线索/泄露检查、查询不相交划分，以及一个包含6,660个公开SkillRet候选者的7,982个候选池。该基准报告有用排名以及有害兄弟率（HSR@K），即风险兄弟技能的top-K暴露程度。我们还提供了SkillResolve，一种参考方法，它解析活跃的候选家族，根据易混淆的库负面示例和合同-配置文件线索对查询条件下的效用进行评分，并在最终top-K列表之前从每个家族中选择一个代表。在已发布的关系下，SkillResolve在保持HSR@3=0的同时，达到了Recall@3 0.766和NDCG@3 0.699。与SkillRouter相比，Recall@3提高了0.112，NDCG@3提高了0.165，同时HSR@3从0.693降至0。在没有代表选择的情况下，相同评分器下的HSR@3上升至0.236，这确定了族内代表选择是将能力检索转化为更安全的程序暴露的机制。

## Abstract
Agent skill libraries are becoming routable software assets: a retrieved skill can contribute instructions, scripts, resource bindings, and execution assumptions to an agent. This makes skill retrieval more than broad relevance matching. A retriever can find the right capability family yet expose the wrong same-capability representative. We study this failure as same-capability execution-risk retrieval. Each query pairs a helpful skill with a query-specific risky sibling that shares the capability family but can lead execution toward a stale resource, missing precondition, or wrong procedure. We introduce SkillResolve-Bench 1.0, an auditable benchmark for this setting with 661 helpful/risky pairs, source-role and admission evidence, cue/leakage checks, query-disjoint splits, and a 7,982-candidate pool that includes 6,660 public SkillRet candidates. The benchmark reports helpful ranking together with harmful sibling rate (HSR@K), the top-K exposure of the risky sibling. We also provide SkillResolve, a reference method that resolves active candidate families, scores query-conditioned utility from confusable library negatives and contract-profile cues, and selects one representative from each family before the final top-K list. Under the released family relation, SkillResolve reaches Recall@3 0.766 and NDCG@3 0.699 while keeping HSR@3=0. It improves over SkillRouter by 0.112 Recall@3 and 0.165 NDCG@3 while reducing HSR@3 from 0.693 to 0. Without representative selection, HSR@3 rises to 0.236 under the same scorer, identifying within-family representative choice as the mechanism that turns capability retrieval into safer procedural exposure.

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题：** 智能体技能库（agent skill library）中的“同能力歧义（same-capability ambiguity）”。现有检索方法可以找到正确的能力家族（capability family），但可能从该家族中暴露出错误的代表技能（representative），该代表技能与有用技能共享相同的域词汇和过程形状，但包含过时资源、缺失前提条件、错误过程等，导致执行风险。
- **研究动机：** 随着技能库规模扩大，技能成为可路由的软件资产（包含指令、脚本、资源绑定等）。检索阶段的选择直接影响智能体后续执行的安全性。现有基准（如SkillRet、SRA-Bench）主要关注正面技能检索，未区分同能力族内的代表歧义。恶意技能检测关注安全性，但属于不同层面。本文首次系统研究“检索到正确能力族却暴露错误代表”这一失败模式。
- **整体含义：** 提出**SkillResolve-Bench 1.0**，一个针对同能力执行风险检索的可审计基准，以及**SkillResolve**方法，通过族解析（capability resolution）、混淆样本效用学习（confusable-negative utility scoring）和代表选择（representative selection）来消除风险暴露，将能力检索转化为安全的程序暴露。

## 2. 方法论：核心思想、关键技术细节

### 核心思想
- 将检索问题拆分为三个步骤：**能力解析**（哪些候选应被视为同一族的替代代表）、**效用评分**（学习查询条件下技能的有用程度）、**代表选择**（每个族只选一个最高效用代表进入最终Top-K列表）。
- 引入**有害兄弟率（Harmful Sibling Rate, HSR@K）** 作为风险暴露指标，与Recall和NDCG共同评估。

### 关键技术细节

1. **任务形式化**  
   每个查询 \(q_i\) 对应一个候选池 \(C(q_i)\)，一个有用技能 \(s_i^+\)，一个同族风险兄弟 \(s_i^-\)，以及一个族关系 \(g^\star\)。标签是查询特定的：同一个技能在不同查询中可能是有用的或风险兄弟。

2. **能力解析（Capability Resolution）**  
   解析器 \(\rho\) 将候选池划分为若干组 \(G_j(q)\)，同一组内的候选被视为同一能力的替代代表。支持多种族源：基准发布的族关系、公开元数据/标题、文本聚类等。族解析只定义局部竞争，不决定哪个技能有用。

3. **效用学习（Utility Learning from Confusable Skills）**  
   学习一个查询条件效用评分器 \(F_\theta(q,s)\)，由两部分组成：  
   - 基座分数 \(a(q,s)\)（如属性投票分数）  
   - 学习效用 \(h_\theta(q,s) = \theta^\top \phi(q,s)\)，其中 \(\phi\) 包含词/字符TF-IDF、倒数排名融合、路由视图分数、属性投票分数、以及**合同配置文件（contract profile）** 特征（资源绑定、前提条件、API/时间范围、输出模式、过程、标识符等）。  
   训练采用成对逻辑回归损失，将有用技能与每个混淆负例（从候选池中挖掘的Top-50中除有用和风险兄弟外的最高排名候选）做对比，鼓励有用技能得分高于混淆负例。最终得分 \(F_\theta = \alpha a + (1-\alpha) h_\theta\)，\(\alpha\) 在开发集上选取。

4. **代表选择（Representative Selection）**  
   在每个解析得到的族内，只保留效用最高的一个候选作为该族的代表，然后对所有代表按其效用排序，输出Top-K列表。这避免了同一族中有用和风险兄弟同时进入最终列表。

5. **算法流程（文字说明）**  
   输入：查询 \(q\)、候选池 \(C(q)\)、解析器 \(\rho\)、评分器组件、预算 \(K\)。  
   ① 解析得到族集合 \(\Pi_q\)。  
   ② 对每个族中的每个技能，计算合同配置文件和基座特征，得到最终效用分数。  
   ③ 每个族选出最高分代表，加入临时池 \(P\)。  
   ④ 对 \(P\) 中所有代表按效用排序，取Top \(K\) 返回。

## 6. 主要结论与发现

- **同能力风险是普遍现象**：在SkillRet审计中，47.3%的查询在Top-3中出现同族兄弟，36.6%同时包含有用和严格同族兄弟。传统相关性方法（BGE、RRF、SkillRouter）的HSR@3高达0.461~0.693，说明它们无法区分族内代表。
- **SkillResolve显著改善**：在保持HSR@3=0的同时，Recall@3达0.766，NDCG@3达0.699，相比SkillRouter Recall提升0.112，NDCG提升0.165；相比Attribution-listwise Recall提升0.089，NDCG提升0.103。
- **代表选择是主要机制**：移除代表选择后，相同评分器的HSR@3从0跃升至0.236，而有用检索几乎不变，说明风险暴露主要源于同一族内多个代表同时入选。
- **混淆库负例优于词汇/BM25负例**：Recall@3提升0.059，NDCG提升0.064。
- **合同特征贡献微小**：移除后性能几乎不变（Recall@3从0.766降至0.758，置信区间跨零），表明合同特征主要作为显式规范而非关键信号。
- **公开族源同样有效**：使用公开元数据/标题或文本聚类作为族源，HSR@3也为0，但Recall略有下降（约0.755），且族粒度更粗。

- **问题定义清晰、新颖**：首次系统研究“同能力执行风险”这一之前被忽视的检索故障模式，并给出了正式化定义和量化指标（HSR）。
- **基准构建严谨**：SkillResolve-Bench 1.0包含661对人工标注的有用/风险兄弟对，公开源角色、接纳证据、风险分类、线索检查、哈希验证、查询不相交划分，具有可审计性。
- **方法简洁有效**：SkillResolve采用线性评分加代表选择的分解方案，不依赖大规模微调，效率高；通过族解析和效用竞争自然消除风险暴露，机制透明。
- **实验设计全面**：主实验、消融、族源分析、风险类型分布、标签有效性验证、暴露路径审计等，证据链完整。

## 8. 不足与局限

- **算力未明确**：文中未提及GPU型号、训练时长等，虽然方法轻量，但不利于复现时评估资源需求。

- **标签偏差风险**：尽管做了线索检查和外部偏好验证，但标注者可能受固有模板影响（改写测试仅覆盖50对），且所有标注源自SRA-Bench和SkillsBench，这些任务领域有限，未必代表所有技能类型。
- **缺乏跨库泛化测试**：未在独立于SkillRet的其他公开库（如HuggingFace、GitHub技能）上验证方法。
