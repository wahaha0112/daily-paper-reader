## 摘要
大型语言模型代理越来越依赖于技能：可重用的过程文档，编码工作流程、工具使用、实现模式、验证检查和领域规则。技能重写通常被视为提示压缩，但较短的技能可能通过移除防止探索、调试和恢复的稀疏操作锚点而使代理更加昂贵。我们通过这种经济视角研究技能重写。我们的受控框架分析技能结构，使用信息保留策略重写技能，并在固定任务指令、环境和验证器下评估重写结果。在SkillsBench上的实验揭示了不同策略之间明确的质量-成本权衡：API/代码锚定、工作流守卫和规则/公式锚定有利于不同的任务族，没有普遍占优的模板。在主要的保留评估中，学习到的策略将总成本降低7.0%，下游代理令牌成本降低6.0%；在冻结的跨模型迁移中，相应的降低平均为14.7%和13.7%，同时验证器质量得以保持。这些结果将技能设计定位为成本感知的操作知识工程，而不是提示压缩。资源：https://github.com/1Reminding/Skill_EE.

## Abstract
Large language model agents increasingly rely on skills: reusable procedural documents encoding workflows, tool use, implementation patterns, validation checks, and domain rules. Skill rewriting is often treated as prompt compression, but shorter skills can make agents more expensive by removing sparse operational anchors that prevent exploration, debugging, and recovery. We study skill rewriting through this economic lens. Our controlled framework profiles skill structure, rewrites skills using information-preservation strategies, and evaluates the rewrites under fixed task instructions, environments, and verifiers. Experiments on SkillsBench reveal distinct quality--cost trade-offs across strategies: API/code anchoring, workflow guarding, and rule/formula anchoring benefit different task families, with no universally dominant template. In the main held-out evaluation, the learned policy reduces total cost by 7.0% and downstream agent-token cost by 6.0%; in frozen cross-model transfer, the corresponding reductions average 14.7% and 13.7%, while verifier quality is preserved. These results position skill design as cost-aware operational knowledge engineering rather than prompt compression. Resources: https://github.com/1Reminding/Skill_EE.

- **研究背景**：大型语言模型（LLM）代理越来越多地依赖“技能”（skills）——可重用的程序化文档，用于编码工作流、工具使用、实现模式、验证检查和领域规则。技能重写通常被简单视为“提示压缩”（prompt compression），即缩短技能文本以降低输入令牌成本。
- **核心问题**：较短的技能可能反而使代理更昂贵。因为技能中某些稀疏的“操作锚点”（operational anchors，如API构造函数、命令行标志、验证阈值、恢复规则等）对于防止探索、调试和恢复至关重要。移除这些锚点会节省直接技能令牌成本，但可能导致下游代理在使用中增加探索、调试、工具调用和恢复，从而推高总执行成本。
- **研究含义**：作者提出技能重写不应是单纯的文本压缩，而应是一项**成本感知的操作知识工程**（cost-aware operational knowledge engineering）。需要回答：技能应该记住哪些信息？不同的任务和技能结构需要不同的保留策略，没有单一的通用模板。

## 6. 主要结论与发现

- **单一固定模板并非最优**：不同任务和技能结构对不同保留策略有不同偏好。API/代码锚定对代码密集型任务效果好；规则/公式锚定对科学计算和基于规则的任务有利；工作流守卫在验证密集型任务中有用，但通常会提高下游执行成本。
- **固定策略暴露权衡**：工作流守卫显著缩短技能长度（令牌比0.58），但下游代理令牌升至1.14倍基线，总成本增加。相反，API/代码锚定在缩短技能的同时也使下游成本下降。
- **策略选择器改进质量-成本前沿**：
  - 在20任务保留评估中，冻结核策略在保持验证质量（QR=1.01）的前提下，将总成本降低7.0%（ρ=0.93），下游令牌成本降低6.0%（ra=0.94）。
  - 在跨模型迁移中，池策略的平均总成本降低14.7%，下游成本降低13.7%，验证分数略升或保持。
- **经济指标的重要性**：仅看技能长度不能反映真实成本；必须同时考虑直接技能令牌和下游代理令牌，因为技能重写可以将成本转移至下游执行。
- **消融实验关键发现**：锚点修复是最关键的组件（移除后质量下降最大）；无损奖励和超支惩罚共同引导策略平衡质量与成本。
