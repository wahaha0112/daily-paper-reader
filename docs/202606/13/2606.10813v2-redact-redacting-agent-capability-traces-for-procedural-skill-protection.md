## 摘要
用户依赖执行轨迹来观察智能体行为、诊断故障并确保问责。这些轨迹包含丰富的程序细节，包括工具调用、中间决策和错误恢复逻辑。然而，这些细节可能暴露私有的程序技能，使下游方法能够恢复关键公式、阈值和策略，而无需访问模型权重或技能文件。为量化这一风险并评估保护措施，我们构建了 \textsc{CapTraceBench}，这是一个包含75个专业长周期任务和154个精选技能的基准，涵盖七个领域。我们还引入了 \textsc{RedAct}（https://github.com/XuShuwenn/RedAct），这是一个受保护的轨迹发布框架，该框架定位受保护的关键信息，在保留验证者关键证据的同时重写轨迹，并嵌入行为水印以供下游溯源分析。在代表性的轨迹重用方法中，\textsc{RedAct} 将归一化技能转移（NST）从原始轨迹的44.7–67.1%降低到无技能基线以下，同时保留审计证据。其独立的行为水印实现了93.6–100.0%的真实检测率，虚警率最高为1.9%。这些结果将公共智能体轨迹视为安全接口，并表明选择性编辑可以在不删除审计证据的情况下减少程序能力泄露。

## Abstract
Users rely on execution traces to observe agent behavior, diagnose failures, and ensure accountability. These traces contain rich procedural detail, including tool invocations, intermediate decisions, and error-recovery logic. Yet this detail can expose private procedural skills, allowing downstream methods to recover key formulas, thresholds, and strategies without access to model weights or skill files. To quantify this risk and evaluate protection, we construct \textsc{CapTraceBench}, a benchmark of 75 specialized long-horizon tasks and 154 curated skills across seven domains. We also introduce \textsc{RedAct} https://github.com/XuShuwenn/RedAct, a protected trace release framework that localizes protected key information, rewrites traces while preserving verifier-critical evidence, and embeds behavioral watermarks for downstream provenance analysis. Across representative trace reuse methods, \textsc{RedAct} reduces normalized skill transfer (NST) from 44.7--67.1\% on raw traces to below the no-skill baseline, while preserving audit evidence. Its standalone behavioral watermarks reach 93.6--100.0\% true detection with a false alarm rate of at most 1.9\%. These results frame public agent traces as security interfaces and show that selective redaction can reduce procedural capability leakage without removing audit evidence.

## 1. 核心问题与整体含义（研究动机和背景）

**研究动机**：随着工具使用智能体从研究原型走向部署，它们在生物医药、金融、工程等领域被用于处理专有数据和工作流。智能体的执行轨迹（traces）记录了详细的工具调用、中间决策、错误恢复逻辑等程序性步骤，这些轨迹常被发布用于透明性、调试和用户信任。然而，轨迹中的细节可能暴露私有的**程序技能（procedural skills）**——包括公式、阈值、工具选择、验证流程等——下游攻击者仅凭发布的轨迹即可恢复并复用这些技能，无需访问模型权重或技能文件。这构成了**黑盒轨迹披露（black-box trace disclosure）**风险：轨迹的审计价值与技能保护之间存在根本性矛盾。

**核心问题**：如何发布有用的智能体轨迹，既能支持审计和调试，又能防止私有的程序技能被下游方法提取和复用，同时还能追踪轨迹的后续使用（溯源）？

## 2. 方法论：核心思想、关键技术细节与算法流程

**核心思想**：提出 **RedAct**（Redacting Agent Capability Traces）框架，包含两个互补层次：
- **选择性重写层**：在发布前，利用技能所有者对私有技能包的访问权限，定位轨迹中受保护的关键信息（如公式、阈值、工具选择、验证逻辑），并将其抽象为任务级描述，同时保留验证者（verifier）所需的关键证据（如最终答案、工具调用记录、执行顺序）。
- **行为水印层**：在部分受保护轨迹中嵌入功能中性的行为模式（如“环境检查”、“仪式标记”等），这些模式在后续被下游学生模型重用时可以被检测出来，从而提供溯源证据。

**关键技术细节**：
1. **关键信息定位（Key-Item Locator）**：使用 LLM 基于任务指令和技能包提取受保护项集合 \(K_{prot}\)，再经人工去重。
2. **轨迹重写（Rewriter）**：LLM 根据 \(K_{prot}\) 将原始轨迹中的助理回复（assistant turns）进行抽象化重写，生成受保护轨迹 \(z_{RA}\)。保留最终答案、工具名称、验证器路径、模式字段等审计所需内容。
3. **行为水印注入**：定义钩子家族 \(h\)，每个家族包含检查函数 \(W_{check}^h\)、注入函数 \(W_{inject}^h\) 和检测函数 \(W_{detect}^h\)。在符合条件的轨迹中以概率 \(r\) 嵌入无害的行为模式（如固定位置的环境探测、工具结果后的交叉验证等）。注入后需确保验证器结果和最终答案不变。
4. **算法流程**（算法1和算法2）：
   - 保护发布：输入任务指令 \(d\)、技能包 \(S\)、原始轨迹 \(\tau\) → 提取所有受保护项 \(K\) → 分离轨迹为用户轮和助理轮 → 对每个助理轮，根据 \(K\) 重写 → 检查重写后是否可解析、是否与原始对齐、最终答案是否保留 → 输出受保护轨迹 \(z_{RA}\)。
   - 水印注入：输入轨迹库 \(C\)、钩子家族 \(h\)、比率 \(r\) → 筛选合格轨迹子集 \(\Omega_h\) → 随机采样 \(m_h\) 条轨迹 → 对每一条注入行为（包括附加激活短语、插入特定动作），检查注入后是否被检测器识别且不改变验证器结果 → 输出带水印痕迹的轨迹库。

## 3. 实验设计：数据集、基准与对比方法

- **数据集与基准**：构建 **CapTraceBench**，包含 **75 个长周期任务**（23 个任务族），覆盖 **7 个领域**（生命科学、化学、地球与气候、工程、金融与经济、媒体与网页、软件与安全）。每个任务附有 1–3 个技能，共 **154 个精选技能**。任务分为易（26.7%）、中（50.7%）、难（22.7%）三个难度级别。
- **对比方法**：评估 **四种下游轨迹重用方法**：
  1. **单智能体技能提取（Extracted Skills）**：AutoRefine 方式从轨迹合成 SKILL.md 文档和可重用脚本。
  2. **多智能体技能进化（Evolved Skills）**：类似 Trace2Skill，通过多智能体迭代从成功/失败轨迹中提炼技能。
  3. **工作流检索重用（Retrieval Reuse）**：将轨迹索引为检索库，推理时注入 top-k 相似轨迹作为上下文演示。
  4. **轨迹微调（Trajectory Fine-tuning）**：在开源模型 Qwen3-8B/4B 上微调受保护轨迹，用于水印检测实验。
- **评估条件**：四种披露条件：**无技能（No Skills）**、**Oracle 技能（Oracle Skills）**（直接提供私有技能）、**原始轨迹（Raw Traces）**、**受保护轨迹（Protected Traces）**（RedAct 发布）。
- **评估指标**：
  - 成功率（SR）：最终任务验证器通过率。
  - 步骤成功率（SSR）：验证器检查点平均通过率。
  - 归一化技能转移（NST）：SSR 相对于无技能基线的增益，除以 Oracle 增益；越低表示技能泄露越少。
  - 恢复受保护信息（RPI）：下游产物中恢复的受保护关键项比例。
- **模型与推理框架**：6 个闭源模型/前端：Claude Opus 4.6、Sonnet 4.6、Haiku 4.5（Claude Code）；GPT-5.2 Codex（Codex CLI）；Gemini 3 Pro、Gemini Flash（Gemini-CLI）。开源模型：Qwen3-8B、Qwen3-4B。任务运行于 Docker 容器，使用 BenchFlow 进行 5 次重复。

## 6. 主要结论与发现

1. **原始轨迹是脆弱攻击面**：仅凭原始轨迹，下游重用方法（提取、进化、检索）就能获得大部分 Oracle 技能增益：平均 SSR 从无技能的 68.0% 提升到 73.5%–73.7%，NST 达 44.7%–67.1%。尤其在困难任务上增益更大（6.5–10.5% SSR），说明轨迹泄露了关键程序知识。
2. **RedAct 有效抑制技能复用**：经过 RedAct 保护后，三种重用方法的 SSR 降至 65.5%–67.5%，全部低于无技能基线（68.0%）；NST 变为负值（-5.9% 至 -29.4%）；RPI 下降 37–48%。保护效果在困难任务上尤为显著。
3. **行为水印提供可靠溯源证据**：独立水印（如环境检查）在 Qwen3-8B 上达到 93.6% 真实检测率，误报率 ≤1.9%；上下文水印（如交叉验证）检测率较低（16–32%）但误报率为 0%。
4. **保护保留审计证据**：最终答案、工具名称、验证器路径、模式字段保留率达 91–96.6%；工具调用次数和轨迹长度在 90–110% 范围内；人类评估显示保护轨迹自然性和可用性良好（Kappa 系数 0.643、0.804）。

- **问题形式化清晰**：首次将智能体轨迹泄露问题形式化为“黑盒轨迹披露”，并定义了可量化的评估框架。

- **双层次保护设计创新**：重写层精确移除敏感内容，保留审计所需；水印层实现事后溯源，且不影响任务语义。
- **消融分析充分**：对比关键信息引导 vs. 通用重写，揭示显式定位的重要性。
- **多模型、多场景验证**：涵盖闭源/开源模型、多种重用方法（合成、进化、检索、微调），增强了结论的泛化性。
- **人类评估补充**：对保护轨迹的自然性和可用性进行人工评分，提升了结果的可信度。

## 8. 不足与局限

1. **仅限于黑盒披露假设**：假设下游只能看到发布轨迹，无法访问模型权重、技能文件、隐藏状态。实际中可能遇到更强的攻击（如白盒蒸馏、部分灰盒访问），未测试这些场景。
2. **基准任务规模有限**：仅75个任务、154个技能，可能无法完全代表真实应用中更复杂、更动态的技能。且所有任务均在同一计算环境中执行，缺乏部署噪声和工具变更。
3. **上下文水印保留率低**：上下文钩子（交叉验证、错误锚点）的检测率仅16–32%，说明注入的复杂行为在学生模型微调后易丢失，限制了其作为强溯源的可靠性。
4. **微调实验规模小**：仅用2k条轨迹、LoRA训练5轮，未探索更大模型或更多训练数据下的水印鲁棒性。
5. **未考虑对抗性移除**：论文指出水印可能被主动移除（如固定标记剥离、结果包装去除、罕见短语释义等），但未进行此类鲁棒性实验。
6. **资源消耗未报告**：未给出重写和水印注入的计算开销，以及整体框架的时延/成本分析，不利于实际部署评估。
7. **缺乏与现有防御的对比**：未与以前的工作（如反蒸馏采样、推理轨迹加密等）进行直接比较。
