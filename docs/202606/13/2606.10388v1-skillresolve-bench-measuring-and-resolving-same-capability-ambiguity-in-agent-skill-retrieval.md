## 摘要
智能体技能库正成为可路由的软件资产：检索到的技能可以为智能体提供指令、脚本、资源绑定和执行假设。这使得技能检索不仅仅是广泛的相关性匹配。检索器可以找到正确的能力家族，但却暴露了错误的同能力代表。我们将这种失败研究为同能力执行风险检索。每个查询将一个有帮助的技能与一个特定于查询的风险兄弟配对，该兄弟共享能力家族，但可能导致执行走向过时的资源、缺失的先决条件或错误的程序。我们引入了SkillResolve-Bench 1.0，这是一个可审计的基准测试，包含661个有益/风险对、来源角色和准入证据、线索/泄漏检查、查询不相交分割，以及一个包含6,660个公开SkillRet候选者的7,982个候选池。该基准报告有益排名以及有害兄弟率（HSR@K），即风险兄弟的前K暴露率。我们还提供了SkillResolve，这是一种参考方法，它解析活跃候选家族，从可混淆的库负例和合约轮廓线索中评分查询条件效用，并在最终前K列表之前从每个家族中选择一个代表。在已发布的关系下，SkillResolve在Recall@3达到0.766，NDCG@3达到0.699，同时保持HSR@3=0。它比SkillRouter在Recall@3上提高了0.112，在NDCG@3上提高了0.165，同时将HSR@3从0.693降低到0。如果没有代表选择，在相同评分器下HSR@3上升到0.236，识别出家族内代表选择是将能力检索转化为更安全程序暴露的机制。

## Abstract
Agent skill libraries are becoming routable software assets: a retrieved skill can contribute instructions, scripts, resource bindings, and execution assumptions to an agent. This makes skill retrieval more than broad relevance matching. A retriever can find the right capability family yet expose the wrong same-capability representative. We study this failure as same-capability execution-risk retrieval. Each query pairs a helpful skill with a query-specific risky sibling that shares the capability family but can lead execution toward a stale resource, missing precondition, or wrong procedure. We introduce SkillResolve-Bench 1.0, an auditable benchmark for this setting with 661 helpful/risky pairs, source-role and admission evidence, cue/leakage checks, query-disjoint splits, and a 7,982-candidate pool that includes 6,660 public SkillRet candidates. The benchmark reports helpful ranking together with harmful sibling rate (HSR@K), the top-K exposure of the risky sibling. We also provide SkillResolve, a reference method that resolves active candidate families, scores query-conditioned utility from confusable library negatives and contract-profile cues, and selects one representative from each family before the final top-K list. Under the released family relation, SkillResolve reaches Recall@3 0.766 and NDCG@3 0.699 while keeping HSR@3=0. It improves over SkillRouter by 0.112 Recall@3 and 0.165 NDCG@3 while reducing HSR@3 from 0.693 to 0. Without representative selection, HSR@3 rises to 0.236 under the same scorer, identifying within-family representative choice as the mechanism that turns capability retrieval into safer procedural exposure.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **问题**：智能体技能检索中，检索器可能找到正确的能力家族（如“雷达信号处理”），但选中了同一家族内具有执行风险的技能——例如指向过期资源、缺失前置条件或使用错误流程。这种“同能力歧义”导致智能体执行失败，而现有检索系统仅关注相关性，无法区分同一家族内不同技能的执行后果。
- **背景**：技能库已发展为可路由的软件资产，包含指令、脚本和资源绑定。已有工作（SkillRet、SRA-Bench、SkillRouter）侧重能力匹配，但忽视了家族内代表选择的安全性。安全研究（MalSkillBench、SkillGuard）关注恶意技能，未涉及非恶意但有执行风险的“兄弟”。
- **整体含义**：提出SkillResolve-Bench基准和SkillResolve方法，首次系统定义并解决“同能力执行风险检索”，为智能体安全技能投放提供可量化的评估标准和实用方案。

### 2. 论文提出的方法论

- **核心思想**：将技能检索分解为三个阶段：能力族解析 → 查询条件效用评分 → 每族代表选择。通过效用模型区分家族内“有用”和“风险”技能，并只暴露每个族中效用最高的代表，避免风险技能混入最终列表。
- **关键技术细节**：
  1. **能力解析器（Capability Resolver）**：对查询和候选池，将属于同一能力族的候选技能归为一组（如通过基准关系、元数据或文本聚类）。组内技能视为竞争性代表。
  2. **效用评分器（Utility Scorer）**：训练一个线性模型 \( h_\theta(q,s) = \theta^\top \phi(q,s) \)，特征 \(\phi\) 包含基础检索信号（TF-IDF、RRF、路由视图等）和**合约配置文件**的16个字段（资源绑定、前置条件、API范围、输出模式、过程、标识符）。合约特征通过关键词/字面检测比较查询和技能的字段重叠、覆盖度和缺失标志。最终评分插值：\( F_\theta = \alpha a + (1-\alpha) h_\theta \)，其中 \(a\) 是属性投票基础分数。训练使用每查询的正例（有用技能）和**可混淆库负例**（从top50中排除有用和风险后选出的5个最高分候选），优化成对逻辑损失。
  3. **代表选择器（Representative Selector）**：对每个能力组内的候选技能，选择效用分数最高的一个作为代表，所有代表按分数排序输出TopK。算法流程见Algorithm 1：解析组 → 对每组内每个技能计算 \(F_\theta\) → 取每组 argmax → 全局排序输出。

- **公式/算法**（文字说明）：成对损失 \( L = \sum_i \sum_{s \in H_i} \log(1 + e^{-(F_\theta(q_i,s_i^+) - F_\theta(q_i,s))}) + \lambda \|\theta\|^2 \)，训练后推理时按上述三步骤获得排名。

### 6. 论文的主要结论与发现

1. **相关性基线暴露高风险**：BGE、RRF、SkillRouter的HSR@3高达0.461~0.693，说明仅靠语义匹配无法避开同能力风险兄弟。
2. **SkillResolve同时提升有用检索和抑制风险**：Recall@3=0.766，NDCG@3=0.699，HSR@3=0，相比SkillRouter提升Recall 0.112、NDCG 0.165，HSR降低0.693。
3. **代表选择是关键机制**：移除代表选择后HSR@3升至0.236，而有用召回几乎不变（0.766→0.762），证明风险抑制主要来自组内代表过滤而非有用排序提升。
4. **合约特征贡献较小但稳定**：移除后Recall@3仅下降0.008（置信区间跨零），说明合约特征作为显式规范而非主要性能推手。
5. **公共元数据解析器也能实现零暴露**：使用元数据/标题或文本聚类解析能力族，在相同评分器下也达到HSR@3=0（Recall@3≈0.755），但组粒度更粗。
