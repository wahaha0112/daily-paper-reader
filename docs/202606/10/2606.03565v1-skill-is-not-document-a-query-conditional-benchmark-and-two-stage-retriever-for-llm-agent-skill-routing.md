## 摘要
LLM智能体通过组合多种技能完成复杂任务，技能检索是智能体的前端阶段。技能检索在监督层面上与传统文档检索有根本区别：Top-K联合正确性不仅取决于每个查询-技能对的语义相关性，还取决于联合检索的技能能否在给定查询下协作完成任务。这种“技能兼容性”无法仅从独立相关性推导出来。然而，现有的基于LLM的数据合成流水线可以为“在此查询下不应联合检索哪些技能”提供直接监督信号——即LLM自身的拒绝决策——但这一信号通常被视为低质量数据而被丢弃。为解决这一问题，我们提出了拒绝即资源检索器（R3），并构建了R3-Skill，这是一个面向真实智能体技能路由的双语（中文-英文）技能检索基准。R3-Skill涵盖四种语言方向，查询措辞接近真实用户请求，并通过多专家交叉验证。在R3-Skill上，我们构建了一个两阶段检索系统（R3-Embedding + R3-Reranker），将技能兼容性作为显式训练信号。梯度分析表明，“推开”信号在双编码器中因双边平衡而被稀释，但在交叉编码器中充当无损分级排序监督——这促使我们将其置于交叉编码器阶段，两个数据集上的消融实验证实了这一点。R3-Embedding + R3-Reranker流水线在R3-Skill上达到了Hit@1=0.7714、NDCG@10=0.8327和Set-Compat=0.3525。数据集、训练代码和模型权重已作为开源发布，用于智能体技能路由。

## Abstract
LLM agents complete complex tasks by composing multiple skills, and skill retrieval is a front-end stage for agents. Skill retrieval differs fundamentally from traditional document retrieval at the supervision level: top-K joint correctness depends not only on the semantic relevance of each individual query-skill pair, but also on whether the skills retrieved together can collaborate to fulfill the task under the given query. Such "skill compatibility" cannot be derived from independent relevance alone. Yet existing LLM-based data synthesis pipelines can produce a direct supervision signal for "which skills should not be jointly retrieved under this query" -- namely the LLM's own rejection decisions -- and this signal is routinely discarded as low-quality data. To address this gap, we propose Reject-as-Resource Retriever (R3) and construct R3-Skill, a bilingual (Chinese-English) skill retrieval benchmark targeting realistic agent skill routing. R3-Skill spans four language directions, features query phrasings close to real user requests, and is verified through multi-expert cross-checking. On R3-Skill, we build a two-stage retrieval system (R3-Embedding + R3-Reranker) with skill compatibility as an explicit training signal. Gradient analysis shows that the "push-away" signal is diluted by bilateral balancing in the bi-encoder but acts as lossless graded ranking supervision in the cross-encoder -- motivating its placement at the cross-encoder stage, as confirmed by ablations on two datasets. The R3-Embedding + R3-Reranker pipeline attains Hit@1 = 0.7714, NDCG@10 = 0.8327 and Set-Compat = 0.3525 on R3-Skill. The dataset, training code and model weights are released as open source for agent skill routing.

## 2. 论文提出的方法论

- **核心思想**：将LLM产生的SKIP决策保留作为负监督信号，用于训练技能兼容性。通过对联合正确性的概率分解：Pr[S* ⊆ top-K | q] ≈ ∏ Pr[s ∈ top-K | q] · C(q, S*)，其中C(q, S*)为技能兼容性因子（<1冲突，>1协同）。训练时，双编码器（bi-encoder）负责初筛，交叉编码器（cross-encoder）利用SKIP信号作为分级标签进行排序优化。
- **关键技术细节**：
  - **R3-Skill数据构建**：
    - 收集95,212个原始技能（GitHub），经哈希去重 + 纯文件操作过滤 → 10,246个干净技能。
    - 使用BGE-M3编码 + KMeans聚类（K=40）得到8个超域×40个子簇。
    - 近邻硬约束采样：k=2要求同子簇，k=3要求同超域，从而生成高质量负样本。
    - LLM（DeepSeek-V4-Pro）对每个技能组合进行WRITE/SKIP决策，WRITE生成6种风格的查询（task_direct, scene, role_setup, constraint, multi_step, debug），涵盖四种语言方向（en2en, en2zh, zh2en, zh2zh）。共得到41,592个接受查询、32,828个SKIP标注（其中15,962个可分类为8类拒绝原因）。
    - 测试集由Qwen3-235B-A22B生成，经多专家交叉验证。
  - **R3两阶段检索**：
    - **第一阶段：R3-Embedding**（基于Qwen3-Embedding-0.6B微调），使用标准InfoNCE损失，候选池包含GT + BM25 hard negatives。
    - **第二阶段：R3-Reranker**（基于Qwen3-Reranker-0.6B微调），使用分级ListNet损失：GT → label=3，SKIP伙伴 → label=1，其余 → label=0。通过softmax归一化后的概率进行交叉熵优化。SKIP信号仅在交叉编码器阶段注入，梯度分析表明双编码器中会因双边平衡被稀释，而交叉编码器可无损利用。
  - **评估协议**：R3-Embedding召回top-20，R3-Reranker在候选内重排序。
- **公式/算法流程**（文字说明）：
  - 联合正确性分解：P(set ⊆ top-K) ≈ 各技能独立召回概率乘积 × 兼容性因子C。
  - InfoNCE损失：嵌入阶段，对每个查询q，在候选池（GT + 负样本）上最小化softmax交叉熵。
  - 分级ListNet：重排序阶段，将SKIP伙伴赋予中间标签，通过softmax归一化标签分布，最小化交叉熵，调整排序顺序。

## 6. 论文的主要结论与发现

- **理论结论**：技能检索与文档检索的核心区别在于技能兼容性因子C(q, S*)，且该因子依赖于查询，无法从独立相关性导出。
- **数据构建价值**：保留LLM拒绝信号可有效增强技能兼容性监督，R3-Skill提供了覆盖4种语言方向、6种查询风格、8类拒绝原因的高质量基准。
- **方法有效性**：R3-Embedding达到Hit@1=0.7024，R3-Reranker进一步提升至0.7714，尤其Set-Compat从0.2218提升至0.3525（+13.07pp），表明SKIP信号对集合级排名有显著帮助。
- **梯度分析验证**：双编码器中SKIP“推开”梯度被多查询双边平衡稀释，效果微弱；交叉编码器中则作为分级监督无损利用，支持了将SKIP信号置于第二阶段的合理性。
- **跨语言表现**：en2zh方向最困难（Set-Compat仅14.87），但R3-Reranker提升至28.21；zh2en和zh2zh虽样本少但趋势类似。
