## 摘要
LLM智能体通过组合多种技能来完成复杂任务，而技能检索是智能体的前端阶段。技能检索在监督层面与传统文档检索有本质区别：top-K联合正确性不仅取决于每个查询-技能对的语义相关性，还取决于一起检索到的技能能否在给定查询下协同完成任务。这种“技能兼容性”无法仅从独立相关性推导得出。然而，现有的基于LLM的数据合成流程可以为“在此查询下不应联合检索哪些技能”提供直接监督信号——即LLM自身的拒绝决策——而这一信号通常被视为低质量数据而被丢弃。为弥补这一差距，我们提出了拒绝即资源检索器（R3），并构建了面向真实智能体技能路由的双语（中文-英文）技能检索基准R3-Skill。R3-Skill涵盖四种语言方向，查询措辞接近真实用户请求，并经过多专家交叉验证。在R3-Skill上，我们构建了一个两阶段检索系统（R3-Embedding + R3-Reranker），将技能兼容性作为显式训练信号。梯度分析表明，“推开”信号在双编码器中因双边平衡而被稀释，但在交叉编码器中充当无损分级排序监督——这促使其被置于交叉编码器阶段，两个数据集上的消融实验证实了这一点。R3-Embedding + R3-Reranker流水线在R3-Skill上达到了Hit@1=0.7714，NDCG@10=0.8327，Set-Compat=0.3525。数据集、训练代码和模型权重已开源，用于智能体技能路由。

## Abstract
LLM agents complete complex tasks by composing multiple skills, and skill retrieval is a front-end stage for agents. Skill retrieval differs fundamentally from traditional document retrieval at the supervision level: top-K joint correctness depends not only on the semantic relevance of each individual query-skill pair, but also on whether the skills retrieved together can collaborate to fulfill the task under the given query. Such "skill compatibility" cannot be derived from independent relevance alone. Yet existing LLM-based data synthesis pipelines can produce a direct supervision signal for "which skills should not be jointly retrieved under this query" -- namely the LLM's own rejection decisions -- and this signal is routinely discarded as low-quality data. To address this gap, we propose Reject-as-Resource Retriever (R3) and construct R3-Skill, a bilingual (Chinese-English) skill retrieval benchmark targeting realistic agent skill routing. R3-Skill spans four language directions, features query phrasings close to real user requests, and is verified through multi-expert cross-checking. On R3-Skill, we build a two-stage retrieval system (R3-Embedding + R3-Reranker) with skill compatibility as an explicit training signal. Gradient analysis shows that the "push-away" signal is diluted by bilateral balancing in the bi-encoder but acts as lossless graded ranking supervision in the cross-encoder -- motivating its placement at the cross-encoder stage, as confirmed by ablations on two datasets. The R3-Embedding + R3-Reranker pipeline attains Hit@1 = 0.7714, NDCG@10 = 0.8327 and Set-Compat = 0.3525 on R3-Skill. The dataset, training code and model weights are released as open source for agent skill routing.

- **背景**：LLM智能体通过组合多个技能（skill）完成复杂任务，技能检索是智能体系统的前端环节。随着技能库规模爆炸式增长（从数千到数十万），将所有技能直接放入提示词中不可行，必须进行高效检索。
- **关键区别**：技能检索与传统的文档检索有本质不同。文档检索中，只要每个文档相关，同时返回它们无害；而技能检索中，top-K返回的技能集合必须在给定查询下能够**协同工作**（即技能兼容性）。同一对技能，在不同查询下兼容性可能相反。
- **现有方法缺陷**：
  - 现有数据集（如SkillsBench、SRA-Bench等）主要关注后检索应用阶段，规模不足以训练检索器。
  - 技能检索训练继承文档检索的对比范式（DPR/ANCE等），忽略技能兼容性。
  - LLM在合成数据时产生的“拒绝信号”（即某个技能组合在当前查询下不合理，被LLM判定为SKIP）通常被丢弃，而这恰好可用于负监督。
  - 跨语言覆盖（中英）缺失，且测试查询措辞远离真实用户请求。
- **论文目标**：显式建模技能兼容性，利用被丢弃的LLM拒绝信号作为监督，构建跨语言、真实查询风格的双语基准R3-Skill，并设计两阶段检索系统R3（R3-Embedding + R3-Reranker）。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：
  - 将技能检索的top-K联合正确性分解为**相关性因子**（每个技能独立被召回的概率）和**技能兼容性因子** \( C(q, S^*_q) \)。文档检索可近似为 \( C \equiv 1 \)，而技能检索中 \( C \) 依赖查询且通常偏离1。
  - **Reject-as-Resource**：保留LLM拒绝的SKIP样本，将其作为负监督信号，用于训练技能兼容性。
  - 理论分析（Theorem 1）表明，SKIP信号在双编码器（bi-encoder）中由于“双边平衡”（同一个技能在不同查询下既被推开又被拉回）而被稀释，而在交叉编码器（cross-encoder）中每个查询-技能对独立评分，可无损利用。

- **关键技术细节**：
  - **数据集构建（R3-Skill）**：
    - 从GitHub收集95,212原始技能（中英），经哈希去重、过滤纯文件操作后获得10,246个干净技能。
    - 使用BGE-M3嵌入，KMeans聚类（K=40），并合并为8个超级域。采样策略：\( k=1 \) 自由采样；\( k=2 \) 强制来自同一子簇；\( k=3 \) 强制来自同一超级域。
    - LLM（DeepSeek-V4-Pro）对每个技能组合进行WRITE/SKIP判决。WRITE分支在6种风格下生成查询；SKIP分支被保留并进一步分为8类拒绝原因。
    - 测试集由Qwen3-235B-A22B生成，并经多专家交叉验证。
    - 最终数据集：41,592个接受查询，32,828个SKIP标注。四种语言方向：en2en, en2zh, zh2en, zh2zh。
  - **两阶段检索器**：
    - **Stage 1: R3-Embedding**（双编码器）：基于Qwen3-Embedding-0.6B微调，使用标准InfoNCE损失。每个查询的候选池包含GT正样本和BM25硬负样本。
    - **Stage 2: R3-Reranker**（交叉编码器）：基于Qwen3-Reranker-0.6B微调，使用分级ListNet损失。标签设置：GT得3，SKIP伙伴得1，其他得0。候选池由Stage1的top-20与SKIP伙伴填充至10个。
    - 推理时，Stage1召回top-20，Stage2重排。

## 6. 主要结论与发现

- **技能兼容性必须显式建模**：仅依赖独立相关性的检索器无法保证多技能协同工作。
- **LLM拒绝信号是有用的监督**：将其作为负样本（SKIP）可有效训练技能兼容性，尤其在交叉编码器阶段。
- **两阶段系统性能**：
  - 在R3-Skill上：Hit@1 = 0.7714，NDCG@10 = 0.8327，Set-Compat = 0.3525。
  - 在SkillRet上：NDCG@10达到82.94，与公开基线持平或略优。
- **SKIP信号在交叉编码器上增益显著**：Set-Compat提升13.07pp（0.2218→0.3525）；在双编码器中反而略降（符合理论预测）。
- **跨语言难点**：en2zh（英文技能+中文查询）的SKIP最多，Set-Compat最低（embedding仅14.87），但重排后提升最大（+13.34pp），说明交叉编码器有效处理查询条件兼容性。
