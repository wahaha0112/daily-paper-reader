## 摘要
现代大语言模型智能体日益依赖技能库来处理复杂任务，使技能演化成为自我改进的主要驱动力。然而，孤立的单用户任务流缺乏构建全面技能所需的多样性。尽管跨用户协作能够克服这一数据瓶颈，但当前的轨迹共享方法会损害用户隐私，并强加一个无法适应客户端异构性的统一全局库。我们提出FederatedSkill，一个面向协作智能体演化的隐私保护框架。超越原始轨迹共享，FederatedSkill将语义技能差异（即局部库上的结构化补丁）作为通信的基本单元。在服务器端，一个演化智能体聚合这些补丁以动态建模客户端特定的能力边界，促进严格的个性化技能演化，而非次优的全局平均。在20个不同的智能体任务族上进行评估，FederatedSkill相较于自演化基线展现出显著提升，成功率最高提升44.4%，计算成本降低37.5%。

## Abstract
Modern LLM agents increasingly rely on skill libraries to handle complex tasks, making skill evolution a primary driver of self-improvement. However, isolated single-user task streams lack the diversity required to build comprehensive skills. While cross-user collaboration can overcome this data bottleneck, current trajectory-sharing approaches compromise user privacy and impose a uniform global library that fails to accommodate client heterogeneity. We introduce FederatedSkill, a privacy-preserving framework for collaborative agent evolution. Moving beyond raw trajectory sharing, FederatedSkill utilizes semantic skill diffs, structured patches over local libraries, as the fundamental unit of communication. On the server side, an evolution agent aggregates these patches to dynamically model client-specific capability boundaries, facilitating strictly personalized skill evolution rather than a suboptimal global average. Evaluated across 20 distinct agent task families, FederatedSkill demonstrates substantial gains over self-evolving baselines, achieving up to a 44.4% increase in success rate and a 37.5% reduction in computational cost.

#### 1. 核心问题与整体含义（研究动机和背景）
- **背景**：现代LLM智能体依赖技能库（如Claude Code、OpenClaw）处理复杂任务，技能演化（新增、修改、删除技能）是实现自我改进的主要途径。
- **问题**：单用户任务流数据多样性不足，导致技能库覆盖不全。跨用户协作虽可缓解数据瓶颈，但现有轨迹共享方案面临两大障碍：
  - **隐私风险**：原始轨迹可能包含敏感内容（如网页私密信息、表格中的机密数据），用户无法安全上传至外部服务器。
  - **客户端异质性**：不同用户使用不同模型族、智能体框架和任务分布，单一的全局技能库无法满足个性化需求，反而可能降低性能。
- **目标**：在保护隐私的前提下，让用户协作演化技能，并获得为其需求量身定制的技能库。

- **核心思想**：将**语义技能差分（Skill Patch）**作为通信单元，替代原始轨迹上传。服务器端通过演化智能体动态建模客户端能力边界，实现个性化技能演化。

#### 6. 主要结论与发现
- **性能提升**：FederatedSkill在三种客户异构设置下均优于自演化，同构设置下平均成功率从37.4%提升至45.8%；异构骨干设置下平均提升+5.82 pp；异构骨干+harness设置下平均提升+4.82 pp；最大单任务提升为44.4%（Production-Capacity-Planning）。
- **成本降低**：异构骨干+harness设置下，每任务成本降低7%~24%，每成功任务成本降低11%~37%（Qwen 11%、GLM-5 33%、Kimi 37.5%）。
- **库质量改善**：FederatedSkill有效抑制了自演化中的库膨胀（如Kimi和Qwen）和库停滞（如GLM-5），将各客户技能库大小稳定在1.0~1.6个技能/族。
- **隐私保护有效**：隐私审计显示，outgoing补丁的敏感实体泄漏率仅5.08%，个性化更新泄漏率0.09%，PII金丝雀测试零泄漏。

#### 7. 优点
- **隐私设计**：以语义补丁替代轨迹上传，结合本地蒸馏和路径验证，从架构上消除数据泄露。
- **个性化演化**：通过服务器端动态建模客户端能力边界，实现跨模型、跨harness的个性化技能吸收，优于全局共享方案。
- **轻量通信**：补丁仅~100-280KB/族/轮，总通信量约3.5MB，远小于参数级联邦学习。
- **可审计性**：补丁为明文JSON/Markdown，决策日志记录来源和理由，适合安全合规场景。

#### 8. 不足与局限
- **规模验证不足**：仅测试3个客户端，扩展到数十/数百客户端时的表现和效率未知。
- **基准单一**：仅评估了SkillFlow，未在其他技能库基准（如SkillsBench）上验证，泛化性需更多证据。
- **对抗性场景未覆盖**：假定可信联邦环境，未考虑恶意客户端上传有毒补丁的防御机制。
- **部分任务性能下降**：少数情况下因硬编码映射表导致过拟合（如Kimi K2.5在Cross-Format-Data-Reconciliation上下降12.5 pp），表明存在负迁移风险。
- **无形式化隐私保证**：依赖经验性审计而非差分隐私等硬性加密保证，绝对安全性存疑。
