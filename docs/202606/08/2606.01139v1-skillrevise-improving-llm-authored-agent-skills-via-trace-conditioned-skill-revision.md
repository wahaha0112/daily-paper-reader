## 摘要
智能体技能是使LLM智能体能够执行工作流、验证约束并从故障中恢复的程序性工件。现有的自进化方法利用累积的轨迹来优化技能。然而，它们在冷启动设置中表现不佳，在这种情况下仅存在初始的不完美的技能。因此，技能构建默认依赖于专家编写或一次性LLM生成。专家编写的技能成本高昂，且可能与LLM智能体实际执行任务的方式不一致，而一次性生成的技能可能在语法上良好但在行为上较弱。为了弥合这一差距，我们提出了SkillRevise，一个基于执行的基础框架，旨在迭代地优化这些初始技能。SkillRevise从执行证据中诊断技能缺陷，从通用记忆中检索相关的修复原则，并应用基于执行的编辑。通过重新执行候选方案并测量经验效用，它系统地保留了最优的技能版本。在三个基准测试和五个LLM上的评估中，SkillRevise显著优于一次性基线，将基础智能体在SkillsBench上的成功率从36.05%提升至61.63%。此外，修订后的技能表现出强烈的跨模型迁移性，捕获了超越模型特定工件的通用程序知识。

## Abstract
Agent skills are procedural artifacts that enable LLM agents to execute workflows, verify constraints, and recover from failures. Existing self-evolving methods refine skills using accumulated trajectories. However, they struggle in cold-start settings, where only an initial, imperfect skill is available. Consequently, skill construction defaults to expert authoring or one-shot LLM generation. Expert-authored skills are costly and may not align with how LLM agents actually execute tasks, while one-shot generated skills can be syntactically well formed yet behaviorally weak. To bridge this gap, we propose SkillRevise, an execution-grounded framework designed to iteratively refine these initial skills. SkillRevise diagnoses skill defects from execution evidence, retrieves relevant repair principles from a general memory, and applies execution-anchored edits. By re-executing candidates and measuring empirical utility, it systematically retains the optimal skill version. Evaluated across three benchmarks and five LLMs, SkillRevise substantially outperforms one-shot baselines, improving the base agent's success rate on SkillsBench from 36.05% to 61.63%. Furthermore, the revised skills exhibit strong cross-model transferability, capturing generalized procedural knowledge over model-specific artifacts.

- **背景**：LLM 智能体（Agent）在复杂、依赖验证器的环境中越来越需要可重用的程序性知识（即“技能”，Skill）来组织多步工作流、验证约束、处理错误。然而，当前技能获取存在三种主要范式：

  - **直接编写/生成**：依赖专家或一次性 LLM 生成，专家成本高且与执行行为脱节，一次性生成技能语法正确但行为薄弱。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：将技能视为可执行、可测试的工件，通过 “执行 → 诊断 → 检索原则 → 锚定编辑 → 重执行 → 效用选择” 的循环迭代优化。
- **关键技术细节**：
  - **诊断 (Diagnosis)**：包含验证规范 (Vi)、失败归因 (Ai)、保留约束 (Ki)，将原始执行证据转化为修复定向信息。
  - **原则记忆 (Principle Memory)**：存储通用的可复用修复原则（共7条初始原则），每个原则定义了触发条件、缺陷标签、修复规则、动作模板和转移约束。查询融合稀疏检索和稠密检索，采用加权倒数秩融合（WRRF）排序。
  - **修订算子 (Revision Operator)**：结合当前技能、诊断信息和绑定后的原则，生成修订技能和修订轨迹，其中轨迹包含证据到编辑的映射和**执行锚点**（如具体动作、预期证据、在技能中的位置）。
  - **有界修订周期 (Bounded Revision Episode)**：

## 6. 主要结论与发现

- **主结论**：SkillRevise 显著优于无技能和一次性生成基线。在 SkillsBench 上，GPT-5.5 成功率从 36.05%（无技能）/ 39.53%（一次性）提升至 61.63%（3轮修订）。
- **跨模型提升**：五个执行器上，修订后技能在大多基准上一致提升（Table 1），最大提升出现在 Opus-4.7（+32.56pp）在 SkillsBench 上。
- **迁移性**：GPT-5.5 修订的技能传递给其他执行器时部分有效，但非完全最优，说明技能包含通用程序知识和模型特定提示约定。
- **预算效应**：收益主要集中在前几轮，后期边际递减；效用门控可防止退化。
- **组件重要性**：诊断是最关键组件（移除后成功率从 53/86 降到 28/86），保留账本和执行锚点次重要。
- **ALFWorld 效果**：小规模校准集（25任务）吸收的10条原则可迁移至新任务，最终解决 71/100 任务。

## 7. 优点

- **方法新颖**：将冷启动技能改进问题形式化为执行导向的有界修订，区别于检索和自进化；提出诊断、原则记忆、锚定编辑的完整流程。
- **实用性强**：无需大量历史轨迹，仅需初始不完美技能和验证器反馈，适合真实冷启动场景。
- **效用门控机制**：保留历史最佳技能，防止修订导致退化；效用函数融合效率、迁移和干扰，设计合理。
- **跨模型迁移验证**：不仅评估自身模型，还测试了技能跨执行器的迁移能力，增强了泛化说服力。
- **实验广泛且详实**：覆盖5个模型、4个基准、多轮消融、预算分析、案例研究，并进行了人工泄漏审计，透明度高。
- **组件消融清晰**：通过逐步移除关键组件（诊断、原则、锚点、保留账本）量化各模块贡献，证明结构化的修订优于自由形式重写。

## 8. 不足与局限

- **对验证器依赖高**：修订质量完全取决于验证器反馈的丰富性和正确性；若验证器稀疏或误导，可能产生过拟合甚至错误修复。
- **成本开销**：每轮修订需要重新执行技能，消耗额外 API 调用和 token，且固定预算并不适应所有任务（容易任务无需修订，困难任务可能不够）。
- **无回退机制**：当前版本不提供“无技能回退”，因此在某些本可通过直接探索解决的任务上，技能反而可能有害（例如视频案例）。
- **评估场景有限**：仅限基于验证器的基准测试，未涉及长期部署、安全关键、对抗性任务；技能迁移性仅在部分执行器上验证，不完全通用。
- **原则记忆静态初始化**：只使用了7条手工编写原则，未实现全自动在线吸收（虽提供可选模块但主要测试中未启用），限制了灵活性。
- **缺乏更多对比基线**：未与同样采用迭代优化的自进化方法（如 Reflexion、ExpeL、SkillRL 等）在统一协议下对比，仅 ALFWorld 部分做了定位比较。
