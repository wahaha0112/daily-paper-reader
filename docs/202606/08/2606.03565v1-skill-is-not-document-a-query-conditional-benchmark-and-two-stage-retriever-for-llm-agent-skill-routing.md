## 摘要
LLM智能体通过组合多种技能完成复杂任务，而技能检索是智能体的前端阶段。技能检索在监督层面上与传统文档检索存在根本差异：前K联合正确性不仅取决于每个查询-技能对的语义相关性，还取决于检索到的技能能否在给定查询下协同完成任务。这种“技能兼容性”无法仅从独立相关性中推导。然而，现有的基于LLM的数据合成流程可以为“在此查询下不应联合检索哪些技能”提供直接监督信号——即LLM自身的拒绝决策——而这一信号通常作为低质量数据被丢弃。为弥补这一空白，我们提出了拒绝即资源检索器（R3），并构建了R3-Skill，一个面向现实智能体技能路由的双语（中文-英文）技能检索基准。R3-Skill涵盖四种语言方向，具有接近真实用户请求的查询措辞，并通过多专家交叉验证。在R3-Skill上，我们构建了一个以技能兼容性作为显式训练信号的两阶段检索系统（R3-Embedding + R3-Reranker）。梯度分析表明，“推开”信号在双编码器中因双边平衡而被稀释，但在交叉编码器中作为无损分级排序监督发挥作用——这证明了将其置于交叉编码器阶段的合理性，并在两个数据集上的消融实验中得到证实。R3-Embedding + R3-Reranker流水线在R3-Skill上达到了Hit@1=0.7714，NDCG@10=0.8327和Set-Compat=0.3525。数据集、训练代码和模型权重已作为开源资源发布，用于智能体技能路由。

## Abstract
LLM agents complete complex tasks by composing multiple skills, and skill retrieval is a front-end stage for agents. Skill retrieval differs fundamentally from traditional document retrieval at the supervision level: top-K joint correctness depends not only on the semantic relevance of each individual query-skill pair, but also on whether the skills retrieved together can collaborate to fulfill the task under the given query. Such "skill compatibility" cannot be derived from independent relevance alone. Yet existing LLM-based data synthesis pipelines can produce a direct supervision signal for "which skills should not be jointly retrieved under this query" -- namely the LLM's own rejection decisions -- and this signal is routinely discarded as low-quality data. To address this gap, we propose Reject-as-Resource Retriever (R3) and construct R3-Skill, a bilingual (Chinese-English) skill retrieval benchmark targeting realistic agent skill routing. R3-Skill spans four language directions, features query phrasings close to real user requests, and is verified through multi-expert cross-checking. On R3-Skill, we build a two-stage retrieval system (R3-Embedding + R3-Reranker) with skill compatibility as an explicit training signal. Gradient analysis shows that the "push-away" signal is diluted by bilateral balancing in the bi-encoder but acts as lossless graded ranking supervision in the cross-encoder -- motivating its placement at the cross-encoder stage, as confirmed by ablations on two datasets. The R3-Embedding + R3-Reranker pipeline attains Hit@1 = 0.7714, NDCG@10 = 0.8327 and Set-Compat = 0.3525 on R3-Skill. The dataset, training code and model weights are released as open source for agent skill routing.

### 2. 论文提出的方法论

#### 核心思想
- **Reject-as-Resource（拒绝即资源）**：保留 LLM 在数据合成时对技能组合的 SKIP（不联合检索）判定，将其作为负样本，监督技能兼容性。
- **技能兼容性形式化**：联合检索概率分解为相关性因子与兼容性因子 C(q,S*)。C<1表示集合冲突，C>1表示相互增强。文档检索近似 C≡1，技能检索中 C 依赖于查询且多技能场景下远非 1。
- **两阶段检索**：
    - **R3-Embedding（双编码器）**：基于 Qwen3-Embedding-0.6B，采用标准 InfoNCE 损失训练，候选池包含正例和 BM25 硬负例。分析表明，SKIP 信号注入 InfoNCE 候选池会引入“双边平衡”（正/负梯度同时作用于相同技能表示），导致收益有限，因此该阶段**不使用 SKIP 信号**。
    - **R3-Reranker（交叉编码器）**：基于 Qwen3-Reranker-0.6B，采用分级 ListNet 损失：正样本标签 3，SKIP 伙伴标签 1，其他 0。SKIP 信号在此阶段作为分级监督，无损地优化排序顺序，且实验验证有效。

#### 关键技术细节
- **数据生成**：从 95,212 原始技能去重至 10,246 个；采用 BGE-M3 编码 + KMeans 聚类（K=40，8个超级领域）进行近邻硬约束采样（k=2 同子簇，k=3 同超级域），生成高难度 SKIP 样本。
- **LLM 注释**：训练集由 DeepSeek-V4-Pro 生成，测试集由 Qwen3-235B-A22B 生成，覆盖 4 种语言方向（en2en、en2zh、zh2en、zh2zh），6 种查询风格。SKIP 进一步分为 8 类拒绝理由。
- **两阶段评估协议**：R3-Embedding 召回 top-20 候选，R3-Reranker 在此池中重排序，计算 Hit@1、NDCG、R@K、Comp@K、Set-Compat（度量完整 GT 集是否同时出现在 top-m 中）。

#### 公式（文字说明）
- 联合概率分解：Pr[S* ⊆ top-K | q] ≈ ∏Pr[s∈top-K|q] · C(q, S*)
- InfoNCE 损失（双编码器）：L_emb = -log exp(sim(q,s+)/τ) / Σ exp(sim(q,c)/τ)
- ListNet 损失（交叉编码器）：L_rrk = -Σ y_s log p_s，其中 y_s 由标签（3/1/0）经 softmax 归一化得到，p_s 为重排序器得分 softmax。

### 6. 论文的主要结论与发现

1. **技能检索与文档检索的本质区别**在于技能兼容性，且该兼容性是查询相关的，无法从独立相关性推断。
2. **将 LLM 拒绝信号作为技能兼容性的负监督有效**，但仅适用于交叉编码器阶段；在双编码器阶段，由于双边平衡机制，收益有限甚至轻微下降。
3. **R3-Embedding + R3-Reranker 流水线**在 R3-Skill 上显著优于现有基线：Hit@1 达到 0.7714（+6.9pp 优于单独嵌入），Set-Compat 达到 0.3525（+13.07pp），体现对多技能联合检索能力的大幅提升。
4. **跨语言场景**（en2zh）最具挑战，且重排序器的提升最为明显（Set-Compat 从 14.87 升至 28.21）。
